# 1. Built-in Field Validation and Error Messages

## 1. Introduction

Input validation is the first line of defense in web security and data integrity. Django forms provide comprehensive built-in validation rules—such as length constraints, value bounds, regular expression matching, and custom error messaging.

---

## 2. Why Do We Need It?

Without rigorous validation:
- Databases become corrupted with malformed strings or impossible values (negative prices, future birthdates).
- Applications become vulnerable to injection attacks and buffer overflows.
- Built-in validation ensures that user input matches domain constraints before touching your database.

---

## 3. How It Works

Django field classes (`CharField`, `IntegerField`, `EmailField`, `DecimalField`) enforce validation via field attributes:
- `required=True` (default): Field cannot be empty.
- `max_length`, `min_length`: Enforces character boundaries.
- `min_value`, `max_value`: Enforces numeric boundaries.
- `validators=[...]`: List of validator callables from `django.core.validators`.
- `error_messages={...}`: Custom dictionary overriding default English error strings.

---

## 4. Syntax

```python
from django import forms
from django.core.validators import MinLengthValidator, RegexValidator

class StudentRegistrationForm(forms.Form):
    # Field with custom error messages
    roll_number = forms.IntegerField(
        min_value=1000,
        max_value=9999,
        error_messages={
            'required': 'Roll number is mandatory.',
            'min_value': 'Roll number must be at least 1000.',
            'max_value': 'Roll number cannot exceed 9999.',
        }
    )

    # Field with RegexValidator for phone numbers
    phone_regex = RegexValidator(
        regex=r'^\+?[1-9]\d{9,14}$',
        message="Phone number must be entered in format: '+999999999'. Up to 15 digits allowed."
    )
    phone_number = forms.CharField(validators=[phone_regex])
```

## 5. Practical Examples

### Complete Form with Built-in Validators
```python
# File: academy/forms.py
from django import forms
from django.core.validators import MinValueValidator, MaxValueValidator

class CourseReviewForm(forms.Form):
    course_name = forms.CharField(
        max_length=100,
        min_length=3,
        error_messages={
            'min_length': 'Course title is too short (min 3 characters).'
        }
    )
    rating = forms.IntegerField(
        validators=[MinValueValidator(1), MaxValueValidator(5)],
        help_text="Rate between 1 and 5 stars"
    )
    feedback = forms.CharField(
        widget=forms.Textarea,
        max_length=1000,
        required=False
    )
```

---

## 6. Code Explanation

- `validators=[MinValueValidator(1), MaxValueValidator(5)]`: Callable validation classes that raise `ValidationError` if values exceed bounds.
- `error_messages={'required': '...'}`: Replaces generic "This field is required" messages with domain-specific text.
- `help_text`: Explanatory instructions rendered next to input fields.

---

## 7. Expected Output

If the user inputs `rating = 7`:
The form fails validation and produces:
```html
<ul class="errorlist">
    <li>Ensure this value is less than or equal to 5.</li>
</ul>
```

## 8. Real-World Use Case

Validating tax identification numbers (SSN, GSTIN, PAN), phone numbers, postal codes, and age limits on registration portals.

---

## 9. Common Mistakes

1. **Relying only on HTML5 frontend validation (`required` attribute):** Users can easily bypass browser checks using DevTools or curl. Always validate on the server side using Django forms!

---

## 10. Best Practices

- Always perform server-side validation regardless of client-side JavaScript checks.
- Use `RegexValidator` for standardized formats (postal codes, phone numbers, employee IDs).
- Provide helpful custom `error_messages` that instruct users how to correct errors.

## 12. Interview Questions

**Q1: Why must server-side validation always be performed even if client-side validation is active?**  
*Answer:* Client-side validation (HTML5 attributes and JavaScript) can be completely bypassed by disabling JavaScript in the browser, tampering with requests via browser DevTools, or sending direct HTTP requests using tools like cURL or Postman. Server-side validation is the only trustworthy security barrier for data integrity.

**Q2: What is the purpose of `django.core.validators`?**  
*Answer:* It provides reusable validation callables that can be attached to both Form fields and Model fields, such as `EmailValidator`, `URLValidator`, `RegexValidator`, `MinValueValidator`, `MaxValueValidator`, and `validate_slug`.

---

## 13. Summary

- Django provides field-level constraints (`max_length`, `min_value`, etc.).
- `validators=[...]` applies reusable validation callables.
- Custom messages are specified via `error_messages={...}`.
