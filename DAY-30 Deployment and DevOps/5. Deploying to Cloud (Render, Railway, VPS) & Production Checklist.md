# 5. Deploying to Cloud and Production Checklist

## 1. Introduction

You have developed, tested, and optimized your Django application. Now comes the final milestone: **Deploying to Cloud Infrastructure**. Whether choosing a modern Platform-as-a-Service (PaaS like Render or Railway) or configuring an unmanaged Virtual Private Server (VPS like AWS EC2, DigitalOcean, or Hetzner), following a systematic **Production Launch Checklist** guarantees a smooth, secure launch.

---

## 2. Why Do We Need It?

- A successful deployment requires orchestrating migrations, static assets, database connections, SSL certificates, environment variables, and process supervisors.
- A single missed security setting (`DEBUG=True`, weak `SECRET_KEY`, open CORS) can compromise user data on day one.
- Having a standardized deployment workflow prevents costly downtime during application releases.

---

## 3. How It Works

### Deployment Options Overview

| Platform | Difficulty | Cost | Control | Best For |
|---|---|---|---|---|
| **Render / Railway** (PaaS) | Low (Git push deploy) | $7 - $20 / mo | Managed | Solo developers, MVPs, quick launches |
| **DigitalOcean / AWS EC2** (VPS) | Medium (Linux config) | $5 - $20 / mo | Full Root | Production apps, custom setups, cost efficiency |
| **AWS ECS / Google Cloud Run** | High (Containers) | Pay per use | High | Scalable enterprise apps, microservices |

## 5. Practical Examples

### 1. Unified `build.sh` Script for PaaS Deployments
```bash
#!/usr/bin/env bash
# File: build.sh
# Exit immediately if any command returns non-zero status
set -o errexit

echo "--- Installing Python Dependencies ---"
pip install --upgrade pip
pip install -r requirements.txt

echo "--- Collecting Static Files ---"
python manage.py collectstatic --no-input

echo "--- Applying Database Migrations ---"
python manage.py migrate --no-input

echo "--- Build Completed Successfully! ---"
```

### 2. Free Automated SSL with Certbot on Ubuntu VPS
```bash
# Install Certbot and Nginx plugin
sudo apt update
sudo apt install -y certbot python3-certbot-nginx

# Obtain and install SSL certificate automatically
sudo certbot --nginx -d ems.mycompany.com --non-interactive --agree-tos -m admin@mycompany.com

# Verify automatic renewal timer
sudo systemctl status certbot.timer
```

---

## 6. Code Explanation

- `build.sh`: Automatically invoked by PaaS platforms on every `git push`. Runs dependency installation, static collection, and database migrations in sequence.
- `certbot --nginx`: Certbot inspects your Nginx configuration, issues a free Let's Encrypt TLS certificate, configures HTTPS redirection, and schedules auto-renewal via systemd timers.
- `set -o errexit`: Ensures the deployment fails immediately if migrations fail, preventing broken releases from going live.

## 8. Real-World Use Case

**Zero-Downtime Blue-Green Deployment:**
Using a cloud load balancer in front of two identical VPS instances. When releasing version 2.0, the update is deployed and verified on instance B ("Green"), after which the load balancer switches all user traffic over seamlessly.

---

## 9. Common Mistakes

1. **Running Migrations Manually After Deploy:** If code relies on new database columns, views fail until migrations are applied. Always automate migrations during build time.
2. **Missing Media Storage Solution:** PaaS instances have ephemeral filesystems. Uploaded user images saved locally vanish upon the next deployment or dyno restart! Use Amazon S3 or Cloudflare R2 for media files.
3. **Neglecting Automated SSL Renewal:** Forgetting to verify Certbot renewal results in expired certificates and scary browser warning pages.

---

## 10. Best Practices

### Complete Pre-Flight Production Checklist
1. [ ] `DEBUG = False` verified.
2. [ ] Cryptographically strong `SECRET_KEY` loaded from environment variables.
3. [ ] `ALLOWED_HOSTS` configured with exact domain names.
4. [ ] Database migrated to MySQL/Postgres with `utf8mb4`.
5. [ ] `collectstatic` executed; static assets served via WhiteNoise or CDN.
6. [ ] User-uploaded media routed to Amazon S3 / object storage.
7. [ ] HTTPS enforced with valid TLS certificate and HSTS enabled.
8. [ ] Error monitoring configured (Sentry).
9. [ ] Automated database backup cron/snapshots scheduled.
10. [ ] `python manage.py check --deploy` passes with 0 warnings.

## 12. Interview Questions

**Q1: What is an ephemeral filesystem and how does it affect Django file uploads on platforms like Render or Heroku?**
*Answer:* An ephemeral filesystem means any files created on the local container or virtual disk are temporary and will be discarded whenever the container restarts, sleeps, or deploys a new release. If users upload profile pictures to a local `media/` folder, those pictures will be permanently lost on the next deployment. To prevent this, Django media storage must be decoupled from the server using cloud object storage (such as Amazon S3, Google Cloud Storage, or Cloudflare R2) via `django-storages`.

**Q2: How do you handle database migrations that modify existing columns with zero downtime?**
*Answer:* Zero-downtime migrations follow the **Expand and Contract pattern**:
1. **Expand:** Add the new column/table without modifying or removing existing columns. Deploy code that writes to both columns.
2. **Backfill:** Run background tasks or management commands to migrate historical data from the old column to the new column.
3. **Contract:** Update code to read and write exclusively from the new column. Finally, deploy a subsequent migration that safely removes the old unused column.

## 13. Summary

- Deploy to PaaS (Render/Railway) for simplicity, or VPS (Ubuntu/Nginx) for full control.
- Automate builds with `build.sh` (dependencies, static collection, migrations).
- Store media assets on cloud object storage (S3).
- Complete the 10-point production deployment checklist before launch.
