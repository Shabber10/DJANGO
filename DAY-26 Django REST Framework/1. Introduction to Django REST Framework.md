# 1. Introduction to Django REST Framework

## 1. Introduction

**Django REST Framework (DRF)** is a powerful, flexible toolkit for building Web APIs in Django. It is the de facto industry standard for building RESTful backends in the Python ecosystem, trusted by companies like Red Hat, Mozilla, and Eventbrite.

---

## 2. Why Do We Need It?

While pure Django *can* return JSON, writing enterprise APIs manually requires hundreds of lines of boilerplate:
- DRF provides **Serializers** that automatically serialize complex QuerySets to JSON and deserialize incoming JSON to validated model instances.
- DRF provides a **Web-Browsable API**—an interactive HTML UI where developers can test endpoints directly in the browser without needing Postman!
- DRF provides built-in support for authentication (Token, Session, JWT), permissions, pagination, filtering, throttling, and ViewSets.

---

## 3. How It Works

1. Install package: `pip install djangorestframework`.
2. Add `'rest_framework'` to `INSTALLED_APPS` in `settings.py`.
3. Configure global defaults in the `REST_FRAMEWORK` settings dictionary.
4. Define serializers and views using DRF classes.

---

## 4. Syntax

### Installing DRF:
```bash
pip install djangorestframework
```

In `config/settings.py`:
```python
INSTALLED_APPS = [
    ...,
    'django.contrib.staticfiles',
    # Django REST Framework
    'rest_framework',
    'rest_framework.authtoken',
]

REST_FRAMEWORK = {
    # Default Authentication
    'DEFAULT_AUTHENTICATION_CLASSES': [
        'rest_framework.authentication.SessionAuthentication',
        'rest_framework.authentication.TokenAuthentication',
    ],
    # Default Permissions (e.g. read-only for guests, write for authenticated)
    'DEFAULT_PERMISSION_CLASSES': [
        'rest_framework.permissions.IsAuthenticatedOrReadOnly',
    ],
    # Default Pagination
    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination',
    'PAGE_SIZE': 10,
}
```

## 5. Practical Examples

### Exploring the Browsable API
When you visit any DRF endpoint in a standard web browser (e.g. `http://127.0.0.1:8000/api/products/`), DRF automatically detects the browser's `Accept: text/html` header and renders the **Browsable API**:
- Interactive GET response viewer with syntax-highlighted JSON.
- An interactive POST/PUT web form at the bottom allowing you to submit test JSON payloads without opening external API tools!
- If requested by an API client (Postman/cURL with `Accept: application/json`), it returns pure, compact JSON.

---

## 6. Code Explanation

- `rest_framework`: The core engine providing serializers, views, and parsers.
- `REST_FRAMEWORK`: Centralized settings dictionary controlling global API behavior.
- Content Negotiation: DRF automatically inspects the client's `Accept` HTTP header to choose between raw JSON and the HTML Browsable API.

---

## 7. Expected Output

Navigating to a DRF endpoint in Chrome/Firefox:
Renders a polished, dark/light themed web console with:
- `HTTP 200 OK`
- `Allow: GET, POST, HEAD, OPTIONS`
- `Content-Type: application/json`
- Prettified JSON data and interactive form controls.

---

## 8. Real-World Use Case

Powering single-page web applications (React, Angular, Vue), mobile backends (iOS, Android, React Native), and public developer developer APIs.

---

## 9. Common Mistakes

1. **Forgetting to add `'rest_framework'` to `INSTALLED_APPS`:** Causes `ModuleNotFoundError` or missing static CSS/JS on the browsable API UI.

---

## 10. Best Practices

- Configure sensible defaults in `settings.REST_FRAMEWORK` (pagination, authentication, permissions).
- Leverage the browsable API for rapid manual testing during development.

## 12. Interview Questions

**Q1: What are the key features that make Django REST Framework so popular?**  
*Answer:* DRF provides:
1. The Web-Browsable API for instant in-browser testing.
2. Powerful Serializers supporting both ORM models and non-ORM data sources.
3. Pluggable authentication (Session, Basic, Token, OAuth2, JWT).
4. Extensive permission and throttling policies.
5. High-level ViewSets and Routers that generate full CRUD REST APIs in minimal code.

**Q2: How do you configure DRF to only return JSON responses in production (disabling the Browsable API)?**  
*Answer:* By setting `DEFAULT_RENDERER_CLASSES` in `settings.REST_FRAMEWORK` to include only `JSONRenderer`:
```python
REST_FRAMEWORK = {
    'DEFAULT_RENDERER_CLASSES': [
        'rest_framework.renderers.JSONRenderer',
    ]
}
```
