# 2. Serializers and ModelSerializers

## 1. Introduction

At the heart of Django REST Framework lies the **Serializer**. Serializers perform a two-way transformation:
1. **Serialization:** Converting complex Django model instances and QuerySets into native Python datatypes that can easily be rendered into JSON.
2. **Deserialization & Validation:** Parsing incoming JSON payloads, validating the data against field rules, and converting it back into validated Python objects or database model records.

---

## 2. Why Do We Need It?

Manually converting model attributes into dictionaries (`{'name': p.name, 'price': float(p.price)}`) is repetitive, fragile, and does not handle nested relationships or validation. **`ModelSerializer`** provides an automated shortcut that mirrors model fields, validators, and relationships with zero boilerplate.

---

## 3. How It Works

- **`serializers.Serializer`:** Base class where you explicitly declare every field and write `create()` and `update()` methods manually (similar to standard Django `forms.Form`).
- **`serializers.ModelSerializer`:** Advanced subclass that inspects the model and auto-generates fields, validators, and default `create()` and `update()` implementations (similar to `forms.ModelForm`).

---

## 4. Syntax

```python
# File: store/serializers.py
from rest_framework import serializers
from .models import Product, Category

class ProductSerializer(serializers.ModelSerializer):
    # Custom read-only calculated field
    discounted_price = serializers.SerializerMethodField()

    class Meta:
        model = Product
        fields = ['id', 'name', 'price', 'stock_count', 'discounted_price', 'created_at']
        read_only_fields = ['id', 'created_at']

    def get_discounted_price(self, obj):
        # obj is the Product instance
        return float(obj.price) * 0.90 # 10% discount

    # Custom field-level validation (clean_<field> equivalent):
    def validate_price(self, value):
        if value <= 0:
            raise serializers.ValidationError("Price must be strictly positive.")
        return value
```

## 5. Practical Examples

### Nested Relationships in Serializers
```python
# File: store/serializers.py
from rest_framework import serializers
from .models import Category, Product

class CategorySerializer(serializers.ModelSerializer):
    class Meta:
        model = Category
        fields = ['id', 'name']

class DetailedProductSerializer(serializers.ModelSerializer):
    # Nested serializer (read-only nested object representation!)
    category = CategorySerializer(read_only=True)
    # Write-only ID for updating relationship
    category_id = serializers.PrimaryKeyRelatedField(
        queryset=Category.objects.all(), source='category', write_only=True
    )

    class Meta:
        model = Product
        fields = ['id', 'name', 'price', 'category', 'category_id']
```

---

## 6. Code Explanation

- `ModelSerializer`: Auto-maps model fields to serializer fields.
- `SerializerMethodField`: A read-only field whose value is calculated by calling a method named `get_<field_name>()`.
- `validate_<fieldname>(self, value)`: Field-level validation hook that raises `serializers.ValidationError`.
- `read_only_fields`: Fields included in outgoing JSON but ignored in incoming POST/PUT payloads.

---

## 7. Expected Output

Serializing in Django shell:
```python
>>> p = Product.objects.get(id=1)
>>> serializer = ProductSerializer(p)
>>> serializer.data
{'id': 1, 'name': 'Laptop', 'price': '999.99', 'discounted_price': 899.991, 'stock_count': 12, 'created_at': '2026-10-31T12:00:00Z'}
```

## 8. Real-World Use Case

Validating user inputs in mobile registration APIs, formatting monetary decimals, and returning nested relationship graphs in REST endpoints.

## 9. Common Mistakes

1. **Forgetting to check `serializer.is_valid()` before accessing `serializer.validated_data`:**
   Accessing `validated_data` before validation raises `AssertionError: You must call .is_valid() before accessing .validated_data`.

---

## 10. Best Practices

- Explicitly list allowed fields in `Meta.fields`; avoid `'__all__'` on public write endpoints.
- Use `SerializerMethodField` for dynamic computed properties.
- Use `nested serializers` for rich GET representations and `PrimaryKeyRelatedField` for writes.

## 12. Interview Questions

**Q1: What is the difference between `serializer.validated_data` and `serializer.data`?**  
*Answer:* `serializer.validated_data` is a dictionary of sanitized Python objects populated during deserialization after calling `serializer.is_valid()`, used to create or update model records. `serializer.data` is the outgoing serialized dictionary representation of model instances prepared for JSON encoding.

**Q2: What is the N+1 query problem in DRF Serializers and how do you resolve it?**  
*Answer:* When a serializer includes related fields (e.g. `category = CategorySerializer()` or foreign key fields) and serializes a QuerySet of 100 items, DRF will execute 1 query for the list and 100 separate queries to fetch the related object for each item. This is resolved by ensuring the view's QuerySet utilizes `select_related()` (for ForeignKeys) or `prefetch_related()` (for ManyToMany).

---

## 13. Summary

- Serializers convert models to JSON and validate incoming payloads.
- `ModelSerializer` automates field generation from models.
- `validate_<field>()` handles custom field validation.
