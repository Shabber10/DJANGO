# 4. GenericAPIView and Concrete Generic Views

## 1. Introduction

While `APIView` provides complete control, writing identical `get()`, `post()`, and `delete()` handlers for every model in your database creates repetitive boilerplate. DRF solves this by providing **Concrete Generic Views**—pre-built combinations of **`GenericAPIView`** and **Mixins** that implement complete CRUD endpoints in 2 lines of code.

---

## 2. Why Do We Need It?

- **Speed:** Build production-grade, validated, paginated REST endpoints in seconds.
- **Consistency:** Standardizes status codes, error handling, and query lookups across your entire API surface.
- **Maintainability:** Easily override specific hooks (`perform_create`, `get_queryset`) without rewriting standard plumbing.

---

## 3. How It Works

DRF provides 9 Concrete Generic Views in `rest_framework.generics`:
- **`ListAPIView`:** Read-only list of records (GET).
- **`CreateAPIView`:** Creation endpoint (POST).
- **`RetrieveAPIView`:** Read-only single record (GET).
- **`UpdateAPIView`:** Update single record (PUT/PATCH).
- **`DestroyAPIView`:** Delete single record (DELETE).
- **`ListCreateAPIView`:** List (GET) + Create (POST).
- **`RetrieveUpdateAPIView`:** Read (GET) + Update (PUT/PATCH).
- **`RetrieveDestroyAPIView`:** Read (GET) + Delete (DELETE).
- **`RetrieveUpdateDestroyAPIView`:** Read (GET) + Update (PUT/PATCH) + Delete (DELETE).

---

## 4. Syntax

```python
# File: store/views.py
from rest_framework import generics
from .models import Product
from .serializers import ProductSerializer

# 1. Endpoint for: GET (list) and POST (create)
class ProductListCreateView(generics.ListCreateAPIView):
    queryset = Product.objects.all().order_by('-created_at')
    serializer_class = ProductSerializer

# 2. Endpoint for: GET (retrieve), PUT/PATCH (update), DELETE (destroy)
class ProductDetailView(generics.RetrieveUpdateDestroyAPIView):
    queryset = Product.objects.all()
    serializer_class = ProductSerializer
```

In `urls.py`:
```python
urlpatterns = [
    path('products/', views.ProductListCreateView.as_view(), name='product_list_create'),
    path('products/<int:pk>/', views.ProductDetailView.as_view(), name='product_detail'),
]
```

## 5. Practical Examples

### Overriding `perform_create` to Attach User
```python
# File: blog/views.py
from rest_framework import generics, permissions
from .models import Article
from .serializers import ArticleSerializer

class ArticleListCreateAPIView(generics.ListCreateAPIView):
    serializer_class = ArticleSerializer
    permission_classes = [permissions.IsAuthenticatedOrReadOnly]

    def get_queryset(self):
        # Filter: only show published articles to guests, all to staff
        if self.request.user.is_staff:
            return Article.objects.all()
        return Article.objects.filter(is_published=True)

    def perform_create(self, serializer):
        # Attach the currently authenticated user as the author!
        serializer.save(author=self.request.user)
```

---

## 6. Code Explanation

- `queryset`: The base collection of records queried by the view.
- `serializer_class`: The serializer used for validating input and serializing output.
- `perform_create(self, serializer)`: Hook called during `POST` before saving. Allows passing additional keyword arguments directly to `serializer.save()`.

---

## 7. Expected Output

With just 8 lines of code in `ArticleListCreateAPIView`:
- `GET /api/articles/`: Returns paginated JSON list of articles.
- `POST /api/articles/`: Validates JSON, auto-attaches `request.user` as author, saves record, and returns `201 Created`.

---

## 8. Real-World Use Case

Building standard microservice CRUD endpoints for mobile and web frontends with high speed and zero boilerplate.

---

## 9. Common Mistakes

1. Calling `serializer.save()` manually inside an overridden `create()` method and forgetting that `perform_create()` exists specifically for this purpose.

---

## 10. Best Practices

- Use `ListCreateAPIView` and `RetrieveUpdateDestroyAPIView` for standard endpoints.
- Override `get_queryset()` for dynamic, user-scoped filtering.
- Override `perform_create()` and `perform_update()` to attach metadata.

## 12. Interview Questions

**Q1: What is the purpose of `perform_create()` in DRF Generic Views?**  
*Answer:* `perform_create(self, serializer)` is a lifecycle hook provided by `CreateModelMixin` that is called when a valid serializer is about to be saved. It allows developers to customize the persistence step—such as injecting attributes not present in the request payload (e.g., `serializer.save(owner=self.request.user)`), sending notification emails, or triggering background Celery tasks.

**Q2: What is the difference between `APIView` and `GenericAPIView`?**  
*Answer:* `APIView` is the base class providing only request dispatching, authentication, and content negotiation. `GenericAPIView` inherits from `APIView` and adds database-aware attributes and methods (`queryset`, `serializer_class`, `get_object()`, `get_queryset()`), serving as the foundational base for Mixins and Concrete Generic Views.

---

## 13. Summary

- Concrete generic views automate common CRUD patterns.
- `ListCreateAPIView` handles collections; `RetrieveUpdateDestroyAPIView` handles individual items.
- Override `perform_create` to attach metadata.
