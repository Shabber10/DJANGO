# 5. ViewSets and Routers

## 1. Introduction

The highest level of abstraction in Django REST Framework is the **ViewSet**. Rather than writing separate view classes for listing, retrieving, creating, updating, and deleting records, a ViewSet combines all of these operations into a single cohesive class. When paired with **Routers**, DRF automatically generates the complete URL scheme.

---

## 2. Why Do We Need It?

- **Ultimate DRY Code:** A single `ModelViewSet` class provides all 5 CRUD operations in 4 lines of code.
- **Automated Routing:** `DefaultRouter` automatically generates all URL patterns (`/products/`, `/products/<pk>/`), including trailing slash handling.
- **Convention over Configuration:** Ensures consistent URL conventions across large engineering teams.

---

## 3. How It Works

- **`ModelViewSet`:** Inherits from `GenericAPIView` and all 5 model mixins (`List`, `Create`, `Retrieve`, `Update`, `Destroy`).
- Action Methods:
  - `list()`: GET `/items/`
  - `create()`: POST `/items/`
  - `retrieve()`: GET `/items/pk/`
  - `update()`: PUT `/items/pk/`
  - `partial_update()`: PATCH `/items/pk/`
  - `destroy()`: DELETE `/items/pk/`
- Custom actions: Defined using the **`@action`** decorator.

---

## 4. Syntax

```python
# File: store/views.py
from rest_framework import viewsets
from rest_framework.decorators import action
from rest_framework.response import Response
from .models import Product
from .serializers import ProductSerializer

class ProductViewSet(viewsets.ModelViewSet):
    queryset = Product.objects.all().order_by('-created_at')
    serializer_class = ProductSerializer

    # Custom non-standard endpoint: /api/products/in_stock/
    @action(detail=False, methods=['get'])
    def in_stock(self, request):
        in_stock_products = self.get_queryset().filter(stock_count__gt=0)
        serializer = self.get_serializer(in_stock_products, many=True)
        return Response(serializer.data)
```

In `urls.py`:
```python
# File: config/urls.py
from rest_framework.routers import DefaultRouter
from django.urls import path, include
from store.views import ProductViewSet

router = DefaultRouter()
router.register(r'products', ProductViewSet, basename='product')

urlpatterns = [
    path('api/', include(router.urls)),
]
```

---

## 5. Practical Examples

### Inspecting the Generated URL Patterns
Registering `router.register(r'products', ProductViewSet)` automatically creates:
```text
URL Pattern                    HTTP Method     Action Method
------------------------------------------------------------
/api/products/                 GET             list
/api/products/                 POST            create
/api/products/<pk>/            GET             retrieve
/api/products/<pk>/            PUT             update
/api/products/<pk>/            PATCH           partial_update
/api/products/<pk>/            DELETE          destroy
/api/products/in_stock/        GET             in_stock
```

---

## 6. Code Explanation

- `viewsets.ModelViewSet`: Complete CRUD implementation in one class.
- `DefaultRouter`: Automatically maps standard REST actions to URLs and generates an API root index page.
- `@action(detail=False)`: Adds a collection-level custom route (`/products/in_stock/`).
- `@action(detail=True)`: Adds a detail-level custom route requiring a primary key (e.g. `POST /products/42/archive/`).

Navigating to `http://127.0.0.1:8000/api/` in the browser:
The `DefaultRouter` renders an **API Root** dashboard listing all registered resources:

## 8. Real-World Use Case

Rapid API development for enterprise backends where dozens of database entities each require full CRUD capabilities.

---

## 9. Common Mistakes

1. **Forgetting `basename` when `queryset` is not defined directly on the ViewSet:** If you override `get_queryset()` and omit the `queryset` class attribute, you MUST provide `basename='modelname'` in `router.register()`.

---

## 10. Best Practices

- Use `ModelViewSet` for standard database entities.
- Use `@action` for domain operations (e.g., `/orders/12/cancel/`, `/users/verify_email/`).
- Use `DefaultRouter` for automatic API root discovery.

## 12. Interview Questions

**Q1: What is the architectural difference between an `APIView` and a `ViewSet` in DRF?**  
*Answer:* An `APIView` binds directly to HTTP method handlers (`get()`, `post()`, `delete()`) and is mapped individually in `urls.py` using `.as_view()`. A `ViewSet` binds to higher-level action handlers (`list()`, `create()`, `retrieve()`, `update()`, `destroy()`). It does not bind to HTTP methods until it is dynamically wired to a `Router`, allowing a single class to manage all endpoints for a resource with automated URL generation.

**Q2: What is the `@action` decorator in DRF?**  
*Answer:* `@action` is a decorator used inside ViewSets to declare custom endpoints beyond standard CRUD. Setting `detail=False` mounts the route at the collection level (e.g., `/users/recent/`), while `detail=True` mounts it at the instance level (e.g., `/users/<pk>/set_password/`), with configurable `methods` (e.g. `['POST']`) and custom permission classes.

---

## 13. Summary

- ViewSets bundle CRUD actions into a single class.
- Routers auto-generate standardized RESTful URLs.
- `@action` defines custom collection and detail endpoints.
