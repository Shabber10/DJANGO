# 3. User Login, Logout, and Authentication Views

## 1. Introduction

Once users are registered, they need to log in to access authenticated features and log out to terminate their sessions. Django provides both low-level functions (**`authenticate()`**, **`login()`**, **`logout()`**) and ready-to-use Class-Based Authentication Views (**`LoginView`**, **`LogoutView`**).

---

## 2. Why Do We Need It?

Managing authentication manually requires:
- Verifying credentials against the database.
- Creating a secure cryptographic session ID in cookies.
- Preventing **Session Fixation** attacks by cycling session keys.
- Cleaning up session tables upon logout.
Django's authentication system automates all of these security details.

---

## 3. How It Works

### The Login Sequence:
1. `authenticate(request, username=u, password=p)`: Queries active auth backends. If credentials match and the account is active, returns the `User` instance; otherwise returns `None`.
2. `login(request, user)`: Attaches the user ID to the session, rotates the session key (preventing session fixation), and sets the session cookie in the client browser.
3. `logout(request)`: Clears the session data, flushes the session cookie, and resets `request.user` to `AnonymousUser`.

---

## 4. Syntax

```python
# Low-level Function-Based Auth:
from django.contrib.auth import authenticate, login, logout
from django.shortcuts import render, redirect

def manual_login(request):
    if request.method == "POST":
        u = request.POST.get('username')
        p = request.POST.get('password')
        user = authenticate(request, username=u, password=p)
        if user is not None:
            login(request, user)
            return redirect('dashboard')
        else:
            return render(request, 'login.html', {'error': 'Invalid credentials'})
    return render(request, 'login.html')

def manual_logout(request):
    logout(request)
    return redirect('login')
```

### Preferred High-Level Route in `urls.py`:
```python
from django.contrib.auth import views as auth_views
from django.urls import path

urlpatterns = [
    path('login/', auth_views.LoginView.as_view(template_name='registration/login.html'), name='login'),
    path('logout/', auth_views.LogoutView.as_view(), name='logout'),
]
```

## 5. Practical Examples

### Protecting Views with `@login_required`
```python
# File: accounts/views.py
from django.contrib.auth.decorators import login_required
from django.shortcuts import render

@login_required
def dashboard_view(request):
    # Only authenticated users can ever reach this line!
    return render(request, 'accounts/dashboard.html', {
        'user': request.user,
        'email': request.user.email
    })
```

In `settings.py`:
```python
# Where to redirect unauthenticated users
LOGIN_URL = 'login'
# Where to redirect users after logging in
LOGIN_REDIRECT_URL = 'dashboard'
# Where to redirect users after logging out
LOGOUT_REDIRECT_URL = 'login'
```

---

## 6. Code Explanation

- `@login_required`: A view decorator. If the visitor is not authenticated, it immediately redirects them to `LOGIN_URL` with a `?next=/target/url/` query parameter.
- After successful login, Django automatically redirects the user back to whatever `?next=` URL they originally requested!
- In modern Django (5.0+), `LogoutView` requires an **HTTP POST** request for security reasons.

---

## 7. Expected Output

Visiting `/dashboard/` as a guest:
Browser is redirected to `http://127.0.0.1:8000/login/?next=/dashboard/`.
Upon entering valid credentials, Django logs you in and redirects you back to `/dashboard/`.

---

## 8. Real-World Use Case

Customer account portals, subscriber paywalls, employee intranets, and SaaS application dashboards.

---

## 9. Common Mistakes

1. **Calling `login(request, user)` without authenticating first:** Always verify credentials with `authenticate()` before calling `login()`.
2. Sending GET requests to `LogoutView` in Django 5.0+ (produces HTTP 405 Method Not Allowed; logout must use POST).

---

## 10. Best Practices

- Configure `LOGIN_URL`, `LOGIN_REDIRECT_URL`, and `LOGOUT_REDIRECT_URL` in `settings.py`.
- Always use POST forms for logouts to prevent malicious sites from logging users out via image pre-fetching.
- Apply `@login_required` to all private views.

## 12. Interview Questions

**Q1: What is Session Fixation and how does Django protect against it?**  
*Answer:* Session fixation is an attack where an attacker tricks a victim into authenticating using a known session ID, allowing the attacker to hijack the session once the user logs in. Django mitigates this by calling `request.session.cycle_key()` inside `login()`, which destroys the old anonymous session key and generates a completely new, cryptographically unique session ID upon authentication.

**Q2: What is the difference between `authenticate()` and `login()`?**  
*Answer:* `authenticate(request, **credentials)` verifies whether the supplied username/password match an active user and returns the `User` instance (or `None`). It does NOT alter session state. `login(request, user)` takes an authenticated user instance and creates the session, setting the session cookie on the outgoing response.

---

## 13. Summary

- `authenticate()` verifies credentials; `login()` creates the session.
- `@login_required` enforces authentication on views.
- Configuration settings (`LOGIN_URL`, `LOGIN_REDIRECT_URL`) guide redirection.
