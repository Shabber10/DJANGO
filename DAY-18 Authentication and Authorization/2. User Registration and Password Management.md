# 2. User Registration and Password Management

## 1. Introduction

User onboarding begins with account registration. Storing passwords securely is one of the most critical responsibilities of backend engineering. Django includes robust built-in password management forms, cryptographic password hashing engines, and password validation pipelines.

---

## 2. Why Do We Need It?

- **Security:** Storing plaintext passwords is an catastrophic failure. If the database is compromised, plaintext credentials expose users across every service they use.
- **Validation:** Weak passwords (`123456`, `password`) leave accounts vulnerable to brute-force credential stuffing.
- Django hashes passwords using **PBKDF2 with SHA-256** and salt by default, and enforces customizable password strength rules.

---

## 3. How It Works

When a password is saved:
1. Django runs the password through `AUTH_PASSWORD_VALIDATORS` in `settings.py`.
2. Django generates a random cryptographic salt.
3. It passes the password, salt, and iterations through PBKDF2-SHA256 (over 720,000 iterations!).
4. The database stores the combined hash string: `<algorithm>$<iterations>$<salt>$<hash>`.
5. When checking a login, Django re-hashes the submitted password with the stored salt and compares the hashes.

---

## 4. Syntax

```python
# File: accounts/views.py
from django.shortcuts import render, redirect
from django.contrib.auth.forms import UserCreationForm
from django.contrib.auth import login

def register_view(request):
    if request.method == "POST":
        form = UserCreationForm(request.POST)
        if form.is_valid():
            user = form.save() # Hashes password and saves User record!
            login(request, user) # Automatically log in the user after signup!
            return redirect('dashboard')
    else:
        form = UserCreationForm()
    return render(request, 'registration/register.html', {'form': form})
```

## 5. Practical Examples

### Programmatic Password Hashing with User Model
```python
from django.contrib.auth.models import User
from django.contrib.auth.hashers import make_password, check_password

# Setting a password safely on a user instance:
user = User(username="rajesh", email="rajesh@example.com")
user.set_password("SuperSecretP@ssword2026!") # Hashes automatically!
user.save()

# Inspecting raw hash in database:
print(user.password)
# pbkdf2_sha256$720000$Kj3f9D...$m8Z4x...

# Verifying passwords:
user.check_password("SuperSecretP@ssword2026!") # Returns True
user.check_password("wrong_password")           # Returns False
```

---

## 6. Code Explanation

- `UserCreationForm`: Built-in ModelForm for the `User` model that collects username, password, and password confirmation with automated validation.
- `user.set_password(raw_password)`: Never assign `user.password = "mypass"`! Always use `user.set_password()`, which computes the PBKDF2 hash.
- `user.check_password(raw_password)`: Compares a candidate raw password against the stored hash securely using constant-time string comparison to prevent timing attacks.

---

## 7. Expected Output

Stored password column in SQLite/PostgreSQL `auth_user`:
```text
pbkdf2_sha256$720000$g9Wz9Nf8k21$QjF...8aBc
```
Notice the raw password is never stored anywhere on the server!

## 8. Real-World Use Case

User registration flows across consumer portals, e-commerce stores, and financial SaaS applications.

---

## 9. Common Mistakes

1. **Assigning plaintext directly to `user.password`:**
   ```python
   # CRITICAL VULNERABILITY:
   user.password = "my_password" # Plaintext saved to database! User will NEVER be able to log in!
   # CORRECT:
   user.set_password("my_password")
   ```
2. Disabling password validators in `settings.py` during production.

---

## 10. Best Practices

- Always use `user.set_password()` or `UserCreationForm`.
- Automatically log the user in using `login(request, user)` after successful signup for seamless onboarding.
- Enforce Argon2 or PBKDF2-SHA256 password hashers.

## 12. Interview Questions

**Q1: How does Django store user passwords securely in the database?**  
*Answer:* Django uses a one-way cryptographic hash with a unique random salt per user (by default, PBKDF2 with SHA-256 and over 720,000 iterations). The database stores the combined string: `<algorithm>$<iterations>$<salt>$<hash>`. Because the hash is one-way, the original password cannot be decrypted even if the database is leaked.

**Q2: What is the purpose of `check_password()`?**  
*Answer:* `check_password(raw_password, encoded_hash)` extracts the salt and iteration count from the encoded hash, passes the candidate raw password through the same hashing function, and compares the resulting hash using constant-time comparison (`secrets.compare_digest`), preventing timing analysis attacks.

---

## 13. Summary

- Passwords must never be stored in plaintext.
- `UserCreationForm` handles user signup safely.
- `user.set_password()` computes salted PBKDF2 hashes.
