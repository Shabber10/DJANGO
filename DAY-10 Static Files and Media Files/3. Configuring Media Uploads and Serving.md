# 3. Configuring Media Uploads and Serving

## 1. Introduction

User-uploaded content—such as employee avatars, product images, and PDF attachments—is managed by Django's **Media** subsystem. Configuring media settings ensures that files are safely uploaded to disk and accessible via browser URLs during development.

---

## 2. Why Do We Need It?

By default, Django does **not** serve user-uploaded media files automatically for security reasons. Developers must configure explicit filesystem storage directories (`MEDIA_ROOT`) and public URL routes (`MEDIA_URL`) to handle uploads and serve them locally.

---

## 3. How It Works

1. **`MEDIA_ROOT`:** The absolute path on the server where uploaded files are written (e.g. `BASE_DIR / 'media'`).
2. **`MEDIA_URL`:** The public URL prefix for serving those files (e.g. `'/media/'`).
3. In local development (`DEBUG = True`), you connect `MEDIA_URL` to `MEDIA_ROOT` in the root `urls.py` using `django.conf.urls.static.static()`.

---

## 4. Syntax

```python
# File: config/settings.py
MEDIA_URL = '/media/'
MEDIA_ROOT = BASE_DIR / 'media'
```

```python
# File: config/urls.py
from django.conf import settings
from django.conf.urls.static import static
from django.urls import path

urlpatterns = [
    # Application routes here...
]

# Serve media files in development ONLY
if settings.DEBUG:
    urlpatterns += static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
```

---

## 5. Practical Examples

### Model Definition with an ImageField
```python
# File: accounts/models.py
from django.db import models
from django.contrib.auth.models import User

class UserProfile(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE)
    # Requires Pillow library: pip install Pillow
    avatar = models.ImageField(upload_to='avatars/', default='avatars/default.png')
    bio = models.TextField(blank=True)

    def __str__(self):
        return self.user.username
```

In template (`profile.html`):
```html
<div class="profile-card">
    <img src="{{ profile.avatar.url }}" alt="{{ profile.user.username }}" width="150" height="150">
    <h2>{{ profile.user.get_full_name }}</h2>
    <p>{{ profile.bio }}</p>
</div>
```

---

## 6. Code Explanation

- `upload_to='avatars/'`: Uploaded files will be stored inside `MEDIA_ROOT / 'avatars/'`.
- `profile.avatar.url`: Retrieves the public browser URL (e.g. `/media/avatars/john_doe.jpg`).
- `static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)`: Adds a temporary view to `urlpatterns` that serves uploaded files while `DEBUG=True`.

---

## 7. Expected Output

When a user uploads `photo.jpg`:
- The file is saved at: `C:/Users/.../myproject/media/avatars/photo.jpg`.
- Visiting `http://127.0.0.1:8000/media/avatars/photo.jpg` renders the image in the browser with `status 200 OK`.

---

## 8. Real-World Use Case

Customer support ticket portals allowing users to upload screenshots of error messages; e-commerce admin panels allowing catalog managers to upload product photos.

---

## 9. Common Mistakes

1. **Forgetting `if settings.DEBUG:` check in `urls.py`:** Serving media files directly through Django in production is insecure and slow. In production, use AWS S3, Cloudflare R2, or Nginx.
2. Forgetting to install **Pillow** (`pip install Pillow`) before using `models.ImageField`.

---

## 10. Best Practices

- Install Pillow when using `ImageField`.
- Always wrap media URL patterns inside `if settings.DEBUG:`.
- Use dynamic `upload_to` functions to organize uploads by user ID or date (`upload_to='uploads/%Y/%m/%d/'`).

## 12. Interview Questions

**Q1: Why is serving media files through Django in production discouraged?**  
*Answer:* Django's Python process is optimized for dynamic application logic, not static I/O streaming. Serving large binary files through Django blocks worker threads, exhausts RAM, and presents security risks. In production, media should be stored in cloud object storage (e.g., AWS S3, Google Cloud Storage) and served directly via a CDN.

**Q2: What is the purpose of the `upload_to` argument in `FileField`?**  
*Answer:* `upload_to` specifies the subdirectory inside `MEDIA_ROOT` where files will be stored. It can be a subpath string (e.g., `'resumes/'`), a date-formatted string (e.g., `'documents/%Y/%m/'`), or a callable function `(instance, filename)` that dynamically computes the path.

---

## 13. Summary

- `MEDIA_ROOT` defines filesystem storage; `MEDIA_URL` defines public URL paths.
- Local development serves media files via `urls.py` with `static()`.
- Production requires cloud object storage (AWS S3) or Nginx.
