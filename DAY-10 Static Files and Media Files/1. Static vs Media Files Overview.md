# 1. Static vs Media Files Overview

## 1. Introduction

In web development, files that are not Python code or database records are categorized as assets. Django makes a strict, critical architectural distinction between **Static Files** and **Media Files**. Conflating these two concepts leads to security risks and deployment failures.

---

## 2. Why Do We Need It?

- **Static Files** are authored by software developers (CSS stylesheets, JavaScript scripts, UI icons, brand SVG logos). They are version-controlled in Git and deployed alongside code.
- **Media Files** are uploaded at runtime by end-users (profile pictures, PDF invoices, resume attachments). They are dynamic, never checked into Git, and require strict security restrictions to prevent malicious file uploads.

---

## 3. How It Works

### Architectural Comparison:

| Criteria | Static Files | Media Files |
| :--- | :--- | :--- |
| **Origin** | Created by developers | Uploaded by end-users |
| **Git Tracking** | Committed to repository | NEVER committed (`.gitignore`) |
| **URL Setting** | `STATIC_URL = '/static/'` | `MEDIA_URL = '/media/'` |
| **Directory Setting** | `STATICFILES_DIRS` & `STATIC_ROOT`| `MEDIA_ROOT` |
| **Deployment Storage** | Served via CDN or WhiteNoise | Object Storage (AWS S3, Google Cloud Storage) |
| **Cache Lifetime** | Cached indefinitely (cache-busting)| Depends on user privacy rules |

---

## 4. Syntax

```python
# File: config/settings.py
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent.parent

# STATIC FILES
STATIC_URL = '/static/'
STATICFILES_DIRS = [BASE_DIR / 'static']
STATIC_ROOT = BASE_DIR / 'staticfiles'

# MEDIA FILES
MEDIA_URL = '/media/'
MEDIA_ROOT = BASE_DIR / 'media'
```

---

## 5. Practical Examples

### Directory Layout in a Production Project
```text
myproject/
├── .gitignore          <-- Contains: /media/ and /staticfiles/
├── manage.py
├── static/             <-- Developer Assets (Committed to Git)
│   ├── css/
│   │   └── style.css
│   ├── js/
│   │   └── app.js
│   └── images/
│       └── logo.png
└── media/              <-- User Uploads (Ignored in Git!)
    ├── avatars/
    │   └── user_42.jpg
    └── documents/
        └── resume_101.pdf
```

---

## 6. Code Explanation

- `STATICFILES_DIRS`: Where developers keep design assets during development.
- `STATIC_ROOT`: The staging directory where `python manage.py collectstatic` compiles all assets for deployment.
- `MEDIA_ROOT`: The filesystem path where Django saves user uploads triggered via `models.FileField` or `models.ImageField`.

---

## 7. Expected Output

- Developer static assets are referenced as: `/static/css/style.css`.
- User uploaded files are referenced as: `/media/avatars/user_42.jpg`.

---

## 8. Real-World Use Case

In an online publishing platform (Medium clone):
- The layout fonts, stylesheets, and clap icons are **static files**.
- The images uploaded by writers inside their articles are **media files**.

---

## 9. Common Mistakes

1. **Committing the `media/` folder to GitHub:** Causes repository bloat and risks leaking personal user files.
2. Setting `STATIC_ROOT` and `STATICFILES_DIRS` to the same folder.

---

## 10. Best Practices

- Always add `/media/` and `/staticfiles/` to `.gitignore`.
- Treat user-uploaded media files as untrusted content; never permit executing uploaded scripts.

---

## 12. Interview Questions

**Q1: Why does Django separate static files and media files into different settings?**  
*Answer:* Because their security profiles, origins, and deployment lifecycles are completely different. Static files are developer-authored and static, enabling aggressive edge caching and CDN distribution. Media files are generated at runtime by untrusted users, requiring access control, virus scanning, dynamic storage backends (AWS S3), and distinct URL routing.

**Q2: What happens if `STATICFILES_DIRS` contains `STATIC_ROOT`?**  
*Answer:* Django's system check framework will raise an error (`models.E002` or `ImproperlyConfigured`) because `collectstatic` would attempt to copy files recursively into its own source directory, creating an infinite loop.

---

## 13. Summary

- Static files are developer assets; Media files are user uploads.
- Governed by `STATIC_URL`/`STATIC_ROOT` and `MEDIA_URL`/`MEDIA_ROOT`.
- Media files must never be committed to Git.
