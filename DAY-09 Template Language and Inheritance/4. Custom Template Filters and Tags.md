# 4. Custom Template Filters and Tags

## 1. Introduction

Although Django includes dozens of built-in filters and tags, custom business requirements often require proprietary formatting or specialized data retrieval. Django allows developers to extend the template engine by authoring **Custom Template Filters and Tags** in regular Python modules.

---

## 2. Why Do We Need It?

- **Custom Filters:** Transform data types in ways built-in filters cannot (e.g., masking credit card numbers, converting currencies, calculating reading time).
- **Custom Tags:** Execute Python code to fetch database records directly (e.g., fetching the top 5 trending articles for a sidebar widget on any page).

---

## 3. How It Works

To create custom template tags/filters:
1. Inside a Django app, create a directory named **`templatetags/`**.
2. Add an empty `__init__.py` inside `templatetags/`.
3. Create a Python module, e.g., `custom_tags.py`.
4. Instantiate `register = template.Library()`.
5. Decorate functions with `@register.filter` or `@register.simple_tag`.
6. Load the library in templates using `{% load custom_tags %}`.

---

## 4. Syntax

Directory layout:
```text
blog/
├── templatetags/
│   ├── __init__.py
│   └── blog_extras.py
```

Inside `blog/templatetags/blog_extras.py`:
```python
from django import template

register = template.Library()

# 1. Custom Filter:
@register.filter(name='mask_email')
def mask_email(value):
    # Transforms 'shabber@example.com' -> 's***r@example.com'
    if not isinstance(value, str) or '@' not in value:
        return value
    user, domain = value.split('@')
    masked_user = user[0] + '***' + user[-1] if len(user) > 2 else user[0] + '***'
    return f"{masked_user}@{domain}"

# 2. Custom Simple Tag:
@register.simple_tag
def current_time_formatted(format_string="%Y-%m-%d"):
    import datetime
    return datetime.datetime.now().strftime(format_string)
```

## 5. Practical Examples

### Practical Tag: Fetching Recent Posts for a Global Sidebar
```python
# File: blog/templatetags/blog_extras.py
from django import template
from blog.models import Article

register = template.Library()

@register.inclusion_tag('blog/partials/_recent_posts.html')
def show_recent_posts(limit=5):
    recent_articles = Article.objects.filter(is_published=True).order_by('-created_at')[:limit]
    return {'recent_articles': recent_articles}
```

In `blog/templates/blog/partials/_recent_posts.html`:
```html
<div class="sidebar-widget">
    <h4>Recent Articles</h4>
    <ul>
    {% for article in recent_articles %}
        <li><a href="{% url 'blog:detail' pk=article.pk %}">{{ article.title }}</a></li>
    {% empty %}
        <li>No recent articles.</li>
    {% endfor %}
    </ul>
</div>
```

In any template (e.g. `base.html` or `home.html`):
```html
{% load blog_extras %}

<!-- Use the custom filter -->
<p>Contact Support: {{ support_email|mask_email }}</p>

<!-- Render the inclusion tag widget -->
{% show_recent_posts 3 %}
```

---

## 6. Code Explanation

- `register = template.Library()`: Registers custom filters and tags with Django's template engine.
- `@register.filter`: Registers a function as a template filter.
- `@register.inclusion_tag`: An advanced tag that fetches data and automatically renders a sub-template with that data, perfect for site-wide sidebar widgets!

## 8. Real-World Use Case

Inclusion tags are used in production across corporate platforms for dynamic navigation menus, notification badge counts, shopping cart item counters, and footer newsletters.

---

## 9. Common Mistakes

1. **Forgetting `__init__.py` inside `templatetags/`:** Django will not recognize the directory as a Python package, throwing `TemplateSyntaxError: 'blog_extras' is not a registered tag library`.
2. Forgetting to restart the development server after creating the `templatetags/` directory.

---

## 10. Best Practices

- Restart `runserver` immediately after adding a new `templatetags/` package.
- Keep filter functions pure (idempotent without database side effects).
- Use `inclusion_tag` for UI components that require database queries.

## 12. Interview Questions

**Q1: What are the three main types of custom template tags in Django?**  
*Answer:*
1. **Simple Tags (`@register.simple_tag`):** Processes data and returns a formatted string.
2. **Inclusion Tags (`@register.inclusion_tag`):** Processes data and renders an HTML sub-template.
3. **Assignment Tags (`@register.simple_tag` with `as var`):** Stores output in a template variable for subsequent use.

**Q2: What is the `takes_context=True` parameter in custom tags?**  
*Answer:* `takes_context=True` passes the current page's `RequestContext` as the first argument to the tag function, giving the tag access to global variables like `request`, `user`, or `messages`.

## 13. Summary

- Custom filters and tags extend DTL functionality.
- Defined inside `myapp/templatetags/` and registered with `template.Library()`.
- Loaded in templates using `{% load <module_name> %}`.
