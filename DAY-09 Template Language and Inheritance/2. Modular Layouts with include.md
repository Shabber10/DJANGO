# 2. Modular Layouts with include

## 1. Introduction

While `{% extends %}` handles high-level page layouts, the **`{% include %}`** tag handles smaller, reusable UI components. It loads a template snippet, renders it with the current context, and embeds it directly into the including document.

---

## 2. Why Do We Need It?

Many UI elements repeat across different layouts or multiple times on the same page:
- Navigation bars and mobile drawer menus.
- Footers and copyright notices.
- Product cards, comment components, and alert messages.
Using `{% include %}` allows you to maintain these components in separate, reusable partial files (often named with a leading underscore, like `_navbar.html`).

---

## 3. How It Works

When DTL parses `{% include 'partials/_navbar.html' %}`:
1. It locates `_navbar.html`.
2. It passes the active context variables (along with any optional keyword parameters specified via `with`).
3. It renders the snippet and injects the resulting HTML markup in place.

---

## 4. Syntax

```html
<!-- Basic include (inherits active context) -->
{% include 'partials/_navbar.html' %}

<!-- Include with extra isolated variables -->
{% include 'components/_card.html' with title="Special Deal" price=49.99 %}

<!-- Include with only explicit variables (isolated from outer context) -->
{% include 'components/_card.html' with title="Exclusive" only %}
```

---

## 5. Practical Examples

### Reusable Component Architecture
Create `templates/components/_alert.html`:
```html
<!-- Reusable dismissible alert component -->
<div class="alert alert-{{ alert_type|default:'info' }}" role="alert">
    <strong>{{ alert_title|default:'Notice' }}:</strong> {{ alert_message }}
</div>
```

In any view template:
```html
{% extends 'base.html' %}

{% block content %}
    <h1>Account Overview</h1>

    {% include 'components/_alert.html' with alert_type="warning" alert_title="Action Required" alert_message="Please verify your email address to unlock full features." %}

    {% include 'components/_alert.html' with alert_type="success" alert_title="Payment Received" alert_message="Your subscription has been renewed." %}
{% endblock %}
```

---

## 6. Code Explanation

- `with alert_type="warning" ...`: Supplies local variables to the included template snippet.
- `only`: Prevents the included template from accessing the parent template's context dictionary, enforcing component encapsulation.

---

## 7. Expected Output

Rendered HTML:
```html
<h1>Account Overview</h1>
<div class="alert alert-warning" role="alert">
    <strong>Action Required:</strong> Please verify your email address to unlock full features.
</div>
<div class="alert alert-success" role="alert">
    <strong>Payment Received:</strong> Your subscription has been renewed.
</div>
```

---

## 8. Real-World Use Case

Modern design systems (Bootstrap, Tailwind UI) modularize their interfaces into partials: `_header.html`, `_sidebar.html`, `_footer.html`, `_pagination.html`, and `_modal.html`.

---

## 9. Common Mistakes

1. **Confusing `{% extends %}` with `{% include %}`:**
   - `{% extends %}` is for top-level structural skeletons (parent-child inheritance).
   - `{% include %}` is for embedding reusable widgets/components into an existing file.
2. Creating circular includes where File A includes File B, which includes File A (causes infinite recursion).

---

## 10. Best Practices

- Prefix partial template filenames with an underscore (e.g. `_navbar.html`) to visually distinguish components from full page templates.
- Store reusable partials in a dedicated `templates/partials/` or `templates/components/` directory.

## 12. Interview Questions

**Q1: What is the architectural difference between `extends` and `include` in Django?**  
*Answer:* `extends` represents "is-a" template inheritance where a child template fills in blocks of an overarching layout skeleton. `include` represents "has-a" composition where an existing template embeds an independent, modular sub-template or widget into itself.

**Q2: What does the `only` option do in an `include` tag?**  
*Answer:* By default, an included template has access to all variables in the parent template's context. Adding `only` isolates the included template so it can only access variables explicitly passed via the `with` clause.

---

## 13. Summary

- `{% include %}` embeds reusable partial templates into pages.
- Can pass scoped variables using `with`.
- `only` restricts context access for modularity.
