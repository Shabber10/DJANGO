# 3. Generic Display Views - ListView and DetailView

## 1. Introduction

The two most common read-only operations in web applications are displaying a list of items and displaying a single item's detailed profile. Django provides **`ListView`** and **`DetailView`** in `django.views.generic` to handle these tasks automatically.

---

## 2. Why Do We Need It?

Writing manual list views requires: querying the database, setting up pagination, building context dictionaries, and rendering templates. `ListView` and `DetailView` accomplish all of this with just 3 lines of declarative configuration.

---

## 3. How It Works

- **`ListView`:**
  - Queries `model.objects.all()` (or custom `get_queryset()`).
  - Sets context variable `object_list` (and custom `context_object_name`).
  - Automatically handles pagination if `paginate_by` is set.
  - Defaults to template: `<app_label>/<model_name>_list.html`.
- **`DetailView`:**
  - Fetches the object using `pk` or `slug` from URL parameters.
  - Automatically raises `Http404` if not found.
  - Sets context variable `object` (and custom `context_object_name`).
  - Defaults to template: `<app_label>/<model_name>_detail.html`.

---

## 4. Syntax

```python
# File: store/views.py
from django.views.generic import ListView, DetailView
from .models import Product

class ProductListView(ListView):
    model = Product
    template_name = 'store/product_list.html'
    context_object_name = 'products' # Use {{ products }} instead of {{ object_list }}
    paginate_by = 12                 # 12 items per page!

class ProductDetailView(DetailView):
    model = Product
    template_name = 'store/product_detail.html'
    context_object_name = 'product'  # Use {{ product }} instead of {{ object }}
```

---

## 5. Practical Examples

### Filtering Querysets in ListView Dynamically
```python
# File: store/views.py
from django.views.generic import ListView
from .models import Product

class ActiveProductListView(ListView):
    model = Product
    template_name = 'store/product_list.html'
    context_object_name = 'products'
    paginate_by = 10

    def get_queryset(self):
        # Only display active products in stock
        return Product.objects.filter(is_available=True, stock_count__gt=0).order_by('-created_at')

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context['page_title'] = "Available Inventory"
        return context
```

---

## 6. Code Explanation

- `context_object_name = 'products'`: Renames the default context variable `object_list` to something domain-specific for readability in templates.
- `paginate_by = 10`: Automatically creates `paginator` and `page_obj` in the template context!
- `get_queryset()`: Overriding this method allows dynamic filtering based on user permissions or GET parameters.

---

## 7. Expected Output

In `product_list.html`:
```html
{% for product in products %}
    <h3>{{ product.name }} - ${{ product.price }}</h3>
{% endfor %}

{% if is_paginated %}
    <p>Page {{ page_obj.number }} of {{ paginator.num_pages }}</p>
{% endif %}
```

---

## 8. Real-World Use Case

E-commerce product listings, blog archives, member directories, and transaction history feeds.

---

## 9. Common Mistakes

1. Looking up by non-standard URL parameter without configuring `pk_url_kwarg`: By default, `DetailView` looks for `<int:pk>` or `<slug:slug>` in the URL. If your URL is `path('<int:item_id>/', ...)`, you must set `pk_url_kwarg = 'item_id'`.

---

## 10. Best Practices

- Always set `context_object_name` for clean template readability.
- Use `get_queryset()` to restrict data by user or state.
- Leverage `paginate_by` for built-in pagination.

## 12. Interview Questions

**Q1: How does `ListView` handle pagination automatically?**  
*Answer:* By setting `paginate_by = N`, `ListView` wraps the QuerySet in Django's `Paginator` and injects `page_obj`, `paginator`, and a boolean `is_paginated` into the template context. In the template, developers can iterate over `page_obj` and render pagination links without writing manual pagination math.

**Q2: What is the default context object name in `DetailView` and how do you customize it?**  
*Answer:* The default context name is `object` (and the lowercase model name, e.g. `article`). You can customize it by setting `context_object_name = 'my_custom_name'`.

---

## 13. Summary

- `ListView` displays collections; `DetailView` displays single records.
- Set `context_object_name` and `template_name` for clean organization.
- `get_queryset()` allows dynamic filtering and customization.
