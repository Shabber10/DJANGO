# 2. Base CBVs - View, TemplateView, and RedirectView

## 1. Introduction

Django provides three fundamental base views in `django.views.generic.base`: **`View`**, **`TemplateView`**, and **`RedirectView`**. These classes serve as the building blocks for all higher-level class-based views.

---

## 2. Why Do We Need It?

Many pages on a website are largely static (About Us, Terms of Service, FAQ) or simply redirect users to new destinations. Writing full view functions for these simple tasks creates unnecessary boilerplate. Base CBVs allow configuring these pages declaratively in one or two lines.

---

## 3. How It Works

- **`View`:** The foundational base class. Handles HTTP method dispatching (`get`, `post`).
- **`TemplateView`:** Renders a specified template directly, with an overridable `get_context_data()` method to inject dynamic context.
- **`RedirectView`:** Automatically redirects requests to a specified URL or route name.

---

## 4. Syntax

```python
# File: pages/views.py
from django.views.generic import TemplateView, RedirectView
from django.views import View
from django.http import HttpResponse

# 1. Base View
class EchoView(View):
    def get(self, request):
        return HttpResponse(f"Echo: {request.GET.get('message', 'Hello')}")

# 2. TemplateView with extra context
class AboutPageView(TemplateView):
    template_name = 'pages/about.html'

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context['company_mission'] = "Building world-class software."
        return context

# 3. Direct TemplateView in urls.py (Zero Python view code!):
from django.urls import path

urlpatterns = [
    path('terms/', TemplateView.as_view(template_name='pages/terms.html'), name='terms'),
    path('old-home/', RedirectView.as_view(url='/', permanent=True), name='old_home'),
    path('about/', AboutPageView.as_view(), name='about'),
]
```

---

## 5. Practical Examples

### Using RedirectView with Dynamic URL Arguments
```python
# File: core/views.py
from django.views.generic import RedirectView

class UserRedirectView(RedirectView):
    permanent = False
    query_string = True # Preserves query parameters like ?ref=twitter
    pattern_name = 'user_profile' # Redirects to route name!

    def get_redirect_url(self, *args, **kwargs):
        # Can dynamically compute target URL
        return super().get_redirect_url(*args, **kwargs)
```

---

## 6. Code Explanation

- `TemplateView.as_view(template_name='...')`: Allows serving static template pages directly inside `urls.py` without authoring a separate view function!
- `super().get_context_data(**kwargs)`: Preserves any default context variables before injecting custom keys.
- `RedirectView(permanent=True)`: Issues an HTTP 301 Permanent Redirect (SEO friendly).

---

## 7. Expected Output

Visiting `/terms/` immediately renders `pages/terms.html`.
Visiting `/old-home/` returns HTTP 301 and redirects the browser to `/`.

---

## 8. Real-World Use Case

Marketing landing pages, documentation index files, privacy policy pages, and managing URL migration redirects.

---

## 9. Common Mistakes

1. **Forgetting to call `super().get_context_data()`:** Overwriting context without calling `super()` drops default context variables provided by Django.

---

## 10. Best Practices

- Use `TemplateView.as_view(template_name='...')` for purely informational pages.
- Always call `super().get_context_data(**kwargs)` when adding extra context.
- Use `permanent=True` on `RedirectView` for permanent URL restructuring (SEO).

## 12. Interview Questions

**Q1: How do you add dynamic data to a `TemplateView`?**  
*Answer:* By overriding the `get_context_data(self, **kwargs)` method:
```python
def get_context_data(self, **kwargs):
    context = super().get_context_data(**kwargs)
    context['extra_data'] = MyModel.objects.count()
    return context
```

**Q2: What is the purpose of `pattern_name` in `RedirectView`?**  
*Answer:* `pattern_name` allows configuring `RedirectView` to redirect to a named URL pattern (using reverse URL resolution) rather than a hardcoded URL string, automatically passing captured positional and keyword arguments through to the destination route.

---

## 13. Summary

- `View` is the low-level base for all CBVs.
- `TemplateView` renders templates declaratively.
- `RedirectView` issues HTTP 301 or 302 redirects.
