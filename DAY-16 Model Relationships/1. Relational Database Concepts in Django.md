# 1. Relational Database Concepts in Django

## 1. Introduction

Relational databases derive their power from the ability to link records across tables using **Foreign Keys** and **Constraints**. Django maps these mathematical entity relationships into elegant Python object attributes, allowing you to traverse complex relational graphs cleanly without writing raw SQL joins.

---

## 2. Why Do We Need It?

Real-world entities rarely exist in isolation:
- An **Author** writes multiple **Articles** (One-to-Many).
- A **User** has one **Profile** (One-to-One).
- A **Student** enrolls in multiple **Courses**, and each Course contains multiple Students (Many-to-Many).
Relational modeling normalizes data, avoids data duplication, and guarantees referential integrity.

---

## 3. How It Works

Django supports three primary relationship types:
1. **Many-to-One (`ForeignKey`):** Many child rows point to a single parent row.
2. **One-to-One (`OneToOneField`):** Exactly one child row points to one parent row.
3. **Many-to-Many (`ManyToManyField`):** Records in Table A link to multiple records in Table B via an intermediary join table.

---

## 4. Syntax

```python
from django.db import models
from django.contrib.auth.models import User

# 1. One-to-One
class UserProfile(models.Model):
    user = models.OneToOneField(User, on_delete=models.CASCADE)

# 2. One-to-Many
class Article(models.Model):
    author = models.ForeignKey(User, on_delete=models.CASCADE, related_name='articles')

# 3. Many-to-Many
class Tag(models.Model):
    name = models.CharField(max_length=50)

class Publication(models.Model):
    tags = models.ManyToManyField(Tag, related_name='publications')
```

---

## 5. Practical Examples

### Visualizing Foreign Key Relationships in Code
```python
# Accessing parent from child (Forward relation):
article = Article.objects.get(id=1)
print(article.author.username) # Traverses ForeignKey!

# Accessing children from parent (Reverse relation):
author = User.objects.get(username="shabber")
# Uses related_name='articles'
author_articles = author.articles.all()
for a in author_articles:
    print(a.title)
```

---

## 6. Code Explanation

- `on_delete`: Mandatory argument on `ForeignKey` and `OneToOneField` defining database behavior when the referenced parent object is deleted.
- `related_name`: Defines the attribute name attached to the parent object for reverse relationship traversal. If omitted, Django defaults to `<modelname>_set` (e.g. `user.article_set.all()`).

---

## 7. Expected Output

Querying relationships in shell:
```text
>>> article.author
<User: shabber>
>>> author.articles.count()
14
```

---

## 8. Real-World Use Case

Order management systems linking customers to orders (`ForeignKey`), user settings linked to authentication accounts (`OneToOneField`), and tagging systems for products (`ManyToManyField`).

---

## 9. Common Mistakes

1. **Omitting `on_delete` on `ForeignKey`:** Triggers a `TypeError: __init__() missing 1 required positional argument: 'on_delete'`.
2. Forgetting that reverse lookups default to `_set` unless `related_name` is explicitly set.

---

## 10. Best Practices

- Always specify an explicit, plural `related_name` on ForeignKeys (e.g., `related_name='orders'`).
- Choose `on_delete` policies intentionally based on business rules.

## 12. Interview Questions

**Q1: What is referential integrity in relational databases and how does Django enforce it?**  
*Answer:* Referential integrity ensures that foreign key references always point to valid, existing parent records. Django enforces this through database-level foreign key constraints and requires explicit `on_delete` rules (such as `CASCADE`, `PROTECT`, or `SET_NULL`) defining what happens to child records when a parent record is deleted.

**Q2: What is the purpose of `related_name` in a `ForeignKey` definition?**  
*Answer:* `related_name` customizes the reverse relation manager attribute attached to the parent model. Instead of the default `parent.childmodel_set`, an explicit `related_name='books'` allows writing `author.books.all()`, creating readable and expressive domain code.

---

## 13. Summary

- Django models support One-to-Many, One-to-One, and Many-to-Many relationships.
- Forward relations traverse direct attributes; Reverse relations use `related_name`.
- `on_delete` governs cascading deletion rules.
