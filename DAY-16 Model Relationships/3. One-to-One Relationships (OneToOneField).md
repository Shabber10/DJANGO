# 3. One-to-One Relationships (OneToOneField)

## 1. Introduction

A **One-to-One Relationship** (represented by **`models.OneToOneField`**) ensures that each record in Table A is linked to exactly one record in Table B, and vice-versa. It is functionally identical to a `ForeignKey` with `unique=True`, but provides a direct reverse attribute rather than a QuerySet manager.

---

## 2. Why Do We Need It?

The primary use case in Django is extending existing models—most notably extending Django's built-in **`User`** model with custom profile fields (phone numbers, avatars, addresses) without modifying Django's core authentication tables.

---

## 3. How It Works

- In the database, Django creates a column with a `UNIQUE` foreign key constraint.
- Forward access: `profile.user` returns the `User` instance.
- Reverse access: `user.profile` returns the single `UserProfile` instance directly (not a QuerySet!).

---

## 4. Syntax

```python
# File: accounts/models.py
from django.db import models
from django.contrib.auth.models import User

class UserProfile(models.Model):
    user = models.OneToOneField(
        User,
        on_delete=models.CASCADE,
        related_name='profile'  # Access via user.profile!
    )
    phone_number = models.CharField(max_length=20, blank=True)
    department = models.CharField(max_length=100, blank=True)
    avatar = models.ImageField(upload_to='avatars/', blank=True)

    def __str__(self):
        return f"Profile for {self.user.username}"
```

---

## 5. Practical Examples

### Automatic Profile Creation Using Django Signals
```python
# File: accounts/signals.py
from django.db.models.signals import post_save
from django.dispatch import receiver
from django.contrib.auth.models import User
from .models import UserProfile

@receiver(post_save, sender=User)
def create_user_profile(sender, instance, created, **kwargs):
    if created:
        UserProfile.objects.create(user=instance)

@receiver(post_save, sender=User)
def save_user_profile(sender, instance, **kwargs):
    instance.profile.save()
```

---

## 6. Code Explanation

- `related_name='profile'`: Allows you to write `request.user.profile.phone_number` directly in views and templates!
- If a user has no profile, accessing `user.profile` raises `UserProfile.DoesNotExist`.
- Signals ensure that whenever a new `User` is created, its corresponding `UserProfile` is automatically instantiated.

---

## 7. Expected Output

In template rendering:
```html
<h1>Welcome, {{ request.user.first_name }}!</h1>
<p>Department: {{ request.user.profile.department }}</p>
<p>Phone: {{ request.user.profile.phone_number }}</p>
```

---

## 8. Real-World Use Case

User profiles, hardware device network configurations, employee background verification records, and merchant billing credentials.

---

## 9. Common Mistakes

1. **Accessing reverse relation before record is created:** Accessing `user.profile` when no row exists raises `RelatedObjectDoesNotExist`. Always create the profile on user creation (via signals or custom registration).

---

## 10. Best Practices

- Always provide `related_name` (e.g. `related_name='profile'`).
- Use Django signals (`post_save`) to automatically create the one-to-one record when the parent is created.

## 12. Interview Questions

**Q1: What is the architectural difference between `ForeignKey(unique=True)` and `OneToOneField`?**  
*Answer:* Structurally and in SQL schema, both create a foreign key column with a unique constraint. However, in the Python ORM:
- With `ForeignKey(unique=True)`, reverse access returns a QuerySet manager (e.g. `parent.child_set.first()`).
- With `OneToOneField`, reverse access directly returns the single child instance (e.g. `parent.child`), raising `DoesNotExist` if absent.

**Q2: What is the User Profile pattern in Django?**  
*Answer:* The User Profile pattern involves creating a separate model (e.g. `UserProfile`) linked to Django's built-in `User` model via a `OneToOneField`. It allows storing application-specific user data (such as avatars, biographies, phone numbers, preferences) without having to override or replace the core authentication user model.

---

## 13. Summary

- `OneToOneField` enforces a 1:1 relationship between models.
- Ideal for the User Profile extension pattern.
- Reverse lookup returns a single instance directly (`user.profile`).
