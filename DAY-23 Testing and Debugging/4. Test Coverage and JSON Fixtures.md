# 4. Test Coverage and JSON Fixtures

## 1. Introduction

Writing tests is only half the battle; knowing which parts of your codebase remain untested is equally critical. **Test Coverage** measures the percentage of code lines executed by your test suite. Additionally, seeding databases with initial or mock data is facilitated by Django's **Fixtures** (`dumpdata` and `loaddata`).

---

## 2. Why Do We Need It?

- **Coverage:** Uncovers hidden branches, untested error handlers, and dead code.
- **Fixtures:** Allows serializing database records into JSON/YAML files to quickly populate staging servers or unit tests with pre-configured mock data (e.g. standard country lists, initial categories, or permission groups).

---

## 3. How It Works

- **Coverage (`coverage.py`):** Instruments the Python interpreter, records executed bytecode lines during `manage.py test`, and generates detailed HTML coverage reports.
- **`dumpdata`:** Exports database records to a JSON file.
- **`loaddata`:** Imports records from a JSON file into the database.

---

## 4. Syntax

### Measuring Test Coverage:
```bash
# 1. Install coverage
pip install coverage

# 2. Run test suite under coverage
coverage run --source='.' manage.py test

# 3. View terminal summary report
coverage report

# 4. Generate visual HTML report
coverage html
```

### Managing Data Fixtures:
```bash
# Export entire database to JSON
python manage.py dumpdata > db_backup.json

# Export a specific app (formatted with indentation)
python manage.py dumpdata store --indent 4 > store/fixtures/products.json

# Load fixture into database
python manage.py loaddata store/fixtures/products.json
```

---

## 5. Practical Examples

### Using Fixtures in TestCase
```python
# File: store/tests.py
from django.test import TestCase
from .models import Product

class ProductFixtureTest(TestCase):
    # Automatically loads JSON data into test database before tests run!
    fixtures = ['products.json']

    def test_fixture_products_loaded(self):
        # Data from products.json is already present!
        self.assertTrue(Product.objects.filter(name="Laptop").exists())
```

---

## 6. Code Explanation

- `coverage.py`: Outputs percentage of lines executed. High-performing engineering teams typically target >85% coverage.
- `fixtures = ['products.json']`: Automatically runs `loaddata` inside the isolated test database before running tests.
- `--indent 4`: Produces clean, readable, version-controllable JSON.

## 8. Real-World Use Case

Populating standard ISO country codes, currency tables, and administrative role fixtures during initial application deployment.

---

## 9. Common Mistakes

1. Relying on massive fixtures for all unit tests. Fixtures can become brittle when model schemas change; for dynamic test data, tools like `factory_boy` are often preferred.
2. Dumping data with sensitive user passwords to public repositories.

---

## 10. Best Practices

- Aim for 80-90% test coverage across models, views, and forms.
- Exclude virtual environments and migration files from coverage reports using a `.coveragerc` config file.
- Use fixtures for static lookup tables (categories, states, countries).

## 12. Interview Questions

**Q1: What are the trade-offs of using fixtures in Django tests?**  
*Answer:* Fixtures are easy to generate using `dumpdata` and provide consistent mock data. However, as models evolve over time, static JSON fixtures become brittle, requiring manual updates to match new schema constraints. Loading large fixtures also adds disk I/O overhead to test runs. Modern teams often prefer programmatic factory libraries (like `factory_boy`) for dynamic test fixtures.

**Q2: What is a `.coveragerc` file?**  
*Answer:* `.coveragerc` is the configuration file for `coverage.py`. It allows specifying which directories to omit (e.g. `venv/*`, `*/migrations/*`, `manage.py`, `config/asgi.py`) so that third-party code and migration files do not skew application test coverage percentages.

---

## 13. Summary

- `coverage.py` measures test thoroughness.
- `dumpdata` and `loaddata` serialize and deserialize records.
- Fixtures provide reproducible data states for tests and seeding.
