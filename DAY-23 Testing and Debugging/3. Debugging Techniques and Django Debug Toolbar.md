# 3. Debugging Techniques and Django Debug Toolbar

## 1. Introduction

Debugging is an essential developer skill. When errors arise or pages load slowly, developers need effective tools to inspect database queries, HTTP headers, template contexts, and execution flow. Django provides native debugging tools, Python breakpoints, and the industry-standard **Django Debug Toolbar**.

---

## 2. Why Do We Need It?

- Print debugging (`print(var)`) is slow, clutters terminals, and offers zero visibility into SQL execution.
- Silent performance killers (such as N+1 queries executing 50 duplicate SQL queries) are invisible without query profiling.
- The Django Debug Toolbar renders an interactive side panel directly in the browser showing queries, timings, headers, and context variables.

---

## 3. How It Works

1. Install `django-debug-toolbar`.
2. Add `'debug_toolbar'` to `INSTALLED_APPS`.
3. Add `'debug_toolbar.middleware.DebugToolbarMiddleware'` to `MIDDLEWARE`.
4. Configure `INTERNAL_IPS = ['127.0.0.1']`.
5. Connect `path('__debug__/', include('debug_toolbar.urls'))` in `urls.py`.
The toolbar injects an interactive collapsible panel on all HTML pages when accessed from localhost.

---

## 4. Syntax

### Installing and Configuring Debug Toolbar:
```bash
pip install django-debug-toolbar
```

```python
# File: config/settings.py
INSTALLED_APPS = [
    ...,
    'debug_toolbar',
]

MIDDLEWARE = [
    # Place DebugToolbar near the top, after GZip but before most middleware
    'debug_toolbar.middleware.DebugToolbarMiddleware',
    'django.middleware.security.SecurityMiddleware',
    ...
]

INTERNAL_IPS = [
    '127.0.0.1',
]
```

```python
# File: config/urls.py
from django.conf import settings
from django.urls import path, include

urlpatterns = [
    # Other routes...
]

if settings.DEBUG:
    import debug_toolbar
    urlpatterns = [
        path('__debug__/', include(debug_toolbar.urls)),
    ] + urlpatterns
```

## 5. Practical Examples

### Native Python Debugging with breakpoint()
```python
# File: store/views.py
def calculate_discount(request, product_id):
    product = Product.objects.get(id=product_id)
    discount_rate = request.GET.get('rate', 0.1)

    # Drops directly into the Python interactive debugger (PDB)!
    breakpoint()

    final_price = product.price * (1 - float(discount_rate))
    return HttpResponse(f"Discounted: {final_price}")
```

---

## 6. Code Explanation

- `breakpoint()`: Built-in Python 3.7+ function. Halts execution and opens an interactive PDB session in your terminal where you can inspect local variables, step through lines (`n`), and execute code.
- `INTERNAL_IPS`: Security guard! The Debug Toolbar will ONLY render for clients connecting from IP addresses listed in `INTERNAL_IPS`.
- Panels in Debug Toolbar:
  - **SQL Panel:** Shows exact SQL statements, execution times, and highlights duplicate queries in red!
  - **Time Panel:** CPU and wall-clock breakdown.
  - **Templates Panel:** Shows every template loaded and context variables passed.

---

## 7. Expected Output

When browsing `http://127.0.0.1:8000/`:
A sidebar appears on the right edge of the browser:
- `SQL: 2 queries in 1.42ms`
- `Templates: 3 templates rendered`
- `Time: 12ms total`

---

## 8. Real-World Use Case

Detecting and eliminating N+1 queries during local development before pushing code to production; auditing HTTP headers; inspecting template context.

---

## 9. Common Mistakes

1. **Forgetting `INTERNAL_IPS`:** If `INTERNAL_IPS = ['127.0.0.1']` is omitted, the Debug Toolbar will not display in the browser.
2. Leaving `debug_toolbar` active in production with `DEBUG = False`.

---

## 10. Best Practices

- Only enable `debug_toolbar` when `DEBUG = True`.
- Use the SQL panel to ensure no duplicate queries appear on list pages.
- Use `breakpoint()` for surgical inspection of complex logic.

## 12. Interview Questions

**Q1: How do you identify and diagnose the N+1 query problem using Django Debug Toolbar?**  
*Answer:* In the Debug Toolbar's **SQL Panel**, Django logs all executed queries and automatically detects duplicate queries, highlighting them in bright red with a warning icon (e.g., "45 similar queries"). Clicking into the panel reveals the exact SQL strings, line numbers in Python code that triggered each query, and execution durations, pinpointing where `select_related` or `prefetch_related` is needed.

**Q2: What is the purpose of `INTERNAL_IPS` in Django?**  
*Answer:* `INTERNAL_IPS` is a list of IP addresses (typically `['127.0.0.1']`) from which debugging tools—such as the Django Debug Toolbar or the `debug` context processor—are permitted to run. It ensures that even if `DEBUG = True` is accidentally exposed, users from external IPs cannot view sensitive database queries or server internals.

---

## 13. Summary

- `breakpoint()` provides instant interactive terminal debugging.
- Django Debug Toolbar profiles SQL, execution time, and templates.
- Enforce `INTERNAL_IPS` to restrict debugging visibility.
