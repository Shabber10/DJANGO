# 2. Testing Models, Views, and Forms

## 1. Introduction

A comprehensive test suite verifies all three layers of the MVT architecture: unit testing **Models** for business calculations and string formatting, testing **Forms** for validation constraints, and testing **Views** using Django's built-in **HTTP Test Client**.

---

## 2. Why Do We Need It?

- **Model Tests:** Ensure that calculations, methods, and default values behave predictably.
- **Form Tests:** Ensure invalid inputs are rejected and custom validators fire correctly.
- **View Tests:** Ensure URLs resolve, HTTP status codes are correct (200, 302, 404), templates render, and unauthorized users are blocked.

---

## 3. How It Works

Django's `self.client` is an integrated dummy browser that simulates HTTP requests (`get`, `post`) without running an actual network web server:
- `response = self.client.get('/url/')`
- Special assertions:
  - `self.assertContains(response, "text", status_code=200)`
  - `self.assertRedirects(response, '/target/')`
  - `self.assertTemplateUsed(response, 'template.html')`

---

## 4. Syntax

```python
# File: store/tests.py
from django.test import TestCase
from django.urls import reverse
from .models import Product
from .forms import ProductForm

class StoreTests(TestCase):
    def setUp(self):
        self.product = Product.objects.create(name="Keyboard", price=49.99)

    # 1. Testing Models
    def test_product_str(self):
        self.assertEqual(str(self.product), "Keyboard")

    # 2. Testing Forms
    def test_product_form_validation(self):
        # Missing required price
        form = ProductForm(data={'name': 'Monitor'})
        self.assertFalse(form.is_valid())
        self.assertIn('price', form.errors)

    # 3. Testing Views with Test Client
    def test_product_list_view(self):
        response = self.client.get(reverse('store:product_list'))
        self.assertEqual(response.status_code, 200)
        self.assertTemplateUsed(response, 'store/product_list.html')
        self.assertContains(response, "Keyboard")
```

## 5. Practical Examples

### Testing Authenticated Views with `self.client.force_login()`
```python
from django.test import TestCase
from django.urls import reverse
from django.contrib.auth import get_user_model

User = get_user_model()

class ProtectedViewTests(TestCase):
    def setUp(self):
        self.user = User.objects.create_user(username="testuser", password="password123")

    def test_dashboard_redirects_anonymous_user(self):
        # Guest should be redirected to login
        response = self.client.get(reverse('dashboard'))
        self.assertRedirects(response, f"/accounts/login/?next={reverse('dashboard')}")

    def test_dashboard_accessible_to_authenticated_user(self):
        # Simulate logged-in session instantly!
        self.client.force_login(self.user)
        response = self.client.get(reverse('dashboard'))
        self.assertEqual(response.status_code, 200)
        self.assertContains(response, "Welcome, testuser!")
```

---

## 6. Code Explanation

- `self.client.force_login(user)`: Bypasses the login form and directly logs the user into the test client's session, saving time and keeping tests focused.
- `assertContains(response, text)`: Asserts status 200 AND checks that `text` appears inside the rendered HTML response.
- `assertRedirects(response, expected_url)`: Verifies HTTP 302 and asserts the final redirected URL.

## 9. Common Mistakes

1. **Testing hardcoded URL strings:** e.g. `self.client.get('/store/products/')`. Always use `reverse('store:product_list')` so tests don't break if URL routes are modified.

---

## 10. Best Practices

- Use `reverse()` to generate URLs in view tests.
- Use `force_login()` rather than submitting login forms in view tests.
- Test both "happy paths" (valid inputs) and "sad paths" (invalid inputs, unauthorized access).

## 12. Interview Questions

**Q1: What is the difference between `self.client.login()` and `self.client.force_login()`?**  
*Answer:* `self.client.login(username=..., password=...)` simulates a user typing credentials, executing Django's full authentication backends and password hashing algorithms (which are CPU-intensive). `self.client.force_login(user)` skips authentication backends and directly constructs the authenticated session for the given User object, executing in microseconds and significantly accelerating test suites.

**Q2: What does `assertTemplateUsed()` do?**  
*Answer:* `assertTemplateUsed(response, 'template_name.html')` asserts that the specified template was rendered as part of the response (including inherited parent templates and included partials).
