# 2. FileField and ImageField in Models

## 1. Introduction

Storing uploaded files directly inside SQL database columns (as binary BLOBs) degrades database performance, bloats backups, and prevents CDN caching. Instead, Django models use **`FileField`** and **`ImageField`** to store the binary file on the filesystem (or cloud storage) while storing only the relative path string in the database column.

---

## 2. Why Do We Need It?

- **Scalability:** Databases remain lightweight and performant because they store simple text paths (e.g. `resumes/2026/john.pdf`).
- **Image Validation:** `ImageField` uses the **Pillow** library to verify that an uploaded file is genuinely a valid image (JPEG, PNG, WEBP), preventing malicious scripts disguised as images.
- **Convenient API:** Exposes `.url`, `.size`, `.path`, and automated file deletion hooks.

---

## 3. How It Works

- `upload_to`: Specifies the target directory inside `MEDIA_ROOT`.
- Can accept a date format string (e.g. `'uploads/%Y/%m/%d/'`).
- Can accept a callable function `(instance, filename) -> path` to dynamically name files.

---

## 4. Syntax

```python
# File: employees/models.py
from django.db import models
import os
import uuid

def employee_resume_path(instance, filename):
    # Generates: resumes/<employee_id>/<uuid>_<filename>
    ext = filename.split('.')[-1]
    unique_filename = f"{uuid.uuid4().hex[:10]}.{ext}"
    return os.path.join(f"resumes/{instance.pk}/", unique_filename)

class Employee(models.Model):
    name = models.CharField(max_length=100)
    # FileField: Any file type (PDF, DOCX, ZIP)
    resume = models.FileField(upload_to=employee_resume_path, blank=True)
    # ImageField: Requires 'pip install Pillow'
    profile_photo = models.ImageField(upload_to='photos/%Y/%m/', default='photos/default.png')

    def __str__(self):
        return self.name
```

## 5. Practical Examples

### ModelForm Integration with ImageField
```python
# File: employees/forms.py
from django import forms
from .models import Employee

class EmployeeForm(forms.ModelForm):
    class Meta:
        model = Employee
        fields = ['name', 'resume', 'profile_photo']
```

In `views.py`:
```python
def create_employee(request):
    if request.method == "POST":
        form = EmployeeForm(request.POST, request.FILES) # Note request.FILES!
        if form.is_valid():
            employee = form.save()
            return redirect('employee_detail', pk=employee.pk)
    else:
        form = EmployeeForm()
    return render(request, 'employee_form.html', {'form': form})
```

---

## 6. Code Explanation

- `Pillow`: The Python Imaging Library fork required by `ImageField` (`pip install Pillow`).
- `employee.profile_photo.url`: Returns the browser URL (e.g. `/media/photos/2026/10/avatar.jpg`).
- `employee.profile_photo.path`: Returns the absolute local filesystem path (e.g. `C:/Users/.../media/photos/2026/10/avatar.jpg`).

---

## 7. Expected Output

In template rendering:
```html
<img src="{{ employee.profile_photo.url }}" alt="{{ employee.name }}" width="200">
<p><a href="{{ employee.resume.url }}" download>Download Resume (PDF)</a></p>
```

## 8. Real-World Use Case

Employee portals, digital receipt storage for expense trackers, real estate property listings with high-resolution photos.

---

## 9. Common Mistakes

1. **Calling `.url` on an empty optional file field:** If a field has `blank=True` and the user didn't upload a file, calling `{{ employee.resume.url }}` raises `ValueError: The 'resume' attribute has no file associated with it.` Always check `{% if employee.resume %}` first!

---

## 10. Best Practices

- Always check `{% if object.field %}` before calling `object.field.url` in templates.
- Organize uploads using dynamic `upload_to` date formatting or functions to prevent thousands of files accumulating in a single directory.
- Never store raw binary files inside database BLOBs.

## 12. Interview Questions

**Q1: What does Django store in the database column for a `FileField` or `ImageField`?**  
*Answer:* Django stores only a relative string path (e.g. `'avatars/2026/10/photo.jpg'`) inside an SQL `VARCHAR(100)` column. It never stores the raw binary bytes of the file in the database. When the property is accessed, Django's `FieldFile` descriptor combines this string path with `MEDIA_ROOT` (for disk access) or `MEDIA_URL` (for web browser access).

**Q2: What validation does `ImageField` perform that `FileField` does not?**  
*Answer:* `ImageField` inherits from `FileField` but adds validation using Pillow to verify that the uploaded file's binary header is a valid, readable image format. It also populates optional `height_field` and `width_field` attributes on the model with the image dimensions in pixels.

---

## 13. Summary

- `FileField` and `ImageField` store file paths, not binary data, in the database.
- `ImageField` requires Pillow and verifies image headers.
- Always check for file existence before accessing `.url`.
