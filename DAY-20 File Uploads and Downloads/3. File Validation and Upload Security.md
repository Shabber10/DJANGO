# 3. File Validation and Upload Security

## 1. Introduction

Allowing arbitrary users to upload files to your server is one of the highest-risk attack vectors in web security. Attackers can upload executable malware (PHP or Python scripts disguised as images), zip bombs, or massive files designed to cause **Denial of Service (DoS)**. Implementing strict file validation and security safeguards is mandatory.

---

## 2. Why Do We Need It?

Without file validation:
- A user could upload a 50 GB file, consuming all server disk space.
- A user could upload a malicious executable named `exploit.php` or `backdoor.py` and execute it on the server.
- File extensions (like `.jpg`) can be easily spoofed; you must validate the true underlying MIME type.

---

## 3. How It Works

A robust file validation pipeline enforces three checks:
1. **File Extension Check:** Using `django.core.validators.FileExtensionValidator`.
2. **File Size Check:** Verifying `file.size <= MAX_ALLOWED_BYTES`.
3. **MIME Type Inspection:** Using libraries like `python-magic` to inspect file magic bytes (signatures), ensuring a file ending in `.png` isn't actually an executable script.

---

## 4. Syntax

```python
# File: core/validators.py
from django.core.exceptions import ValidationError
from django.core.validators import FileExtensionValidator

# 1. Extension Validator
validate_document_extension = FileExtensionValidator(
    allowed_extensions=['pdf', 'docx', 'txt'],
    message="Unsupported file format. Please upload a PDF, DOCX, or TXT file."
)

# 2. File Size Validator (Max 5 MB)
def validate_file_size(file):
    max_size_mb = 5
    if file.size > max_size_mb * 1024 * 1024:
        raise ValidationError(f"File size exceeds the maximum allowed limit of {max_size_mb} MB.")
```

---

## 5. Practical Examples

### Attaching Validators Directly to Model Fields
```python
# File: submissions/models.py
from django.db import models
from core.validators import validate_document_extension, validate_file_size

class ProjectSubmission(models.Model):
    title = models.CharField(max_length=200)
    document = models.FileField(
        upload_to='submissions/%Y/',
        validators=[validate_document_extension, validate_file_size],
        help_text="Upload PDF or DOCX up to 5 MB"
    )
```

---

## 6. Code Explanation

- `FileExtensionValidator`: Compares the file extension against a whitelist of permitted extensions.
- `validate_file_size`: Checks the byte length before the file is written to permanent storage.
- If any validator raises `ValidationError`, Django halts the form submission and displays the error message directly on the form field.

---

## 7. Expected Output

Uploading a 15 MB file triggers validation failure:
```html
<ul class="errorlist">
    <li>File size exceeds the maximum allowed limit of 5 MB.</li>
</ul>
```

Uploading an `.exe` file triggers:
```html
<ul class="errorlist">
    <li>Unsupported file format. Please upload a PDF, DOCX, or TXT file.</li>
</ul>
```

---

## 8. Real-World Use Case

Enterprise customer support portals, KYC (Know Your Customer) identity verification uploaders (validating passport PDFs), and applicant tracking systems.

---

## 9. Common Mistakes

1. **Relying solely on `file.content_type` for security:** The `content_type` attribute on `UploadedFile` is supplied directly by the client's browser and can be trivial to spoof!
2. Allowing user uploads to be stored inside directories served as executable code.

---

## 10. Best Practices

- Whitelist permitted file extensions explicitly.
- Enforce strict file size limits (e.g. 5 MB or 10 MB).
- Store user uploads on external object storage (AWS S3) or serve them with `Content-Disposition: attachment` to prevent script execution in the browser.

## 12. Interview Questions

**Q1: What is a Directory Traversal attack in file uploads and how does Django prevent it?**  
*Answer:* A directory traversal attack occurs when an attacker uploads a file with a malicious filename like `../../etc/passwd` or `../../settings.py` to overwrite critical system files. Django protects against this using `os.path.basename()` and internal storage sanitization (`get_valid_name()`), stripping leading directory separators and relative dots before saving.

**Q2: Why should uploaded user media never be executed on the web server?**  
*Answer:* If an attacker uploads a Python, PHP, or executable shell script into the media folder and the web server is configured to execute scripts in that directory, the attacker can execute arbitrary remote commands on your server. Media directories must always be configured with script execution completely disabled.

---

## 13. Summary

- User file uploads present severe security risks.
- Enforce extension validation and file size restrictions.
- Store media separately from executable application code.
