# 2. HTTP and HTTPS Protocols

## 1. Introduction

**Hypertext Transfer Protocol (HTTP)** is an application-layer protocol for transmitting hypermedia documents. It is the foundation of data communication for the World Wide Web. **HTTPS (HTTP Secure)** is the encrypted version of HTTP, utilizing Transport Layer Security (TLS) to encrypt all communication between client and server.

---

## 2. Why Do We Need It?

Web developers must understand HTTP because web applications interact entirely via HTTP messages. Knowing HTTP methods (GET, POST, PUT, DELETE, PATCH), request headers, and security guarantees ensures you design clean REST APIs and robust web forms.

---

## 3. How It Works

### Primary HTTP Methods:
- **GET:** Requests a representation of the specified resource. Must be idempotent and safe (no side effects on the database).
- **POST:** Submits data to be processed to the specified resource, often causing a change in state or side effects on the server.
- **PUT:** Replaces all current representations of the target resource with the uploaded content (idempotent).
- **PATCH:** Applies partial modifications to a resource.
- **DELETE:** Deletes the specified resource.

### An HTTP Request Anatomy:
```text
POST /api/v1/orders/ HTTP/1.1
Host: api.example.com
Authorization: Bearer eyJhbGciOi...
Content-Type: application/json
Content-Length: 45

{"product_id": 104, "quantity": 2}
```

---

## 4. Syntax

Handling different HTTP methods in Django views:

```python
# File: core/views.py
from django.http import HttpResponse, HttpResponseNotAllowed

def item_handler(request):
    if request.method == "GET":
        return HttpResponse("Returning item data")
    elif request.method == "POST":
        return HttpResponse("Creating new item", status=201)
    else:
        return HttpResponseNotAllowed(["GET", "POST"])
```

---

## 5. Practical Examples

### Using Django's Built-in View Decorators
```python
# File: core/views.py
from django.views.decorators.http import require_http_methods, require_POST
from django.http import JsonResponse

@require_http_methods(["GET", "POST"])
def user_endpoint(request):
    if request.method == "GET":
        return JsonResponse({"users": ["Alice", "Bob"]})
    # If POST
    return JsonResponse({"message": "User created successfully"}, status=201)

@require_POST
def delete_account(request):
    # Only allows POST submissions for security
    return JsonResponse({"message": "Account scheduled for deletion"})
```

---

## 6. Code Explanation

- `@require_http_methods(["GET", "POST"])`: A decorator that automatically checks `request.method`. If a client sends an unsupported method (e.g. `PUT`), Django automatically responds with `405 Method Not Allowed`.
- `@require_POST`: Guarantees destructive actions cannot be accidentally triggered via simple browser GET link clicks.

---

## 7. Expected Output

Sending a GET request to `/delete-account/`:
```text
HTTP/1.1 405 Method Not Allowed
Allow: POST
Content-Type: text/html; charset=utf-8
```
Sending a POST request to `/delete-account/`:
```json
{
  "message": "Account scheduled for deletion"
}
```

---

## 8. Real-World Use Case

Payment gateways, order placements, and banking transfers strictly require POST/PUT methods with CSRF protection and HTTPS encryption to prevent replay attacks and man-in-the-middle data theft.

---

## 9. Common Mistakes

1. **Using GET for state-changing operations:** e.g., `/delete-user/?id=5` via GET. Web crawlers (like Googlebot) following links could inadvertently delete all users!
2. **Sending passwords or credit cards over HTTP:** Always enforce HTTPS in production.

---

## 10. Best Practices

- Keep GET requests idempotent and safe (read-only).
- Use POST for record creation, PUT/PATCH for updates, and DELETE for removals.
- Protect all state-changing POST requests with CSRF tokens.

## 12. Interview Questions

**Q1: What does it mean for an HTTP method to be "safe" and "idempotent"?**  
*Answer:* A method is "safe" if it does not alter server state (e.g., GET, HEAD, OPTIONS). A method is "idempotent" if executing it multiple identical times produces the same result on the server as executing it once (e.g., GET, PUT, DELETE). POST is neither safe nor idempotent.

**Q2: How does Django enforce allowed HTTP methods on a view?**  
*Answer:* Developers can manually check `if request.method == "POST"` or use decorators from `django.views.decorators.http` like `@require_http_methods`, `@require_GET`, or `@require_POST`, which return an `HttpResponseNotAllowed` (405) with an `Allow` header if mismatched.

---

## 13. Summary

- HTTP is the protocol of the web; HTTPS provides TLS encryption.
- GET is for retrieving data; POST is for submitting and changing data.
- Django provides method decorators to enforce correct HTTP semantics.
