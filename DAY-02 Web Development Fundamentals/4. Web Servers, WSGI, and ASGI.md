# 4. Web Servers, WSGI, and ASGI

## 1. Introduction

A web application written in Python cannot communicate directly with traditional web servers like Nginx or Apache out of the box. To bridge this gap, Python introduced standardized interfaces: **WSGI (Web Server Gateway Interface)** and its modern asynchronous counterpart, **ASGI (Asynchronous Server Gateway Interface)**.

---

## 2. Why Do We Need It?

- Traditional web servers (Nginx, Apache) are written in C and optimized for socket handling and static file delivery, but do not speak Python.
- WSGI (PEP 3333) standardizes how servers forward requests to Python web applications.
- ASGI standardizes asynchronous capabilities, enabling WebSockets, long polling, and high-concurrency event loops in Python.

---

## 3. How It Works

### The Production Stack:
```
[ Client Browser ]
        │ HTTPS
        ▼
[ Nginx / Apache ] (Reverse Proxy, SSL Termination, Static Files)
        │ Unix Socket or TCP
        ▼
[ Gunicorn / uWSGI (WSGI) OR Uvicorn / Daphne (ASGI) ] (Application Server)
        │ Invokes Python callable
        ▼
[ Django Application (wsgi.py / asgi.py) ]
```

### WSGI vs ASGI:
- **WSGI (Synchronous):** Synchronous request-response. One worker thread processes one request at a time until completed.
- **ASGI (Asynchronous):** Built on Python's `asyncio`. Handles thousands of concurrent idle connections (WebSockets, chat, real-time notifications) with minimal memory.

---

## 4. Syntax

Inside every generated Django project:

```python
# File: myproject/wsgi.py
import os
from django.core.wsgi import get_wsgi_application

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myproject.settings')
application = get_wsgi_application()
```

```python
# File: myproject/asgi.py
import os
from django.core.asgi import get_asgi_application

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myproject.settings')
application = get_asgi_application()
```

---

## 5. Practical Examples

### Writing an Asynchronous View in Modern Django (Django 4.0+)
```python
# File: core/views.py
import asyncio
from django.http import JsonResponse

async def async_data_fetch(request):
    # Non-blocking async sleep simulating remote API call
    await asyncio.sleep(1)
    return JsonResponse({
        "status": "success",
        "mode": "asynchronous",
        "data": [10, 20, 30]
    })
```

---

## 6. Code Explanation

- `get_wsgi_application()`: Returns a callable that accepts `(environ, start_response)` per PEP 3333.
- `get_asgi_application()`: Returns a callable that accepts `(scope, receive, send)`.
- `async def async_data_fetch(request)`: In Django, views defined with `async def` run asynchronously on the event loop, releasing threads during `await` calls.

## 8. Real-World Use Case

- **Gunicorn + WSGI:** The gold standard for standard CRUD applications, content websites, and traditional business software.
- **Uvicorn / Daphne + ASGI:** Used for chat applications, live notifications, trading dashboards, and Django Channels WebSockets.

---

## 9. Common Mistakes

1. **Running `python manage.py runserver` in production:** `runserver` is single-threaded, lacks security hardening, and is intended strictly for local development.
2. Mixing blocking database calls inside `async` views without using `sync_to_async` or `a*` ORM methods (e.g. `await Article.objects.afirst()`).

---

## 10. Best Practices

- In production, always place Nginx in front of Gunicorn or Uvicorn.
- Use Gunicorn for synchronous Django applications and Uvicorn for ASGI/WebSocket workloads.

## 12. Interview Questions

**Q1: What is WSGI and why is it necessary in Python web development?**  
*Answer:* WSGI is PEP 3333, a specification describing how a web server communicates with a Python web framework. It provides a standardized interface so any WSGI server (Gunicorn, uWSGI) can run any WSGI framework (Django, Flask) interchangeably.

**Q2: What is the main advantage of ASGI over WSGI?**  
*Answer:* ASGI supports asynchronous I/O (`asyncio`), allowing long-lived connections like WebSockets, server-sent events, and concurrent background tasks without exhausting worker threads.

---

## 13. Summary

- WSGI connects synchronous Python web apps to web servers.
- ASGI enables asynchronous, non-blocking I/O and WebSockets.
- Production deployments use Nginx as a reverse proxy coupled with Gunicorn or Uvicorn.
