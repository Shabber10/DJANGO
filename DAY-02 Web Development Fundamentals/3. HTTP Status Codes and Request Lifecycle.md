# 3. HTTP Status Codes and Request Lifecycle

## 1. Introduction

Every HTTP response returned by a server includes an **HTTP Status Code**—a 3-digit integer categorized into five standard ranges. These codes communicate the outcome of the client's request, indicating whether it succeeded, failed, required redirection, or caused a server fault.

---

## 2. Why Do We Need It?

Using accurate HTTP status codes is essential for:
- Browsers to know how to render the response (e.g., render page, prompt login, follow redirect).
- REST API clients to parse responses programmatically without parsing error text.
- Search engine spiders (SEO) to index pages or update URLs upon redirects.

---

## 3. How It Works

### The Five Status Code Classes:
- **1xx (Informational):** Request received, continuing process (e.g., `101 Switching Protocols`).
- **2xx (Success):** Request successfully received, understood, and accepted.
  - `200 OK`: Standard success.
  - `201 Created`: Resource created successfully (common in POST APIs).
  - `204 No Content`: Action succeeded, no response body returned (common in DELETE).
- **3xx (Redirection):** Further action required to complete request.
  - `301 Moved Permanently`: Resource permanently relocated (SEO friendly).
  - `302 Found`: Temporary redirect.
- **4xx (Client Error):** The client sent an invalid request.
  - `400 Bad Request`: Malformed syntax or invalid payload.
  - `401 Unauthorized`: Authentication required (unauthenticated).
  - `403 Forbidden`: Authenticated, but lacking permission.
  - `404 Not Found`: Resource does not exist.
  - `405 Method Not Allowed`: HTTP method not permitted on endpoint.
- **5xx (Server Error):** Server encountered an unhandled error.
  - `500 Internal Server Error`: Unhandled exception in server code.
  - `502 Bad Gateway`: Upstream server failure.
  - `503 Service Unavailable`: Server overloaded or undergoing maintenance.

---

## 4. Syntax

Returning status codes in Django:

```python
# File: core/views.py
from django.http import HttpResponse, JsonResponse, Http404

def custom_status_view(request):
    # Explicit status parameter
    return HttpResponse("Resource Created", status=201)

def error_view(request):
    return JsonResponse({"error": "Invalid payload"}, status=400)
```

---

## 5. Practical Examples

### Real-World Status Code Logic
```python
# File: store/views.py
from django.http import JsonResponse, Http404
from django.shortcuts import get_object_or_404
from .models import Product

def get_product(request, product_id):
    try:
        product = Product.objects.get(id=product_id)
        return JsonResponse({
            "id": product.id,
            "name": product.name,
            "price": float(product.price)
        }, status=200)
    except Product.DoesNotExist:
        return JsonResponse({
            "error": "Product not found"
        }, status=404)
```

---

## 6. Code Explanation

- `status=201`: Sets the HTTP response header status line to `HTTP/1.1 201 Created`.
- `status=404`: Informs the client that the requested entity does not exist.
- `JsonResponse(..., status=...)`: Automatically sets `Content-Type: application/json` and serializes the dictionary.

---

## 7. Expected Output

Querying an existing product (`/products/1/`):
```text
HTTP/1.1 200 OK
Content-Type: application/json
{"id": 1, "name": "Mechanical Keyboard", "price": 99.99}
```

Querying a missing product (`/products/999/`):
```text
HTTP/1.1 404 Not Found
Content-Type: application/json
{"error": "Product not found"}
```

---

## 8. Real-World Use Case

In modern Single Page Applications (React, Next.js, Flutter), frontends rely strictly on status codes to display toast alerts, route users to login screens (on 401), or show 404 error layouts.

---

## 9. Common Mistakes

1. **Returning 200 OK with an error message in the body:**
   ```python
   # INCORRECT:
   return JsonResponse({"success": False, "error": "Unauthorized"}) # Status is still 200!
   # CORRECT:
   return JsonResponse({"error": "Unauthorized"}, status=401)
   ```
2. Confusing `401 Unauthorized` (identity unknown) with `403 Forbidden` (identity known, but access denied).

---

## 10. Best Practices

- Always use semantic HTTP status codes.
- Use `201 Created` when creating database records.
- Use `204 No Content` for successful deletes.
- Use Django's `get_object_or_404()` shortcut in HTML views.

## 12. Interview Questions

**Q1: What status code should a REST API return when a record is successfully deleted?**  
*Answer:* A REST API should return `204 No Content` if no response body is returned, or `200 OK` if a confirmation payload is included.

**Q2: How do you trigger a 404 response in Django?**  
*Answer:* You can raise `Http404("Message")` from `django.http`, use `get_object_or_404()`, or return `HttpResponseNotFound("Content")` / `HttpResponse(status=404)`.

---

## 13. Summary

- HTTP status codes communicate execution results to clients.
- 2xx indicates success, 3xx redirection, 4xx client errors, and 5xx server errors.
- Django allows specifying custom status codes in `HttpResponse` and `JsonResponse`.
