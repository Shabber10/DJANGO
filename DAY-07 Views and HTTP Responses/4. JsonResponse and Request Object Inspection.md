# 4. JsonResponse and Request Object Inspection

## 1. Introduction

Modern web development increasingly requires delivering JSON data to JavaScript frontends, mobile applications, and external APIs. Django provides **`JsonResponse`**, an `HttpResponse` subclass designed specifically for serializing Python data into JSON. Additionally, the `HttpRequest` object contains rich inspection tools for inspecting query parameters, POST payloads, headers, and client identity.

---

## 2. Why Do We Need It?

Using standard `HttpResponse` to send JSON requires manually calling `json.dumps()` and setting `content_type='application/json'`. `JsonResponse` streamlines this into a single constructor while providing safety checks against non-dict payloads.

---

## 3. How It Works

- `JsonResponse(data)` automatically passes `data` through `json.dumps()` using Django's `DjangoJSONEncoder` (which knows how to serialize dates, UUIDs, and decimals).
- Sets `Content-Type: application/json`.
- The `HttpRequest` object provides parsed dictionaries: `request.GET` for URL query strings, `request.POST` for form data, `request.headers` for HTTP headers, and `request.body` for raw byte payloads.

---

## 4. Syntax

```python
from django.http import JsonResponse

def api_view(request):
    data = {
        'status': 'success',
        'count': 2,
        'results': [
            {'id': 1, 'name': 'Python'},
            {'id': 2, 'name': 'Django'},
        ]
    }
    return JsonResponse(data)
```

## 5. Practical Examples

### Request Inspection and Safe JSON Handling
```python
# File: core/views.py
from django.http import JsonResponse
import json

def inspect_request(request):
    # Query parameters: ?search=django&page=2
    query_search = request.GET.get('search', '')
    query_page = request.GET.get('page', '1')

    # Reading custom HTTP headers (Django 2.2+)
    auth_header = request.headers.get('Authorization', 'None')
    client_agent = request.headers.get('User-Agent', 'Unknown')

    data = {
        "method": request.method,
        "is_ajax": request.headers.get('x-requested-with') == 'XMLHttpRequest',
        "query_params": {
            "search": query_search,
            "page": int(query_page) if query_page.isdigit() else 1
        },
        "headers": {
            "authorization_present": auth_header != 'None',
            "user_agent": client_agent,
        }
    }
    return JsonResponse(data)

def raw_json_receiver(request):
    if request.method == "POST":
        try:
            # Parse raw JSON body sent by fetch() or Postman
            payload = json.loads(request.body)
            return JsonResponse({"received": payload, "status": "processed"}, status=201)
        except json.JSONDecodeError:
            return JsonResponse({"error": "Malformed JSON payload"}, status=400)
    return JsonResponse({"error": "Method not allowed"}, status=405)
```

---

## 6. Code Explanation

- `request.GET`: A `QueryDict` instance containing GET parameters parsed from the URL query string.
- `request.headers`: A case-insensitive dictionary wrapper around HTTP request headers.
- `request.body`: The raw byte stream of the request body, useful when clients send JSON payloads via `POST`/`PUT`.
- `safe=False`: If you serialize top-level lists (e.g. `JsonResponse([1, 2, 3], safe=False)`), you must pass `safe=False`.

Frontend search autocompletion bars (typeaheads) query lightweight Django `JsonResponse` endpoints asynchronously using `fetch()` without refreshing the browser page.

## 9. Common Mistakes

1. **Returning a top-level list without `safe=False`:**
   ```python
   # INCORRECT:
   return JsonResponse([1, 2, 3]) # TypeError: In order to allow non-dict objects to be serialized set safe=False.
   # CORRECT:
   return JsonResponse([1, 2, 3], safe=False)
   ```
2. Trying to read `request.POST` when clients send raw JSON bodies (use `json.loads(request.body)` instead).

---

## 10. Best Practices

- Always pass a top-level dictionary to `JsonResponse` for security against historical JSON array vulnerabilities.
- Use `request.GET.get('key', default)` to prevent `KeyError` exceptions.

## 12. Interview Questions

**Q1: What is a `QueryDict` in Django and how does it differ from a standard Python dict?**  
*Answer:* `QueryDict` is a dictionary-like class customized to handle multiple values for the same key (e.g., `?category=shoes&category=hats`). A standard dict would overwrite earlier values, whereas `QueryDict.getlist('category')` returns all values as a list `['shoes', 'hats']`.

**Q2: Why does `JsonResponse` have `safe=True` as its default parameter?**  
*Answer:* Older ECMAScript implementations had a security vulnerability where top-level JavaScript arrays could be hijacked across domains using `Array` prototype poisoning. Forcing developers to pass dictionaries (or explicitly specify `safe=False`) mitigates this risk.

---

## 13. Summary

- `JsonResponse` serializes Python data to JSON with appropriate headers.
- Top-level non-dict objects require `safe=False`.
- `request.GET`, `request.POST`, and `request.headers` inspect incoming data.
