# 3. redirect(), Http404, and Error Handling

## 1. Introduction

Web applications frequently need to send users to different URLs after actions occur (such as logging in or submitting a form) or halt execution when requested data does not exist. Django provides the **`redirect()`** shortcut and the **`Http404`** exception to handle these flows gracefully.

---

## 2. Why Do We Need It?

- **Post/Redirect/Get (PRG) Pattern:** After a successful form submission via POST, redirecting the browser prevents duplicate submissions if the user refreshes the page.
- **Missing Resources:** When a user requests an ID that doesn't exist in the database, raising `Http404` stops execution and presents a standard 404 page.

---

## 3. How It Works

- `redirect()` returns an `HttpResponseRedirect` (HTTP status `302 Found`) or `HttpResponsePermanentRedirect` (HTTP status `301 Moved Permanently`).
- Raising `raise Http404("Item not found")` interrupts the view execution. Django catches this exception and renders the `404.html` template.

---

## 4. Syntax

```python
from django.shortcuts import redirect, get_object_or_404
from django.http import Http404

# Redirecting via route name:
def after_login(request):
    return redirect('dashboard')

# Redirecting with arguments:
def after_create(request, new_id):
    return redirect('post_detail', pk=new_id)

# Raising Http404 manually:
def item_view(request, item_id):
    if item_id > 1000:
        raise Http404("Item ID does not exist")
    return HttpResponse("Item Found")
```

---

## 5. Practical Examples

### Using get_object_or_404() Shortcut
```python
# File: blog/views.py
from django.shortcuts import render, redirect, get_object_or_404
from .models import Article

def article_detail(request, pk):
    # Automatically raises Http404 if article with pk does not exist!
    article = get_object_or_404(Article, pk=pk)
    return render(request, 'blog/detail.html', {'article': article})

def publish_article(request, pk):
    article = get_object_or_404(Article, pk=pk)
    article.is_published = True
    article.save()
    # Redirect to detail page
    return redirect('blog:article_detail', pk=article.pk)
```

---

## 6. Code Explanation

- `get_object_or_404(ModelClass, **kwargs)`: Calls `ModelClass.objects.get(**kwargs)`. If the object does not exist (`DoesNotExist` exception), it immediately catches it and raises `Http404`.
- `redirect('blog:article_detail', pk=article.pk)`: Resolves the URL dynamically and issues an HTTP 302 redirect.

---

## 7. Expected Output

Visiting an existing article `/articles/1/`:
```text
HTTP/1.1 200 OK
... HTML content ...
```

Visiting a missing article `/articles/999/` with `DEBUG=True`:
```text
Page not found (404)
No Article matches the given query.
```

With `DEBUG=False` in production:
Django renders your custom `404.html` template with HTTP status `404 Not Found`.

---

## 8. Real-World Use Case

All e-commerce checkout funnels use the Post/Redirect/Get pattern: submitting a credit card payment redirects the user to `/order-confirmation/109/` so refreshing never double-charges the card.

---

## 9. Common Mistakes

1. **Returning `Http404` instead of raising it:**
   ```python
   # INCORRECT:
   return Http404() # Http404 is an Exception, not an HttpResponse!

   # CORRECT:
   raise Http404("Item not found")
   ```
2. Hardcoding redirect paths (`redirect('/account/home/')`) instead of using URL names (`redirect('account:home')`).

---

## 10. Best Practices

- Always use `get_object_or_404()` instead of raw `try...except Model.DoesNotExist` in views.
- Always implement the Post/Redirect/Get (PRG) pattern on POST requests.
- Create custom `404.html` and `500.html` templates in the root template directory for production.

## 12. Interview Questions

**Q1: What does `get_object_or_404` do under the hood?**  
*Answer:* It executes `get()` on the model or QuerySet. If the record exists, it returns it; if `Model.DoesNotExist` is raised, it catches the exception and raises `django.http.Http404`, resulting in a clean 404 response.

**Q2: What is the Post/Redirect/Get (PRG) pattern?**  
*Answer:* PRG is a web development design pattern where a view handling an HTTP POST (e.g. form submission) redirects to an HTTP GET view rather than directly rendering a template. This ensures that if the user refreshes or bookmarks the page, they don't accidentally re-submit the POST payload.

---

## 13. Summary

- `redirect()` sends users to a new URL via HTTP 302 or 301.
- `Http404` is an exception that triggers standard 404 handling.
- `get_object_or_404` simplifies database lookups and error handling.
