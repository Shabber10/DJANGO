# 2. Template Syntax and Context Rendering

## 1. Introduction

The Django Template Language uses four primary syntactic constructs: **Variables** `{{ ... }}`, **Tags** `{% ... %}`, **Filters** `{{ ...|filter }}`, and **Comments** `{# ... #}`. Understanding how Django resolves variables and evaluates lookups is fundamental to rendering dynamic views.

---

## 2. Why Do We Need It?

Static HTML cannot display personalized user data, real-time prices, or database records. DTL provides a clean syntax to inject dynamic Python objects into HTML documents without cluttering markup.

---

## 3. How It Works

When DTL encounters a variable `{{ user.profile.bio }}`:
Django performs a sequence of lookup attempts known as **Dot Notation Resolution**:
1. **Dictionary lookup:** `user['profile']`
2. **Attribute lookup:** `user.profile`
3. **Method call lookup:** `user.profile()` (called with zero arguments)
4. **List-index lookup:** `user[profile]` (if integer index)
If all lookups fail, Django renders the setting `string_if_invalid` (empty string by default).

---

## 4. Syntax

### The Four DTL Constructs:
```html
<!-- 1. Variables: Outputs a value -->
<p>Hello, {{ user.first_name }}!</p>

<!-- 2. Tags: Performs logic, loops, or control flow -->
{% if user.is_authenticated %}
    <p>Welcome back!</p>
{% endif %}

<!-- 3. Filters: Formats or transforms data -->
<p>Joined on: {{ user.date_joined|date:"F Y" }}</p>

<!-- 4. Single-line Comment -->
{# This comment will never appear in the rendered HTML output #}

<!-- 5. Multi-line Comment -->
{% comment "Optional description" %}
    <p>This entire block is ignored by Django.</p>
{% endcomment %}
```

---

## 5. Practical Examples

### Rendering Complex Python Objects
In `views.py`:
```python
def student_profile(request):
    student = {
        'name': 'Rahul Sharma',
        'scores': [85, 92, 78],
        'address': {
            'city': 'Bengaluru',
            'state': 'Karnataka'
        }
    }
    return render(request, 'students/profile.html', {'student': student})
```

In `students/templates/students/profile.html`:
```html
<h2>Student: {{ student.name }}</h2>
<p>City: {{ student.address.city }}</p>
<p>First Test Score: {{ student.scores.0 }}</p>
```

---

## 6. Code Explanation

- `student.address.city`: Resolves nested dictionary keys.
- `student.scores.0`: Uses numeric index `0` to access the first element of the `scores` list.
- Method calls without parentheses: If an object has a method `user.get_full_name()`, in DTL you simply write `{{ user.get_full_name }}`.

---

## 7. Expected Output

Rendered browser output:
```html
<h2>Student: Rahul Sharma</h2>
<p>City: Bengaluru</p>
<p>First Test Score: 85</p>
```

---

## 8. Real-World Use Case

Rendering user profiles, shopping carts, and dynamic dashboards with nested customer details, order statuses, and localized timestamps.

---

## 9. Common Mistakes

1. **Adding parentheses to method calls in DTL:**
   ```html
   <!-- INCORRECT: -->
   <p>{{ user.get_full_name() }}</p> <!-- TemplateSyntaxError! -->
   <!-- CORRECT: -->
   <p>{{ user.get_full_name }}</p>
   ```
2. Using HTML comments `<!-- comment -->` instead of `{# comment #}` for sensitive notes. HTML comments are visible to anyone viewing browser source code!

---

## 10. Best Practices

- Use DTL comments `{# ... #}` so internal comments are stripped before sending HTML to the client.
- Avoid passing excessively deep object hierarchies to templates.

## 12. Interview Questions

**Q1: How does dot lookup work in Django templates?**  
*Answer:* Django evaluates dots in four steps: first as a dictionary key (`foo['bar']`), second as an attribute (`foo.bar`), third as a callable method (`foo.bar()`), and fourth as a list index (`foo[bar]`).

**Q2: Can you call a Python method with arguments inside a Django template?**  
*Answer:* No. DTL intentionally does not allow calling methods with arguments (e.g., `{{ user.has_perm('edit') }}`). Any data requiring parameters must be precomputed in the view or handled via a custom template filter or tag.

---

## 13. Summary

- `{{ ... }}` displays variables; `{% ... %}` executes tags.
- Dot notation resolves dict keys, attributes, methods, and list indices.
- Methods are called automatically without parentheses.
