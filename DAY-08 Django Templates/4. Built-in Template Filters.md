# 4. Built-in Template Filters

## 1. Introduction

**Template Filters** transform and format variables before they are rendered into the output. Filters are appended to variables using the pipe character (`|`), and can accept an optional argument following a colon (`:`).

---

## 2. Why Do We Need It?

Raw database values often require formatting for human consumption:
- Datetime stamps (`2026-10-31 12:00:00`) need user-friendly formatting (`Oct 31, 2026`).
- Long text passages need truncation for preview cards.
- String casing needs adjustments (lowercase, uppercase, title case).
- Missing/None values need friendly default placeholders.

---

## 3. How It Works

When DTL parses `{{ article.published_date|date:"F j, Y" }}`:
1. It retrieves `article.published_date`.
2. It passes the value and the argument `"F j, Y"` to the registered filter function `django.template.defaultfilters.date`.
3. The function returns a formatted string (`"October 31, 2026"`), which is inserted into the HTML output.
Filters can also be chained: `{{ text|lower|truncatewords:10 }}`.

---

## 4. Syntax

```html
<!-- Basic filter without argument -->
{{ name|upper }}

<!-- Filter with argument -->
{{ message|truncatewords:20 }}

<!-- Filter chaining -->
{{ title|lower|title }}

<!-- Default value if variable is None or empty -->
{{ profile.bio|default:"No biography provided yet." }}
```

---

## 5. Practical Examples

### Common Built-in Filters in Action
```html
<!-- String formatting -->
<h1>{{ "welcome to django"|title }}</h1> <!-- Welcome To Django -->
<p>{{ "HELLO WORLD"|lower }}</p>         <!-- hello world -->

<!-- Date formatting -->
<p>Published: {{ article.created_at|date:"M d, Y H:i" }}</p> <!-- Oct 31, 2026 12:00 -->

<!-- Number formatting -->
<p>Total Items: {{ items|length }}</p>
<p>File Size: {{ 1048576|filesizeformat }}</p> <!-- 1.0 MB -->

<!-- Text truncation -->
<p>{{ article.body|truncatechars:50 }}</p>
<p>{{ article.body|truncatewords:15 }}</p>

<!-- Handling HTML & Security -->
<!-- By default, Django escapes HTML: -->
{{ user_input }} 
<!-- To explicitly trust and render raw HTML: -->
{{ safe_trusted_html|safe }}
```

---

## 6. Code Explanation

- `|default:"..."`: Displays fallback text if the variable is falsey (`None`, `""`, `[]`).
- `|filesizeformat`: Converts raw bytes into human-readable units (KB, MB, GB).
- `|safe`: Marks a string as not requiring HTML escaping. **Caution:** Never use `|safe` on unvalidated user input, as it introduces XSS vulnerabilities!

---

## 7. Expected Output

Rendered browser output:
```html
<h1>Welcome To Django</h1>
<p>hello world</p>
<p>Published: Oct 31, 2026 12:00</p>
<p>Total Items: 4</p>
<p>File Size: 1.0 MB</p>
<p>Django is a high-level Python web framework that...</p>
```

---

## 8. Real-World Use Case

Formatting monetary amounts, converting timestamps to relative human time (`{{ post.created_at|timesince }} ago` -> `2 hours ago`), and showing fallback avatars or bio text.

---

## 9. Common Mistakes

1. **Adding spaces around filter arguments:**
   ```html
   <!-- INCORRECT: -->
   {{ name|default: "Anonymous" }} <!-- TemplateSyntaxError! No spaces allowed around colon -->
   <!-- CORRECT: -->
   {{ name|default:"Anonymous" }}
   ```
2. Using the `|safe` filter indiscriminately on user-submitted content.

---

## 10. Best Practices

- Keep filters focused on presentation formatting, not data computation.
- Chain filters logically: `{{ bio|striptags|truncatewords:30 }}` strips HTML tags before truncating words.

## 12. Interview Questions

**Q1: How do you chain multiple template filters together in Django?**  
*Answer:* By separating each filter with a pipe `|`: `{{ text|striptags|lower|truncatewords:20 }}`. Django evaluates filters sequentially from left to right, passing the output of each filter as input to the next.

**Q2: What is the purpose of the `|slugify` filter?**  
*Answer:* `|slugify` converts a string to lowercase, converts spaces to hyphens, and removes non-alphanumeric characters (e.g., `'Django Masterclass 2026!'|slugify` becomes `'django-masterclass-2026'`), creating URL-safe strings.

---

## 13. Summary

- Filters format and transform variables inside templates (`{{ var|filter }}`).
- Filters can accept arguments using a colon without spaces (`{{ var|date:"Y-m-d" }}`).
- Multiple filters can be chained together.
