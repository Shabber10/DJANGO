# 3. Installing Django and Verifying Setup

## 1. Introduction

Once your virtual environment is active, you can install Django using Python's package manager, **pip**. This installs the core Django framework, command-line utilities (`django-admin`), and required runtime dependencies.

---

## 2. Why Do We Need It?

Installing Django inside an isolated environment ensures reproducible builds, allows version pinning, and provides access to the `django-admin` CLI used to generate projects and manage apps.

---

## 3. How It Works

When running `pip install django`:
1. pip connects to the Python Package Index (PyPI).
2. It downloads the Django wheel package and its dependencies (e.g., `asgiref`, `sqlparse`).
3. It places the packages in `venv/Lib/site-packages/` (or `venv/lib/python3.x/site-packages/`).
4. It creates the `django-admin` executable in `venv/Scripts/` (or `venv/bin/`).

---

## 4. Syntax

```bash
# Ensure pip is up to date
python -m pip install --upgrade pip

# Install latest stable Django
pip install django

# Install specific version (e.g., LTS)
pip install "django>=5.1,<5.2"

# Verify installation
python -m django --version
```

---

## 5. Practical Examples

### Generating and Using requirements.txt
```bash
# 1. Install Django
pip install django

# 2. Check installed packages
pip list

# 3. Save dependencies to requirements.txt
pip freeze > requirements.txt

# 4. View requirements.txt content
cat requirements.txt
# (On Windows: type requirements.txt)
```

---

## 6. Code Explanation

- `pip freeze > requirements.txt`: Outputs all currently installed packages and their exact versions into a text file.
- `pip install -r requirements.txt`: Allows teammates or production servers to replicate the exact environment with a single command.

---

## 7. Expected Output

Verifying version:
```bash
python -m django --version
```
Output:
```text
5.1.2
```

`requirements.txt` contents:
```text
asgiref==3.8.1
Django==5.1.2
sqlparse==0.5.1
```

---

## 8. Real-World Use Case

In continuous delivery (CI/CD) pipelines (e.g., GitHub Actions), build runners install project dependencies using `pip install -r requirements.txt` before executing automated test suites.

---

## 9. Common Mistakes

1. Running `pip install django` outside the virtual environment.
2. Forgetting to update `requirements.txt` after installing new third-party packages.

---

## 10. Best Practices

- Always use `python -m pip` instead of bare `pip` to ensure you target the interpreter tied to your active environment.
- Pin dependency versions in `requirements.txt` for production stability.

## 12. Interview Questions

**Q1: What are the core dependencies of Django?**  
*Answer:* In modern Django (5.x), the core dependencies installed automatically are:
- `asgiref`: Provides ASGI server specifications and sync/async helper functions.
- `sqlparse`: A non-validating SQL parser used for formatting and inspecting SQL in migrations and debugging.
- `tzdata`: Provides timezone data on Windows systems.

**Q2: Why is `python -m django --version` preferred over `django-admin --version` when verifying?**  
*Answer:* `python -m django` guarantees you are testing the Django package importable by the currently active Python interpreter, preventing false positives from global `django-admin` executables in system PATH.

---

## 13. Summary

- Django is installed via `pip install django` inside an active virtual environment.
- Dependencies are captured using `pip freeze > requirements.txt`.
- Verification is performed with `python -m django --version`.
