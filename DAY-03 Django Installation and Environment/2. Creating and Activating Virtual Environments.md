# 2. Creating and Activating Virtual Environments

## 1. Introduction

Creating a virtual environment is only the first step; you must **activate** it in your terminal session before installing libraries or running commands. When activated, your terminal prompt changes to reflect the active environment.

---

## 2. Why Do We Need It?

If you run `pip install django` without activating your virtual environment, Django will be installed globally on your machine, defeating the purpose of project isolation and potentially triggering permission errors.

---

## 3. How It Works

The activation script temporarily modifies environment variables in your current shell:
- Prepend `venv/Scripts` (Windows) or `venv/bin` (macOS/Linux) to `$PATH`.
- Prepends `(venv)` to the command prompt.
Running `deactivate` restores your terminal's original environment variables.

---

## 4. Syntax

### Activation Commands by Platform:

**Windows (PowerShell):**
```powershell
.env\Scripts\Activate.ps1
```

**Windows (Command Prompt `cmd`):**
```cmd
venv\Scriptsctivate.bat
```

**macOS / Linux (bash/zsh):**
```bash
source venv/bin/activate
```

**Deactivation (All platforms):**
```bash
deactivate
```

---

## 5. Practical Examples

### Full Lifecycle in Terminal
```bash
# Activate
source venv/bin/activate

# Check active Python path
which python
# On Windows: where python

# Expected output shows path inside venv!
# .../my_project/venv/bin/python

# Deactivate when done
deactivate
```

---

## 6. Code Explanation

- `where python` / `which python`: Displays the exact binary used when typing `python`. When active, it points inside the `venv` folder.
- `deactivate`: A shell function loaded during activation that resets `$PATH` to its prior state.

---

## 7. Expected Output

In PowerShell:
```powershell
PS C:/Users\Dev\django_project> .env\Scripts\Activate.ps1
(venv) PS C:/Users\Dev\django_project>
```
In Linux / macOS:
```bash
user@machine:~/django_project$ source venv/bin/activate
(venv) user@machine:~/django_project$
```

---

## 8. Real-World Use Case

Development teams use activation scripts in automated local build steps and deployment Dockerfiles to guarantee commands run inside the isolated environment.

---

## 9. Common Mistakes

1. **PowerShell `Execution_Policies` restriction:**
   *Error:* `File ... cannot be loaded because running scripts is disabled on this system.`
   *Fix:* Run `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` in PowerShell.
2. Opening a new terminal window and forgetting to reactivate the environment.

---

## 10. Best Practices

- Always verify the `(venv)` prefix is present before running `pip install` or `python manage.py`.
- Configure VS Code to automatically activate the environment when a new terminal is opened.

## 12. Interview Questions

**Q1: What does the `source` command do when activating an environment in Linux/macOS?**  
*Answer:* `source` (or `.`) executes the script in the context of the current shell rather than spawning a subshell, allowing the script's exported environment variables (like `PATH`) to persist in the current terminal session.

**Q2: What should you do if VS Code selects the global Python interpreter instead of `venv`?**  
*Answer:* Press `Ctrl + Shift + P` (or `Cmd + Shift + P`), search for **Python: Select Interpreter**, and select the interpreter located inside `./venv/Scripts/python.exe` or `./venv/bin/python`.

---

## 13. Summary

- Activation redirects Python execution to the virtual environment directory.
- Indicated by the `(venv)` prefix in the terminal prompt.
- Restored with the `deactivate` command.
