# 2. Create and Read Operations with Views

## 1. Introduction

The **Create** and **Read** operations form the first half of the CRUD lifecycle. Read operations display collections of records (List view) or single records (Detail view). Create operations present an empty form and persist validated input to the database.

---

## 2. Why Do We Need It?

Displaying data and capturing new records are the most common interactions on the web. Implementing clean views using `ModelForm` and QuerySets ensures rapid, secure data entry.

---

## 3. How It Works

- **List View:** Queries `Model.objects.all()` and renders a table or grid.
- **Detail View:** Uses `get_object_or_404(Model, pk=pk)` and renders specific attributes.
- **Create View:** Handles GET (empty form) and POST (validates and executes `form.save()`).

---

## 4. Syntax

```python
# File: books/views.py
from django.shortcuts import render, redirect, get_object_or_404
from .models import Book
from .forms import BookForm

# 1. READ: List View
def book_list(request):
    books = Book.objects.all().order_by('-created_at')
    return render(request, 'books/book_list.html', {'books': books})

# 2. READ: Detail View
def book_detail(request, pk):
    book = get_object_or_404(Book, pk=pk)
    return render(request, 'books/book_detail.html', {'book': book})

# 3. CREATE: Form Processing
def book_create(request):
    if request.method == "POST":
        form = BookForm(request.POST)
        if form.is_valid():
            book = form.save()
            return redirect('books:detail', pk=book.pk)
    else:
        form = BookForm()
    return render(request, 'books/book_form.html', {'form': form})
```

## 6. Code Explanation

- `book = form.save()`: Persists the new record directly to the database and returns the created model instance containing its assigned `pk`.
- `redirect('books:detail', pk=book.pk)`: Implements the Post/Redirect/Get pattern, sending the user to the newly created book's detail page.

---

## 7. Expected Output

Submitting a valid book via `/books/create/`:
- Database executes SQL `INSERT INTO books_book (...) VALUES (...)`.
- Browser is redirected to `/books/14/`.
- Page renders book details with a confirmation message.

---

## 8. Real-World Use Case

Adding items to an inventory catalog, publishing blog articles, registering new student records.

## 9. Common Mistakes

1. Forgetting to pass `request.POST` to the form in POST handling: `form = BookForm()`, which creates an empty form rather than validating submitted data!

---

## 10. Best Practices

- Always use `get_object_or_404()` in detail views.
- Always implement the PRG pattern on successful creation.

## 12. Interview Questions

**Q1: How do you attach `request.user` to a model instance during `ModelForm` creation?**  
*Answer:* By calling `form.save(commit=False)`:
```python
if form.is_valid():
    book = form.save(commit=False)
    book.author = request.user
    book.save()
    form.save_m2m() # Save any many-to-many relationships
    return redirect(book)
```

**Q2: What happens if `get_object_or_404` is called and multiple matching records exist?**  
*Answer:* `get_object_or_404` invokes `get()` internally. If multiple records match the query criteria, it raises `MultipleObjectsReturned`, triggering a 500 server error rather than a 404. Lookups in `get_object_or_404` should always use unique fields (like `pk` or `slug`).

---

## 13. Summary

- Read queries data via `all()` or `get_object_or_404()`.
- Create validates POST data using `ModelForm` and persists via `form.save()`.
- Successfully created items redirect to detail pages via the PRG pattern.
