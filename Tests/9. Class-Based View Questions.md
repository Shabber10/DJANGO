## Section A: Multiple-Choice Questions

#### Q1. Which method is responsible for dispatching incoming HTTP requests to method handlers (such as `get()` or `post()`) in a Class-Based View?
- [ ] **A**. `handle()`
- [ ] **B**. `dispatch()`
- [ ] **C**. `route()`
- [ ] **D**. `execute()`

**Answer:** B. `dispatch()`  
*Explanation:* When `as_view()` is called, it creates a view function that calls `dispatch()`. `dispatch()` inspects `request.method` and forwards the request to the matching method (e.g., `get()` or `post()`).

#### Q2. In generic editing views (`CreateView` / `UpdateView`), which method is called when form validation succeeds?
- [ ] **A**. `form_success()`
- [ ] **B**. `form_valid(self, form)`
- [ ] **C**. `on_valid()`
- [ ] **D**. `save_instance()`

**Answer:** B. `form_valid(self, form)`  
*Explanation:* `form_valid(self, form)` saves the instance (`form.save()`) and redirects to `get_success_url()`. Overriding this method is the standard way to attach extra attributes (like `form.instance.author = self.request.user`).

#### Q3. In Python multiple inheritance with CBV Mixins, where must the Mixin class appear in the class definition?
- [ ] **A**. After the primary generic view (to the right)
- [ ] **B**. Before the primary generic view (to the left)
- [ ] **C**. In a separate nested class
- [ ] **D**. Placement order does not matter

**Answer:** B. Before the primary generic view (to the left)  
*Explanation:* Python resolves inheritance from left to right using Method Resolution Order (MRO). Mixins must be placed to the left of the base view class so their overridden methods (e.g., `dispatch()`) execute first.

#### Q4. Which method on `ListView` should be overridden to dynamically alter the list of objects returned?
- [ ] **A**. `get_objects()`
- [ ] **B**. `get_queryset(self)`
- [ ] **C**. `filter_data()`
- [ ] **D**. `fetch_records()`

**Answer:** B. `get_queryset(self)`  
*Explanation:* Overriding `get_queryset(self)` allows dynamic filtering based on user permissions, session data, or URL query parameters.

#### Q5. What is the purpose of `get_context_data(self, **kwargs)` in Class-Based Views?
- [ ] **A**. Validates incoming form data.
- [ ] **B**. Populates the dictionary of context variables passed to the rendered template.
- [ ] **C**. Saves records to the database.
- [ ] **D**. Authenticates the request headers.

**Answer:** B. Populates the dictionary of context variables passed to the rendered template.  
*Explanation:* `get_context_data()` constructs and returns the template context dictionary, allowing developers to inject additional variables into templates.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Reusable Multi-Tenant Mixin
**Question:** A SaaS application stores data for multiple corporate organizations. Every model contains an `organization_id`. Build a reusable CBV Mixin `TenantQuerySetMixin` that automatically restricts any `ListView`, `DetailView`, or `UpdateView` to objects belonging solely to `self.request.user.organization`.

**Model Answer:**
```python
# File: apps/core/mixins.py
from django.core.exceptions import PermissionDenied

class TenantQuerySetMixin:
    # Ensures views only query objects belonging to the current user's organization.
    def get_queryset(self):
        queryset = super().get_queryset()
        user = self.request.user
        
        if not user.is_authenticated or not hasattr(user, 'organization'):
            raise PermissionDenied("User does not belong to a valid tenant organization.")
            
        return queryset.filter(organization=user.organization)

# Usage in views:
class EmployeeListView(TenantQuerySetMixin, ListView):
    model = Employee
    template_name = 'employees/list.html'
    context_object_name = 'employees'
```

#### Exercise 1: Custom CreateView with Auto-Assigned User and Extra Context
**Problem Statement:** Write a `LeaveRequestCreateView` using `CreateView` that:
1. Attaches the currently logged-in user's employee profile (`form.instance.employee = self.request.user.employee_profile`) upon successful submission.
2. Injects the employee's remaining leave balance into the template context via `get_context_data`.

```python
# Write your solution code here
```

**Correct Code Solution:**
```python
from django.views.generic import CreateView
from django.urls import reverse_lazy
from django.contrib.auth.mixins import LoginRequiredMixin
from django.contrib.messages.views import SuccessMessageMixin
from apps.leaves.models import LeaveRequest
from apps.leaves.forms import LeaveApplicationForm

class LeaveRequestCreateView(LoginRequiredMixin, SuccessMessageMixin, CreateView):
    model = LeaveRequest
    form_class = LeaveApplicationForm
    template_name = 'leaves/apply.html'
    success_url = reverse_lazy('leaves:my_leaves')
    success_message = "Your leave request has been submitted for review."

    def form_valid(self, form):
        # Automatically assign current employee
        form.instance.employee = self.request.user.employee_profile
        return super().form_valid(form)

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        emp = self.request.user.employee_profile
        context['available_balance'] = emp.leave_balance
        return context
```

## Section D: Debugging Tasks

#### Task 1: Broken Mixin Inheritance Order
**Buggy Code Snippet:**
```python
from django.views.generic import ListView
from django.contrib.auth.mixins import LoginRequiredMixin

# Class inheritance order inverted:
class ProtectedEmployeeListView(ListView, LoginRequiredMixin):
    model = Employee
    template_name = 'employees/list.html'
```

**Bug Explanation:**  
Because `ListView` is inherited before `LoginRequiredMixin`, Python's Method Resolution Order (MRO) executes `ListView.dispatch()` before `LoginRequiredMixin.dispatch()`. Unauthenticated users will bypass the login check!

**Fixed Code Solution:**
```python
# Place Mixin to the left of the base generic view:
class ProtectedEmployeeListView(LoginRequiredMixin, ListView):
    model = Employee
    template_name = 'employees/list.html'
```
