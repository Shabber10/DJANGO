## Section A: Multiple-Choice Questions

#### Q1. Which DRF serializer class automatically generates serializer fields based on a Django model?
- [ ] **A**. `serializers.Serializer`
- [ ] **B**. `serializers.ModelSerializer`
- [ ] **C**. `serializers.DatabaseSerializer`
- [ ] **D**. `serializers.AutoSerializer`

**Answer:** B. `serializers.ModelSerializer`  
*Explanation:* `ModelSerializer` inspects the specified model and automatically generates corresponding serializer fields, default validators, and implementations of `.create()` and `.update()`.

#### Q2. Which DRF component automatically determines URL patterns for standard CRUD operations on a ViewSet?
- [ ] **A**. `URLDispatcher`
- [ ] **B**. `DefaultRouter`
- [ ] **C**. `PathResolver`
- [ ] **D**. `APIRegistry`

**Answer:** B. `DefaultRouter`  
*Explanation:* Registering a ViewSet with `DefaultRouter` (`router.register('employees', EmployeeViewSet)`) generates standard RESTful routes (`/employees/`, `/employees/{pk}/`) and an interactive root API index.

#### Q3. In a custom DRF permission class, which method enforces object-level permissions?
- [ ] **A**. `check_permission()`
- [ ] **B**. `has_permission(self, request, view)`
- [ ] **C**. `has_object_permission(self, request, view, obj)`
- [ ] **D**. `validate_object()`

**Answer:** C. `has_object_permission(self, request, view, obj)`  
*Explanation:* `has_permission` checks general view-level access. `has_object_permission` is called when retrieving or modifying a specific instance `obj` via `get_object()`.

#### Q4. What is the role of SimpleJWT's Refresh Token?
- [ ] **A**. It decrypts passwords on the database.
- [ ] **B**. It is a longer-lived token used to obtain a new short-lived Access Token without re-entering user credentials.
- [ ] **C**. It clears the browser cache.
- [ ] **D**. It acts as a CSRF token.

**Answer:** B. It is a longer-lived token used to obtain a new short-lived Access Token without re-entering user credentials.  
*Explanation:* Access tokens expire quickly (e.g., 5-15 minutes) for security. When an access token expires, the client sends the refresh token to `/api/token/refresh/` to receive a fresh access token.

#### Q5. What HTTP header must clients send when authenticating with a JSON Web Token (JWT)?
- [ ] **A**. `X-Auth-Token: <token>`
- [ ] **B**. `Authorization: Bearer <token>`
- [ ] **C**. `Cookie: jwt=<token>`
- [ ] **D**. `Token: <token>`

**Answer:** B. `Authorization: Bearer <token>`  
*Explanation:* The RFC 6750 standard specifies the `Bearer` authentication scheme in the `Authorization` header.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Multi-Role Object-Level Permissions in DRF
**Question:** Design a custom permission class `IsOwnerOrHRAdmin` that allows:
1. Any authenticated user to read articles (`GET`, `HEAD`, `OPTIONS`).
2. Only the original author of an article OR users with role `HR`/`ADMIN` to update (`PUT`/`PATCH`) or delete (`DELETE`) the article.

**Model Answer:**
```python
# File: apps/api/permissions.py
from rest_framework import permissions

class IsOwnerOrHRAdmin(permissions.BasePermission):
    # Object-level permission:
    # - Safe methods (GET, HEAD, OPTIONS) allowed to any authenticated user.
    # - Write methods allowed only to the author or HR/Admin users.
    def has_permission(self, request, view):
        return request.user and request.user.is_authenticated

    def has_object_permission(self, request, view, obj):
        # Read permissions are safe
        if request.method in permissions.SAFE_METHODS:
            return True

        # HR and Admins have full write access
        if request.user.role in ['HR', 'ADMIN'] or request.user.is_superuser:
            return True

        # Regular employees can only modify their own object
        return obj.author == request.user or getattr(obj, 'user', None) == request.user
```

#### Exercise 1: ModelViewSet with Filter, Search, and Pagination
**Problem Statement:** Write a complete `EmployeeViewSet` that:
1. Uses `EmployeeSerializer`.
2. Optimizes database queries with `select_related('user', 'department')`.
3. Supports filtering by `department` and `status`.
4. Supports searching by `employee_id` and `user__first_name`.
5. Supports ordering by `salary` and `hire_date`.

```python
# Write your solution code here
```

**Correct Code Solution:**
```python
from rest_framework import viewsets, filters
from django_filters.rest_framework import DjangoFilterBackend
from apps.employees.models import Employee
from apps.api.serializers import EmployeeSerializer
from apps.api.permissions import IsOwnerOrHRAdmin

class EmployeeViewSet(viewsets.ModelViewSet):
    queryset = Employee.objects.select_related('user', 'department').all()
    serializer_class = EmployeeSerializer
    permission_classes = [IsOwnerOrHRAdmin]
    
    filter_backends = [DjangoFilterBackend, filters.SearchFilter, filters.OrderingFilter]
    filterset_fields = ['department', 'status']
    search_fields = ['employee_id', 'user__first_name', 'user__last_name', 'designation']
    ordering_fields = ['salary', 'hire_date', 'created_at']
    ordering = ['-created_at']
```

## Section D: Debugging Tasks

#### Task 1: Missing `serializer.is_valid()` Check
**Buggy Code Snippet:**
```python
@api_view(['POST'])
def create_department(request):
    serializer = DepartmentSerializer(data=request.data)
    # Saving directly without calling is_valid():
    dept = serializer.save()  # Raises AssertionError: You must call .is_valid() before calling .save().
    return Response(serializer.data, status=201)
```

**Bug Explanation:**  
DRF requires invoking `serializer.is_valid(raise_exception=True)` before calling `serializer.save()`. Calling `.save()` prematurely raises an `AssertionError`.

**Fixed Code Solution:**
```python
@api_view(['POST'])
def create_department(request):
    serializer = DepartmentSerializer(data=request.data)
    serializer.is_valid(raise_exception=True)  # Validates and raises 400 Bad Request on failure
    dept = serializer.save()
    return Response(serializer.data, status=status.HTTP_201_CREATED)
```
