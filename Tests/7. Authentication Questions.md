## Section A: Multiple-Choice Questions

#### Q1. When starting a new Django project, why does Django officially recommend configuring a custom user model immediately?
- [ ] **A**. The built-in user model cannot store passwords.
- [ ] **B**. Changing `AUTH_USER_MODEL` mid-project after running initial migrations is notoriously complex and disrupts database foreign keys.
- [ ] **C**. Django's default user model does not support email.
- [ ] **D**. Custom user models run faster in Python.

**Answer:** B. Changing `AUTH_USER_MODEL` mid-project after running initial migrations is notoriously complex and disrupts database foreign keys.  
*Explanation:* The default User model (`auth.User`) is referenced by many internal Django tables. Switching to a custom user model after initial migrations require manual migration surgery. Creating `AbstractUser` on Day 1 ensures full future customization.

#### Q2. What algorithm does Django use by default to hash user passwords?
- [ ] **A**. MD5
- [ ] **B**. SHA-1
- [ ] **C**. PBKDF2 with SHA-256
- [ ] **D**. Plain text with salt

**Answer:** C. PBKDF2 with SHA-256  
*Explanation:* Django uses PBKDF2 (Password-Based Key Derivation Function 2) with a SHA-256 hash by default, applying hundreds of thousands of work iterations and unique cryptographic salts.

#### Q3. Which decorator restricts function-based views to authenticated users?
- [ ] **A**. `@login_required`
- [ ] **B**. `@user_passes_test`
- [ ] **C**. `@authenticate`
- [ ] **D**. `@require_user`

**Answer:** A. `@login_required`  
*Explanation:* `@login_required` checks `request.user.is_authenticated`. If false, it redirects to `settings.LOGIN_URL` with a `?next=` query parameter.

#### Q4. How do you programmatically authenticate credentials without logging the user into the session?
- [ ] **A**. `auth.login(request, username, password)`
- [ ] **B**. `auth.authenticate(request, username=username, password=password)`
- [ ] **C**. `User.objects.verify(username, password)`
- [ ] **D**. `request.user.check(username, password)`

**Answer:** B. `auth.authenticate(request, username=username, password=password)`  
*Explanation:* `authenticate()` verifies the username and password against configured authentication backends and returns the `User` instance if valid, or `None` if invalid, without creating a session.

#### Q5. Which attribute on the `User` model indicates whether a user has administrative access to the Django Admin portal?
- [ ] **A**. `is_admin`
- [ ] **B**. `is_staff`
- [ ] **C**. `is_active`
- [ ] **D**. `can_login`

**Answer:** B. `is_staff`  
*Explanation:* `is_staff = True` allows a user to log into the Django Admin dashboard. `is_superuser = True` grants all permissions unconditionally.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Email-Based Authentication
**Question:** Many modern websites use email addresses instead of usernames for authentication. Explain how to configure a custom user model inheriting from `AbstractUser` that uses `email` as the unique login identifier.

**Model Answer:**
```python
# File: apps/accounts/models.py
from django.contrib.auth.models import AbstractUser
from django.db import models

class User(AbstractUser):
    # Make email unique and mandatory
    email = models.EmailField(unique=True)
    
    # Configure email as the primary login identifier
    USERNAME_FIELD = 'email'
    # Fields prompted when running createsuperuser (excluding USERNAME_FIELD and password)
    REQUIRED_FIELDS = ['username', 'first_name', 'last_name']

    def __str__(self):
        return self.email
```
In `settings.py`:
```python
AUTH_USER_MODEL = 'accounts.User'
```

#### Exercise 1: Custom Role-Based Access Decorator
**Problem Statement:** Write a decorator `@role_required(['ADMIN', 'HR'])` that allows access only to authenticated users whose `user.role` matches one of the specified roles, raising `PermissionDenied` otherwise.

```python

```

**Correct Code Solution:**
```python
from functools import wraps
from django.core.exceptions import PermissionDenied

def role_required(allowed_roles):
    def decorator(view_func):
        @wraps(view_func)
        def _wrapped_view(request, *args, **kwargs):
            if not request.user.is_authenticated:
                from django.shortcuts import redirect
                return redirect('accounts:login')
            if request.user.role in allowed_roles or request.user.is_superuser:
                return view_func(request, *args, **kwargs)
            raise PermissionDenied("You lack the required role to view this page.")
        return _wrapped_view
    return decorator
```

## Section D: Debugging Tasks

#### Task 1: Storing Plaintext Passwords
**Buggy Code Snippet:**
```python
# Creating user programmatically:
user = User(username="john", email="john@example.com", password="MyPassword123")
user.save()
# User cannot log in!
```

**Bug Explanation:**  
Assigning a string directly to `user.password` saves the raw unhashed plaintext string. Django's authentication system expects a PBKDF2 hash string and will fail to authenticate the password.

**Fixed Code Solution:**
```python
# Use create_user helper or set_password method:
user = User.objects.create_user(username="john", email="john@example.com", password="MyPassword123")

# Or if updating an existing instance:
# user.set_password("MyPassword123")
# user.save()
```
