## Section A: Multiple-Choice Questions

#### Q1. Which HTTP status code should be returned after successfully creating a new resource via POST?
- [ ] **A**. 200 OK
- [ ] **B**. 201 Created
- [ ] **C**. 204 No Content
- [ ] **D**. 202 Accepted

**Answer:** B. 201 Created  
*Explanation:* According to REST standards (RFC 7231), HTTP 201 Created signals that the request has succeeded and led to the creation of a new resource.

#### Q2. Which HTTP method is designed for partial updates to an existing resource?
- [ ] **A**. PUT
- [ ] **B**. PATCH
- [ ] **C**. POST
- [ ] **D**. UPDATE

**Answer:** B. PATCH  
*Explanation:* `PUT` replaces the entire resource representation with the payload provided. `PATCH` applies partial modifications to specific fields.

#### Q3. In a pure Django view, how do you parse JSON data sent in the request body of a POST or PUT request?
- [ ] **A**. `request.POST['data']`
- [ ] **B**. `json.loads(request.body)`
- [ ] **C**. `request.JSON`
- [ ] **D**. `request.get_json()`

**Answer:** B. `json.loads(request.body)`  
*Explanation:* Non-form payloads (such as raw JSON) are accessed via `request.body` (raw bytes) and parsed using Python's `json.loads()`.

#### Q4. Which cURL flag specifies the HTTP request method (e.g. GET, POST, DELETE)?
- [ ] **A**. `-d`
- [ ] **B**. `-H`
- [ ] **C**. `-X`
- [ ] **D**. `-u`

**Answer:** C. `-X`  
*Explanation:* `curl -X POST ...` defines the HTTP verb. `-d` passes the request payload body, and `-H` defines HTTP headers.

#### Q5. What does idempotence mean in REST API design?
- [ ] **A**. The endpoint runs in sub-millisecond time.
- [ ] **B**. Making multiple identical requests produces the exact same server state as making a single request.
- [ ] **C**. The endpoint requires an API key.
- [ ] **D**. Data is encrypted using AES-256.

**Answer:** B. Making multiple identical requests produces the exact same server state as making a single request.  
*Explanation:* HTTP `GET`, `PUT`, `DELETE`, and `HEAD` are idempotent. Calling `DELETE /api/items/5/` ten times has the exact same net effect on database state as calling it once.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Pure Django REST Endpoint vs DRF
**Question:** Explain the trade-offs of building REST APIs using pure Django (`JsonResponse`, `json.loads(request.body)`) versus using Django REST Framework (DRF). When is pure Django sufficient?

**Model Answer:**
- **Pure Django APIs:**
  - *Pros:* Zero external dependencies, minimal memory footprint, lightweight.
  - *Cons:* Must manually parse JSON, manually validate input fields, handle JSON decoding errors, write custom serializers for complex models, and build auth token parsing from scratch.
  - *When Sufficient:* Simple internal webhooks, basic health-check endpoints, or single microservices with 1-2 endpoints.
- **Django REST Framework (DRF):**
  - *Pros:* Powerful `ModelSerializer`, automatic input validation, built-in browsable web API, pagination, authentication (JWT, OAuth, Session), rate limiting, and automated OpenAPI schema generation.
  - *When Required:* Any production-grade REST API supporting mobile apps, third-party developers, or enterprise microservices.

## Section C: Practical Coding Exercises

#### Exercise 1: Pure Django JSON CRUD Endpoint with Error Handling
**Problem Statement:** Write a pure Django view `department_api(request, pk)` that:
1. Returns department JSON on `GET`.
2. Updates `name` and `code` from JSON body on `PUT`.
3. Deletes the department on `DELETE`.
4. Returns appropriate HTTP status codes (200, 204, 400, 404, 405).

```python
# Write your solution code here
```

**Correct Code Solution:**
```python
import json
from django.http import JsonResponse, HttpResponse
from django.views.decorators.csrf import csrf_exempt
from apps.employees.models import Department

@csrf_exempt
def department_api(request, pk):
    try:
        dept = Department.objects.get(pk=pk)
    except Department.DoesNotExist:
        return JsonResponse({'error': 'Department not found'}, status=404)

    if request.method == 'GET':
        return JsonResponse({
            'id': dept.id,
            'name': dept.name,
            'code': dept.code,
            'description': dept.description
        })

    elif request.method == 'PUT':
        try:
            data = json.loads(request.body)
        except json.JSONDecodeError:
            return JsonResponse({'error': 'Invalid JSON body'}, status=400)

        dept.name = data.get('name', dept.name)
        dept.code = data.get('code', dept.code)
        dept.save()
        return JsonResponse({'id': dept.id, 'name': dept.name, 'code': dept.code})

    elif request.method == 'DELETE':
        dept.delete()
        return HttpResponse(status=204)

    return JsonResponse({'error': 'Method not allowed'}, status=405)
```

## Section D: Debugging Tasks

#### Task 1: `TypeError: In order to allow non-dict objects to be serialized set safe=False`
**Buggy Code Snippet:**
```python
def list_departments_api(request):
    departments = list(Department.objects.values('id', 'name'))
    return JsonResponse(departments)  # Raises TypeError!
```

**Bug Explanation:**  
`JsonResponse` expects a Python `dict` by default for top-level JSON objects. When passed a Python `list`, it raises `TypeError` unless `safe=False` is explicitly specified.

**Fixed Code Solution:**
```python
def list_departments_api(request):
    departments = list(Department.objects.values('id', 'name'))
    return JsonResponse(departments, safe=False)
```
