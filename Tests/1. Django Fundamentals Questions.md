## Section A: Multiple-Choice Questions

#### Q1. Which architectural pattern does Django fundamentally implement?
- [ ] **A**. Model-View-Controller (MVC)
- [ ] **B**. Model-View-Template (MVT)
- [ ] **C**. Model-View-ViewModel (MVVM)
- [ ] **D**. Pipe-and-Filter

**Answer:** B. Model-View-Template (MVT)  
*Explanation:* While closely related to MVC, Django handles the Controller responsibility internally within the framework itself, leaving developers to define the Model (data), View (business logic / data retrieval), and Template (HTML rendering).

#### Q2. What is the primary difference between a Django Project and a Django Application?
- [ ] **A**. A project contains models; an application contains only views.
- [ ] **B**. An application is the entire website; a project is a plugin.
- [ ] **C**. A project is a complete web configuration containing one or more modular applications.
- [ ] **D**. There is no difference; they are interchangeable terms.

**Answer:** C. A project is a complete web configuration containing one or more modular applications.  
*Explanation:* A Django project represents the overall website container and configuration (`settings.py`, root `urls.py`, `wsgi.py`). An application is a modular, portable Python package providing a specific business capability (e.g., `blog`, `accounts`, `billing`).

#### Q3. Which file acts as the primary command-line execution entry point for an individual Django project?
- [ ] **A**. `django-admin.py`
- [ ] **B**. `manage.py`
- [ ] **C**. `wsgi.py`
- [ ] **D**. `settings.py`

**Answer:** B. `manage.py`  
*Explanation:* `manage.py` is automatically generated in your project root. It configures `DJANGO_SETTINGS_MODULE` and delegates CLI commands (`runserver`, `migrate`, `createsuperuser`) to `django.core.management`.

#### Q4. What will happen if `DEBUG = False` is set in `settings.py` without configuring `ALLOWED_HOSTS`?
- [ ] **A**. Django will automatically use `['*']`.
- [ ] **B**. Django will raise a `CommandError` or return `Bad Request (400)` for all incoming HTTP requests.
- [ ] **C**. Django will switch to SQLite automatically.
- [ ] **D**. The web server will ignore `DEBUG = False`.

**Answer:** B. Django will raise a `CommandError` or return `Bad Request (400)` for all incoming HTTP requests.  
*Explanation:* When `DEBUG = False`, Django enforces the security barrier of `ALLOWED_HOSTS`. If the incoming request `Host` header is not explicitly matched in `ALLOWED_HOSTS`, Django rejects the request with HTTP 400 to prevent HTTP Host Header Poisoning attacks.

#### Q5. What is the role of `ROOT_URLCONF` in `settings.py`?
- [ ] **A**. It defines the database connection URL.
- [ ] **B**. It points to the top-level Python module that contains the project's root `urlpatterns` list.
- [ ] **C**. It stores the absolute path to static CSS files.
- [ ] **D**. It configures Redis caching endpoints.

**Answer:** B. It points to the top-level Python module that contains the project's root `urlpatterns` list.  
*Explanation:* When an HTTP request enters Django, the request routing engine consults `ROOT_URLCONF` (typically `<project_name>.urls`) to begin matching the URL against defined URL patterns.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Developing vs Production Configuration Isolation
**Question:** Explain how an enterprise Django team can isolate development settings (verbose SQL logging, SQLite, debug toolbars) from production settings (MySQL/PostgreSQL, WhiteNoise, Sentry, HTTPS headers) without modifying code across environments.

**Model Answer:**  
Enterprise Django applications manage environment segregation via two primary industry approaches:
1. **Environment Variables (`.env` with `python-dotenv` or `django-environ`):** A unified `settings.py` reads critical configurations dynamically (`DEBUG=os.getenv('DEBUG', 'False') == 'True'`, `DATABASES['default'] = dj_database_url.config()`). Secret keys and environment-specific parameters are injected through `.env` files or container orchestration (Kubernetes / Docker secrets).
2. **Split Settings Package:** Replacing `settings.py` with a `settings/` package containing:
   - `base.py`: Common installed apps, middleware, template configurations.
   - `development.py`: Sets `DEBUG=True`, SQLite backend, and adds `debug_toolbar`.
   - `production.py`: Sets `DEBUG=False`, production database cluster, strict HSTS, and SSL flags.
The active configuration is toggled via `export DJANGO_SETTINGS_MODULE=myproject.settings.production`.

## Section C: Practical Coding Exercises

#### Exercise 1: Dynamic Settings Helper for Comma-Separated Values
**Problem Statement:** Write a Python helper function in `settings.py` that parses a comma-separated environment variable (e.g. `ALLOWED_HOSTS=example.com,api.example.com,localhost`) into a clean Python list, stripping leading/trailing whitespace and ignoring empty strings.

```python
# Write your solution code here
```

**Correct Code Solution:**
```python
import os

def get_env_list(var_name, default=""):
    raw_val = os.environ.get(var_name, default)
    return [item.strip() for item in raw_val.split(",") if item.strip()]

# Usage in settings.py:
ALLOWED_HOSTS = get_env_list("ALLOWED_HOSTS", "127.0.0.1,localhost")
```

## Section D: Debugging Tasks

#### Task 1: Resolving `AppRegistryNotReady` Exception
**Buggy Code Snippet:**
```python
# File: myproject/settings.py
import os
from django.contrib.auth import get_user_model

# Attempting to load User model during settings evaluation:
User = get_user_model()
DEFAULT_SUPERUSER_EMAIL = User.objects.first().email if User.objects.exists() else "admin@example.com"
```

**Bug Explanation:**  
Calling `get_user_model()` or querying the database directly inside `settings.py` triggers `django.core.exceptions.AppRegistryNotReady: Apps aren't loaded yet`. Django cannot execute model operations until all applications in `INSTALLED_APPS` are fully imported and registered.

**Fixed Code Solution:**
```python
# File: myproject/settings.py
# Remove any model imports or database lookups from settings.py.
# Use environment variables or management commands instead:
import os

DEFAULT_SUPERUSER_EMAIL = os.environ.get("DEFAULT_SUPERUSER_EMAIL", "admin@example.com")
```
