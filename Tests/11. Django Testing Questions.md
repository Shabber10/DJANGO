## Section A: Multiple-Choice Questions

#### Q1. How does Django isolate individual test runs from each other when subclassing `TestCase`?
- [ ] **A**. It creates a brand-new database for every single test method.
- [ ] **B**. It wraps each test method in an atomic database transaction and rolls it back when the test finishes.
- [ ] **C**. It restarts the operating system.
- [ ] **D**. It saves data to SQLite in-memory only.

**Answer:** B. It wraps each test method in an atomic database transaction and rolls it back when the test finishes.  
*Explanation:* Django's `TestCase` executes each test method inside an atomic transaction (`transaction.atomic()`). At test completion, it issues an SQL `ROLLBACK`, restoring the database to its pristine state.

#### Q2. When should `SimpleTestCase` be used instead of `TestCase`?
- [ ] **A**. When testing views that do not interact with any database.
- [ ] **B**. When testing complex database queries.
- [ ] **C**. When running production migrations.
- [ ] **D**. There is no difference.

**Answer:** A. When testing views that do not interact with any database.  
*Explanation:* `SimpleTestCase` disallows database queries entirely, running significantly faster for pure unit tests (like testing custom template filters, forms without database queries, or utility functions).

#### Q3. Which assertion method verifies that an HTTP response has redirected to a specific destination?
- [ ] **A**. `self.assertLocation(response, '/login/')`
- [ ] **B**. `self.assertRedirects(response, expected_url)`
- [ ] **C**. `self.assertEqual(response.status_code, 302)`
- [ ] **D**. `self.assertTrue(response.is_redirect)`

**Answer:** B. `self.assertRedirects(response, expected_url)`  
*Explanation:* `assertRedirects` verifies the status code (301 or 302), follows the redirect chain, and asserts that the final URL matches `expected_url`.

#### Q4. Which tool is officially used in the Python ecosystem to measure test code coverage?
- [ ] **A**. `pytest-lint`
- [ ] **B**. `coverage.py`
- [ ] **C**. `django-audit`
- [ ] **D**. `black`

**Answer:** B. `coverage.py`  
*Explanation:* `coverage run --source='.' manage.py test` followed by `coverage report` or `coverage html` generates code coverage statistics.

#### Q5. What method allows you to test that a view triggers exactly 2 database queries?
- [ ] **A**. `self.assertDatabaseCount(2)`
- [ ] **B**. `with self.assertNumQueries(2):`
- [ ] **C**. `self.assertEqual(django.queries, 2)`
- [ ] **D**. `self.assertQueriesEqual(2)`

**Answer:** B. `with self.assertNumQueries(2):`  
*Explanation:* `assertNumQueries(n)` is a context manager provided by `TestCase` to verify that code executes an exact expected number of SQL queries, preventing N+1 regressions.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Mocking External Third-Party APIs in Tests
**Question:** When processing employee payroll, an external tax calculation API is invoked over HTTP. Explain why you must never call live third-party APIs during automated test runs, and show how to mock the API using `unittest.mock.patch`.

**Model Answer:**
- **Why Mock:** Live HTTP calls introduce network latency, rate limiting, monetary charges, and external downtime that causes flaky test failures.
- **Implementation:**
```python
from django.test import TestCase
from unittest.mock import patch
from apps.payroll.services import calculate_employee_net_pay

class PayrollTaxTest(TestCase):
    @patch('apps.payroll.services.requests.post')
    def test_tax_calculation_success(self, mock_post):
        # Configure mock return value
        mock_post.return_value.status_code = 200
        mock_post.return_value.json.return_value = {'tax_rate': 0.20, 'deduction': 1000.0}

        net_pay = calculate_employee_net_pay(gross_salary=5000.0)
        self.assertEqual(net_pay, 4000.0)
        mock_post.assert_called_once()
```

#### Exercise 1: Complete View and Authentication Test Case
**Problem Statement:** Write a complete test case for `DepartmentCreateView` that asserts:
1. Anonymous users are redirected to login (`status_code == 302`).
2. Standard employees receive `403 Forbidden`.
3. HR managers can create a department and are redirected to `departments:list`.

```python
# Write your solution code here
```

**Correct Code Solution:**
```python
from django.test import TestCase, Client
from django.urls import reverse
from django.contrib.auth import get_user_model
from apps.employees.models import Department

User = get_user_model()

class DepartmentCreateViewTest(TestCase):
    def setUp(self):
        self.client = Client()
        self.url = reverse('departments:create')
        self.hr_user = User.objects.create_user(username="hr", password="pass", role="HR")
        self.emp_user = User.objects.create_user(username="emp", password="pass", role="EMPLOYEE")

    def test_anonymous_redirect(self):
        res = self.client.get(self.url)
        self.assertEqual(res.status_code, 302)

    def test_employee_forbidden(self):
        self.client.login(username="emp", password="pass")
        res = self.client.get(self.url)
        self.assertEqual(res.status_code, 403)

    def test_hr_create_success(self):
        self.client.login(username="hr", password="pass")
        payload = {'name': 'Legal', 'code': 'LGL', 'description': 'Corporate Legal Affairs'}
        res = self.client.post(self.url, payload)
        self.assertRedirects(res, reverse('departments:list'))
        self.assertTrue(Department.objects.filter(code='LGL').exists())
```

## Section D: Debugging Tasks

#### Task 1: Flaky Tests Relying on Execution Order
**Buggy Code Snippet:**
```python
class EmployeeOrderTest(TestCase):
    def test_a_create_employee(self):
        Employee.objects.create(...)
        self.assertEqual(Employee.objects.count(), 1)

    def test_b_verify_employee_exists(self):
        # Assumes test_a ran first!
        emp = Employee.objects.first()
        self.assertIsNotNone(emp)  # FAILS!
```

**Bug Explanation:**  
Django rolls back transactions between each test method. Objects created in `test_a` are discarded when `test_b` begins. Tests must be completely independent and self-contained.

**Fixed Code Solution:**
```python
class EmployeeOrderTest(TestCase):
    def setUp(self):
        # Common setup executed freshly before every single test:
        self.emp = Employee.objects.create(...)

    def test_verify_employee_exists(self):
        self.assertIsNotNone(self.emp)
        self.assertEqual(Employee.objects.count(), 1)
```
