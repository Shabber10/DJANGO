## Section A: Multiple-Choice Questions

#### Q1. Which template tag is used to inherit from a parent layout template?
- [ ] **A**. `{% include 'base.html' %}`
- [ ] **B**. `{% extends 'base.html' %}`
- [ ] **C**. `{% load 'base.html' %}`
- [ ] **D**. `{% import 'base.html' %}`

**Answer:** B. `{% extends 'base.html' %}`  
*Explanation:* `{% extends %}` must be the very first tag in a child template, signaling to the Django template engine that it inherits blocks from the parent template.

#### Q2. What does the template filter `{{ article.content|truncatewords:30 }}` do?
- [ ] **A**. Truncates the text to 30 characters.
- [ ] **B**. Truncates the text to 30 words and appends an ellipsis (`...`).
- [ ] **C**. Splits the text into a list of 30 words.
- [ ] **D**. Replaces 30 vulgar words with asterisks.

**Answer:** B. Truncates the text to 30 words and appends an ellipsis (`...`).  
*Explanation:* `truncatewords` counts whitespace-separated words and appends `...` if the word count exceeds the specified threshold. To truncate by character count, use `truncatechars`.

#### Q3. In a Django template `{% for item in items %}` loop, how do you determine if the current iteration is the first pass?
- [ ] **A**. `{% if forloop.first %}`
- [ ] **B**. `{% if loop.index == 0 %}`
- [ ] **C**. `{% if forloop.is_start %}`
- [ ] **D**. `{% if items.first == item %}`

**Answer:** A. `{% if forloop.first %}`  
*Explanation:* The `forloop` context variable exposes loop status flags: `forloop.first` (boolean), `forloop.last` (boolean), `forloop.counter` (1-indexed), and `forloop.counter0` (0-indexed).

#### Q4. Which built-in tag prevents cross-site request forgery when submitting HTML forms?
- [ ] **A**. `{% csrf %}`
- [ ] **B**. `{% csrf_token %}`
- [ ] **C**. `{% secure_token %}`
- [ ] **D**. `{% form_security %}`

**Answer:** B. `{% csrf_token %}`  
*Explanation:* `{% csrf_token %}` renders a hidden `<input type="hidden" name="csrfmiddlewaretoken" value="...">` tag inside HTML forms.

#### Q5. What is the fundamental difference between `{% include %}` and `{% extends %}`?
- [ ] **A**. `include` is for CSS files; `extends` is for HTML files.
- [ ] **B**. `extends` creates an inheritance parent-child structure; `include` embeds a reusable snippet directly into the current location.
- [ ] **C**. `include` runs faster than `extends`.
- [ ] **D**. There is no difference.

**Answer:** B. `extends` creates an inheritance parent-child structure; `include` embeds a reusable snippet directly into the current location.  
*Explanation:* `extends` defines a master skeleton where child templates override specific `{% block %}` regions. `include` copies and renders a self-contained sub-template (like a navigation bar or alert banner) at that specific spot.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Reusable Master Layout with Dynamic Page Titles and Meta Tags
**Question:** Design a professional `base.html` template that allows child templates to dynamically define:
1. Custom `<title>` tags with a default fallback.
2. Custom OpenGraph meta tags.
3. Page-specific CSS stylesheets and JavaScript bundles without clashing.

**Model Answer:**
```html
<!-- File: templates/base.html -->
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>{% block title %}Enterprise EMS{% endblock %} | Company Portal</title>
    
    <!-- Global CSS -->
    <link rel="stylesheet" href="{% static 'css/bootstrap.min.css' %}">
    
    <!-- Child Page Specific CSS -->
    {% block extra_css %}{% endblock %}
</head>
<body>
    {% include 'includes/navbar.html' %}
    
    <main class="container my-4">
        {% include 'includes/messages.html' %}
        {% block content %}{% endblock %}
    </main>

    {% include 'includes/footer.html' %}

    <!-- Global JS -->
    <script src="{% static 'js/bootstrap.bundle.min.js' %}"></script>
    
    <!-- Child Page Specific JS -->
    {% block extra_js %}{% endblock %}
</body>
</html>
```

#### Exercise 1: Custom Template Filter for Relative Time Formatting
**Problem Statement:** Create a custom Django template filter named `time_ago` in a `custom_tags.py` file that formats a `datetime` object into a clean human-readable relative string (e.g., "5 minutes ago", "2 hours ago", "yesterday").

```python
# Write your solution code here
```

**Correct Code Solution:**
```python
# File: apps/core/templatetags/custom_tags.py
from django import template
from django.utils import timezone

register = template.Library()

@register.filter(name='time_ago')
def time_ago(value):
    if not value:
        return ""
    now = timezone.now()
    diff = now - value

    seconds = diff.total_seconds()
    if seconds < 60:
        return "just now"
    elif seconds < 3600:
        minutes = int(seconds // 60)
        return f"{minutes} minute{'s' if minutes > 1 else ''} ago"
    elif seconds < 86400:
        hours = int(seconds // 3600)
        return f"{hours} hour{'s' if hours > 1 else ''} ago"
    elif seconds < 172800:
        return "yesterday"
    else:
        days = int(seconds // 86400)
        return f"{days} days ago"
```

## Section D: Debugging Tasks

#### Task 1: Unrendered Variables Inside Empty Loops
**Buggy Code Snippet:**
```html
<!-- File: templates/employees.html -->
{% for emp in employee_list %}
    <p>{{ emp.name }}</p>
{% empty %}
    <p>No employees registered yet.</p>
{% endfor %}
```
*Issue:* The page displays "No employees registered yet" even when employees exist in the database.

**Bug Explanation:**  
The view passes context variable `employees` (`render(request, 'employees.html', {'employees': employees})`), but the template iterates over `employee_list`. Because `employee_list` evaluates to `None` in the context, the template executes the `{% empty %}` block.

**Fixed Code Solution:**
```html
<!-- Update template variable name to match context key: -->
{% for emp in employees %}
    <p>{{ emp.name }}</p>
{% empty %}
    <p class="text-muted">No employees registered yet.</p>
{% endfor %}
```
