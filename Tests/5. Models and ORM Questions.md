## Section A: Multiple-Choice Questions

#### Q1. What does the `F()` expression allow you to do in Django ORM?
- [ ] **A**. Format strings inside templates.
- [ ] **B**. Filter records by foreign keys only.
- [ ] **C**. Perform database operations referencing model field values directly on the database server without pulling them into Python memory.
- [ ] **D**. Flush the database cache.

**Answer:** C. Perform database operations referencing model field values directly on the database server without pulling them into Python memory.  
*Explanation:* `F()` expressions allow atomic SQL operations directly on the database (e.g., `Product.objects.update(stock=F('stock') - 1)`), avoiding race conditions.

#### Q2. Which QuerySet method combines multiple conditions using SQL `OR`?
- [ ] **A**. `.filter_or()`
- [ ] **B**. `Q` objects combined with the `|` operator
- [ ] **C**. `.union()`
- [ ] **D**. `models.OR()`

**Answer:** B. `Q` objects combined with the `|` operator  
*Explanation:* `Q(status='active') | Q(role='admin')` translates to SQL `WHERE status = 'active' OR role = 'admin'`.

#### Q3. What is the fundamental difference between `aggregate()` and `annotate()`?
- [ ] **A**. `aggregate()` is for SQLite; `annotate()` is for PostgreSQL.
- [ ] **B**. `aggregate()` returns a dictionary summarizing the entire QuerySet; `annotate()` adds calculated fields to each individual row in the QuerySet.
- [ ] **C**. `annotate()` modifies the database schema; `aggregate()` does not.
- [ ] **D**. They are aliases for the exact same ORM operation.

**Answer:** B. `aggregate()` returns a dictionary summarizing the entire QuerySet; `annotate()` adds calculated fields to each individual row in the QuerySet.  
*Explanation:* `aggregate(Avg('salary'))` returns `{'salary__avg': 75000.0}`. `annotate(total_employees=Count('employees'))` calculates and attaches `total_employees` to every individual department object.

#### Q4. What happens when calling `Employee.objects.get(id=999)` if record `999` does not exist?
- [ ] **A**. Returns `None`
- [ ] **B**. Returns an empty QuerySet
- [ ] **C**. Raises `Employee.DoesNotExist` exception
- [ ] **D**. Creates a new record with `id=999`

**Answer:** C. Raises `Employee.DoesNotExist` exception  
*Explanation:* `.get()` expects strictly 1 matching record. If none exist, it raises `<Model>.DoesNotExist`; if multiple records match, it raises `<Model>.MultipleObjectsReturned`.

#### Q5. Which QuerySet method checks if any records match a condition without loading all records into memory?
- [ ] **A**. `.has_any()`
- [ ] **B**. `.exists()`
- [ ] **C**. `.count() > 0`
- [ ] **D**. `.is_present()`

**Answer:** B. `.exists()`  
*Explanation:* `.exists()` executes an optimized SQL query: `SELECT (1) AS "a" FROM table LIMIT 1`, which is significantly faster than retrieving rows or evaluating `count()`.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Avoiding Race Conditions in Financial and Inventory Transactions
**Question:** Explain how a race condition occurs when updating user account balances using standard Python variables, and show how Django's `F()` expression paired with `select_for_update()` resolves it.

**Model Answer:**
- **The Problem:** Two concurrent requests read `balance = 100`. Both requests add 50 in Python memory (`100 + 50 = 150`). Both write 150 back to the database. The final balance is 150 instead of 200 (a Lost Update race condition).
- **The Solution:** Use `F()` expressions or row-level locking:
```python
from django.db import transaction
from django.db.models import F
from .models import Account

# Approach A: F expression (Direct SQL increment)
Account.objects.filter(id=account_id).update(balance=F('balance') + 50)

# Approach B: Pessimistic Locking with select_for_update
with transaction.atomic():
    account = Account.objects.select_for_update().get(id=account_id)
    account.balance += 50
    account.save()
```

## Section C: Practical Coding Exercises

#### Exercise 1: Department Statistics Aggregation
**Problem Statement:** Write an ORM query that retrieves all `Department` records annotated with:
1. `headcount`: Total number of active employees.
2. `avg_salary`: Average salary of employees in that department (rounded to 2 decimal places).
Filter out departments with zero active employees and order by `headcount` descending.

```python
# Write your solution code here
```

**Correct Code Solution:**
```python
from django.db.models import Count, Avg, Q, Round
from apps.employees.models import Department

departments = (
    Department.objects
    .annotate(
        headcount=Count('employees', filter=Q(employees__status='ACTIVE')),
        avg_salary=Round(Avg('employees__salary', filter=Q(employees__status='ACTIVE')), 2)
    )
    .filter(headcount__gt=0)
    .order_by('-headcount')
)
```

## Section D: Debugging Tasks

#### Task 1: Inefficient Filter and Exists Check
**Buggy Code Snippet:**
```python
# Check if an employee has already clocked in today:
today_attendance = Attendance.objects.filter(employee=emp, date=today)
if len(today_attendance) > 0:
    print("Already clocked in")
```

**Bug Explanation:**  
Calling `len(today_attendance)` forces the ORM to evaluate the QuerySet, fetching all columns and rows from the database into Python memory. For a simple existence check, this wastes memory and database bandwidth.

**Fixed Code Solution:**
```python
# Use .exists() for instantaneous SQL LIMIT 1 check:
if Attendance.objects.filter(employee=emp, date=today).exists():
    print("Already clocked in")
```
