## Section A: Multiple-Choice Questions

#### Q1. Where are cleaned, validated form inputs stored after calling `form.is_valid()`?
- [ ] **A**. `form.raw_data`
- [ ] **B**. `form.cleaned_data`
- [ ] **C**. `form.validated_inputs`
- [ ] **D**. `form.data`

**Answer:** B. `form.cleaned_data`  
*Explanation:* When `form.is_valid()` evaluates to `True`, validated, normalized Python data types (e.g., strings converted to integers or dates) are populated inside the `form.cleaned_data` dictionary.

#### Q2. Which method should you override to validate a single form field named `email`?
- [ ] **A**. `validate_email(self)`
- [ ] **B**. `clean_email(self)`
- [ ] **C**. `check_email(self)`
- [ ] **D**. `is_valid_email(self)`

**Answer:** B. `clean_email(self)`  
*Explanation:* Django's form validation pipeline automatically searches for methods matching the pattern `clean_<fieldname>()` to perform field-specific validation.

#### Q3. In a `ModelForm`, what does `commit=False` do when calling `form.save(commit=False)`?
- [ ] **A**. It rolls back the database transaction.
- [ ] **B**. It saves the instance to the database immediately without running validation.
- [ ] **C**. It constructs and returns the model instance without saving it to the database yet.
- [ ] **D**. It permanently disables the form.

**Answer:** C. It constructs and returns the model instance without saving it to the database yet.  
*Explanation:* `commit=False` allows developers to attach extra attributes (e.g., `instance.author = request.user`) before manually executing `instance.save()`.

#### Q4. What type of exception must custom validators raise when input fails validation?
- [ ] **A**. `ValueError`
- [ ] **B**. `TypeError`
- [ ] **C**. `django.core.exceptions.ValidationError`
- [ ] **D**. `django.forms.FormError`

**Answer:** C. `django.core.exceptions.ValidationError`  
*Explanation:* Raising `ValidationError` informs the form framework that validation failed and causes the message to be attached to the field's error list.

#### Q5. Where should cross-field validation (such as comparing `password` with `confirm_password`) be implemented?
- [ ] **A**. Inside `clean_password()`
- [ ] **B**. Inside `clean_confirm_password()`
- [ ] **C**. Inside the form's `clean()` method
- [ ] **D**. In the view function before calling `form.is_valid()`

**Answer:** C. Inside the form's `clean()` method  
*Explanation:* The form's general `clean()` method executes after individual field `clean_<fieldname>()` methods, making it the proper location to compare multiple fields from `cleaned_data`.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Multi-Step Leave Application Validation
**Question:** Design a `LeaveApplicationForm` that validates:
1. `start_date` cannot be in the past.
2. `end_date` must be equal to or greater than `start_date`.
3. Total requested days cannot exceed the employee's current `available_leave_days`.

**Model Answer:**
```python
# File: apps/leaves/forms.py
from django import forms
from django.core.exceptions import ValidationError
from django.utils import timezone
from .models import LeaveRequest

class LeaveApplicationForm(forms.ModelForm):
    class Meta:
        model = LeaveRequest
        fields = ['leave_type', 'start_date', 'end_date', 'reason']
        widgets = {
            'start_date': forms.DateInput(attrs={'type': 'date', 'class': 'form-control'}),
            'end_date': forms.DateInput(attrs={'type': 'date', 'class': 'form-control'}),
            'reason': forms.Textarea(attrs={'rows': 3, 'class': 'form-control'}),
        }

    def __init__(self, *args, **kwargs):
        # Pass employee instance to check available balance
        self.employee = kwargs.pop('employee', None)
        super().__init__(*args, **kwargs)

    def clean_start_date(self):
        start_date = self.cleaned_data.get('start_date')
        if start_date and start_date < timezone.now().date():
            raise ValidationError("Leave start date cannot be in the past.")
        return start_date

    def clean(self):
        cleaned_data = super().clean()
        start_date = cleaned_data.get('start_date')
        end_date = cleaned_data.get('end_date')

        if start_date and end_date:
            if end_date < start_date:
                raise ValidationError("End date cannot be earlier than start date.")
            
            days_requested = (end_date - start_date).days + 1
            if self.employee and self.employee.leave_balance < days_requested:
                raise ValidationError(
                    f"Insufficient leave balance. Requested {days_requested} days, but only {self.employee.leave_balance} days available."
                )
        return cleaned_data
```

#### Exercise 1: Custom Regex Validator for Employee Badges
**Problem Statement:** Write a reusable validator function `validate_employee_badge` that ensures a badge ID strictly follows the format `EMP-XXXX` where `XXXX` are 4 digits (e.g., `EMP-1049`).

**Correct Code Solution:**
```python
import re
from django.core.exceptions import ValidationError

def validate_employee_badge(value):
    pattern = r'^EMP-\d{4}$'
    if not re.match(pattern, value):
        raise ValidationError(
            f"'{value}' is not a valid badge ID. Must match the format 'EMP-XXXX' with 4 digits."
        )
```

## Section D: Debugging Tasks

#### Task 1: Missing Return Value in `clean_<field>`
**Buggy Code Snippet:**
```python
class RegistrationForm(forms.Form):
    email = forms.EmailField()

    def clean_email(self):
        email = self.cleaned_data.get('email')
        if email.endswith('@competitor.com'):
            raise ValidationError("Competitor emails not allowed.")
        # Missing return statement!
```

**Bug Explanation:**  
If a `clean_<fieldname>()` method does not explicitly return the cleaned value, Python implicitly returns `None`. Consequently, `form.cleaned_data['email']` will be set to `None`, corrupting valid email entries during form processing.

**Fixed Code Solution:**
```python
class RegistrationForm(forms.Form):
    email = forms.EmailField()

    def clean_email(self):
        email = self.cleaned_data.get('email')
        if email.endswith('@competitor.com'):
            raise ValidationError("Competitor emails not allowed.")
        return email  # Always return the validated value!
```
