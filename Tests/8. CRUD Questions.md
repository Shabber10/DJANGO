## Section A: Multiple-Choice Questions

#### Q1. Which HTTP method should strictly be used to submit record deletions to the server?
- [ ] **A**. GET
- [ ] **B**. POST or DELETE
- [ ] **C**. HEAD
- [ ] **D**. OPTIONS

**Answer:** B. POST or DELETE  
*Explanation:* Deleting data alters database state. HTTP GET requests must be safe and idempotent. Triggering deletions on GET can lead to accidental mass deletion by web crawlers or browser link prefetching.

#### Q2. In Django pagination, which class handles paginating a QuerySet?
- [ ] **A**. `django.core.paginator.Paginator`
- [ ] **B**. `django.db.pagination.PageList`
- [ ] **C**. `django.views.generic.PaginatorHelper`
- [ ] **D**. `django.utils.PageManager`

**Answer:** A. `django.core.paginator.Paginator`  
*Explanation:* `Paginator(queryset, per_page)` slices QuerySets into individual `Page` objects.

#### Q3. What is the purpose of `get_object_or_404(Model, pk=pk)`?
- [ ] **A**. Returns `None` if the object is not found.
- [ ] **B**. Calls `Model.objects.get()` and automatically raises `Http404` if `DoesNotExist` occurs.
- [ ] **C**. Automatically creates the record if it does not exist.
- [ ] **D**. Redirects to the homepage on error.

**Answer:** B. Calls `Model.objects.get()` and automatically raises `Http404` if `DoesNotExist` occurs.  
*Explanation:* `get_object_or_404` simplifies error handling by catching `DoesNotExist` and converting it directly to an HTTP 404 response.

#### Q4. In a paginated view, what exception is raised if a user requests page number `999` on a 5-page list?
- [ ] **A**. `ValueError`
- [ ] **B**. `django.core.paginator.EmptyPage`
- [ ] **C**. `django.core.paginator.PageNotAnInteger`
- [ ] **D**. `IndexError`

**Answer:** B. `django.core.paginator.EmptyPage`  
*Explanation:* `EmptyPage` is raised when the page number is a valid integer but contains no records. `PageNotAnInteger` is raised if non-numeric characters (e.g., `?page=abc`) are passed.

#### Q5. What is the standard design pattern for redirecting after a successful form POST submission?
- [ ] **A**. Render-After-Post
- [ ] **B**. Post/Redirect/Get (PRG)
- [ ] **C**. Double-Submit Pattern
- [ ] **D**. Asynchronous Callback

**Answer:** B. Post/Redirect/Get (PRG)  
*Explanation:* The Post/Redirect/Get pattern prevents duplicate form submissions when users refresh their browser after submitting data.

## Section B: Conceptual and Scenario-Based Questions

#### Scenario 1: Implementing Safe Deletion with Confirmation and Soft-Delete
**Question:** Explain how an enterprise application implements safe record deletion. Compare a physical confirmation page workflow with a soft-delete mechanism.

**Model Answer:**
1. **Physical Deletion with Confirmation Page:**
   - User clicks "Delete" -> directed to a confirmation view (`GET /employee/5/delete/`).
   - Page displays warning and `<form method="POST">{% csrf_token %}<button>Confirm</button></form>`.
   - On POST: Record is permanently removed via `employee.delete()`.
2. **Soft-Delete Alternative:**
   - Record is never physically deleted with SQL `DELETE`.
   - The model has a `deleted_at = models.DateTimeField(null=True, blank=True)`.
   - A custom model manager filters out soft-deleted records (`WHERE deleted_at IS NULL`).
   - Allows instant restoration if deleted by accident and preserves historical audit trails.

#### Exercise 1: Search, Filter, and Pagination in Function-Based View
**Problem Statement:** Write a complete function-based view `employee_list(request)` that:
1. Searches employees by first name, last name, or employee ID via query param `?q=`.
2. Filters by `department_id` via query param `?dept=`.
3. Paginates results to 10 employees per page, handling `PageNotAnInteger` and `EmptyPage`.

```python
# Write your solution code here
```

**Correct Code Solution:**
```python
from django.shortcuts import render
from django.core.paginator import Paginator, EmptyPage, PageNotAnInteger
from django.db.models import Q
from apps.employees.models import Employee, Department

def employee_list(request):
    queryset = Employee.objects.select_related('user', 'department').all()

    # Search
    search_query = request.GET.get('q', '').strip()
    if search_query:
        queryset = queryset.filter(
            Q(user__first_name__icontains=search_query) |
            Q(user__last_name__icontains=search_query) |
            Q(employee_id__icontains=search_query)
        )

    # Department Filter
    dept_id = request.GET.get('dept')
    if dept_id:
        queryset = queryset.filter(department_id=dept_id)

    # Pagination
    paginator = Paginator(queryset.order_by('-created_at'), 10)
    page_number = request.GET.get('page', 1)

    try:
        page_obj = paginator.page(page_number)
    except PageNotAnInteger:
        page_obj = paginator.page(1)
    except EmptyPage:
        page_obj = paginator.page(paginator.num_pages)

    departments = Department.objects.all()
    return render(request, 'employees/list.html', {
        'page_obj': page_obj,
        'departments': departments,
        'search_query': search_query,
        'selected_dept': dept_id,
    })
```

## Section D: Debugging Tasks

#### Task 1: Accidental Resubmission on Page Refresh
**Buggy Code Snippet:**
```python
def create_department(request):
    if request.method == 'POST':
        form = DepartmentForm(request.POST)
        if form.is_valid():
            dept = form.save()
            # Directly rendering template instead of redirecting:
            return render(request, 'departments/success.html', {'dept': dept})
    else:
        form = DepartmentForm()
    return render(request, 'departments/create.html', {'form': form})
```

**Bug Explanation:**  
Returning `render()` directly in response to a successful POST request leaves the browser in a POST state. If the user presses F5 (refresh), the browser resubmits the POST data, creating duplicate departments.

**Fixed Code Solution:**
```python
from django.shortcuts import redirect
from django.contrib import messages

def create_department(request):
    if request.method == 'POST':
        form = DepartmentForm(request.POST)
        if form.is_valid():
            dept = form.save()
            messages.success(request, f"Department '{dept.name}' created successfully.")
            return redirect('departments:list')  # PRG Pattern: Redirect to GET view!
    else:
        form = DepartmentForm()
    return render(request, 'departments/create.html', {'form': form})
```
