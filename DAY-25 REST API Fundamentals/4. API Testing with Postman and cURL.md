# 4. API Testing with Postman and cURL

## 1. Introduction

Unlike web applications that render HTML in a browser, REST APIs transmit raw JSON data. Testing and interacting with API endpoints requires specialized API clients. The two industry-standard tools are **Postman** (a powerful graphical API development environment) and **cURL** (the universal command-line data transfer tool).

---

## 2. Why Do We Need It?

Browsers natively only make GET requests when you type an address in the URL bar, and POST requests when submitting HTML forms. You cannot test PUT, PATCH, DELETE, custom HTTP headers (like `Authorization: Bearer ...`), or raw JSON payloads directly in a browser address bar. Postman and cURL allow you to execute any HTTP method with custom headers and payloads.

---

## 3. How It Works

- **cURL:** Command-line tool available on Windows (PowerShell/CMD), macOS, and Linux. Excellent for quick scriptable testing and terminal workflows.
- **Postman:** Desktop GUI application allowing developers to organize endpoints into **Collections**, manage **Environment Variables** (dev, staging, prod), inspect response headers and times, and write automated API test scripts.

---

## 4. Syntax

### Essential cURL Commands for REST APIs:

```bash
# 1. GET Request
curl http://127.0.0.1:8000/api/products/

# 2. GET Request with Headers (verbose output)
curl -i http://127.0.0.1:8000/api/products/1/

# 3. POST Request with JSON Body
curl -X POST http://127.0.0.1:8000/api/products/ \
     -H "Content-Type: application/json" \
     -d '{"name": "Wireless Mouse", "price": 29.99}'

# 4. PUT Request (Update)
curl -X PUT http://127.0.0.1:8000/api/products/1/ \
     -H "Content-Type: application/json" \
     -d '{"name": "Ergonomic Mouse", "price": 34.99}'

# 5. DELETE Request
curl -X DELETE http://127.0.0.1:8000/api/products/1/

# 6. Authenticated Request with Token
curl http://127.0.0.1:8000/api/profile/ \
     -H "Authorization: Bearer eyJhbGciOi..."
```

---

## 5. Practical Examples

### Structuring a Postman Collection
In professional development:
1. Create a Collection named `TechMart API`.
2. Add an Environment named `Local Development` with variable `{{base_url}} = http://127.0.0.1:8000`.
3. Configure requests:
   - `GET {{base_url}}/api/products/`
   - `POST {{base_url}}/api/products/` (Body > raw > JSON)
4. Postman Tests Tab: Write automated assertions in JavaScript:
   ```javascript
   pm.test("Status code is 200", function () {
       pm.response.to.have.status(200);
   });
   pm.test("Response contains products array", function () {
       var jsonData = pm.response.json();
       pm.expect(jsonData).to.be.an("array");
   });
   ```

---

## 6. Code Explanation

- `-X METHOD`: Specifies HTTP method (`POST`, `PUT`, `DELETE`).
- `-H "Header: Value"`: Injects HTTP request headers.
- `-d '{"key": "value"}'`: Sends raw data payload in the request body.
- `-i`: Includes HTTP response headers in the terminal output.

---

## 9. Common Mistakes

1. **Forgetting `-H "Content-Type: application/json"` in cURL:** Without this header, Django cannot identify that the incoming byte payload is JSON!
2. In Windows Command Prompt, single quotes `'` in `-d` can cause syntax errors; use double quotes with escaped inner quotes: `-d "{\"name\": \"Mouse\"}"`.

---

## 10. Best Practices

- Export and commit Postman collection JSON files to your project repository for team documentation.
- Use Postman environment variables (`{{base_url}}`, `{{auth_token}}`) rather than hardcoding hosts.

## 12. Interview Questions

**Q1: How do you debug an API endpoint returning `400 Bad Request` using cURL?**  
*Answer:* Run cURL with the `-v` (verbose) or `-i` (include headers) flag: `curl -v -X POST ...`. This outputs the complete HTTP conversation: the request line, outgoing headers, request payload, incoming response status line, response headers, and response error body, allowing you to verify whether headers (like `Content-Type`) or payload syntax were malformed.

**Q2: What is Newman and how does it relate to Postman?**  
*Answer:* Newman is the official command-line collection runner for Postman. It allows developers to execute Postman API collections and automated tests directly from terminal scripts or CI/CD pipelines (e.g. GitHub Actions), generating automated reports without opening the Postman desktop GUI.

---

## 13. Summary

- Postman and cURL test REST API endpoints across all HTTP methods.
- cURL is terminal-based; Postman provides a visual GUI and test scripts.
- Always include `Content-Type: application/json` when posting JSON.
