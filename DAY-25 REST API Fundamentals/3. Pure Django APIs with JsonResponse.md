# 3. Pure Django APIs with JsonResponse

## 1. Introduction

Before diving into specialized third-party frameworks like Django REST Framework (DRF), it is crucial to understand that **pure Django can build functional JSON APIs** using only built-in tools: **`JsonResponse`**, **`request.body`**, and the standard library **`json`** module.

---

## 2. Why Do We Need It?

Building a lightweight API in pure Django demystifies how REST backends operate under the hood:
- Parsing incoming JSON byte streams from `request.body`.
- Converting Python model QuerySets into JSON-serializable dictionaries.
- Setting appropriate status codes and headers manually.
This foundational understanding makes you appreciate the automation that DRF provides later.

---

## 3. How It Works

- Incoming JSON: `json.loads(request.body)` parses the raw HTTP request body into a Python dict.
- CSRF Handling: Non-browser API clients (mobile apps, Postman) do not send CSRF tokens, requiring `@csrf_exempt` on pure Django API endpoints.
- Outgoing JSON: Model attributes are converted to Python dictionaries and passed to `JsonResponse()`.

---

## 4. Syntax

```python
# File: api/views.py
import json
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from store.models import Product

@csrf_exempt
def product_api(request, pk=None):
    # READ ALL / READ ONE
    if request.method == "GET":
        if pk:
            try:
                p = Product.objects.get(pk=pk)
                return JsonResponse({'id': p.id, 'name': p.name, 'price': float(p.price)})
            except Product.DoesNotExist:
                return JsonResponse({'error': 'Product not found'}, status=404)
        
        products = list(Product.objects.values('id', 'name', 'price'))
        return JsonResponse(products, safe=False)

    # CREATE
    elif request.method == "POST":
        try:
            data = json.loads(request.body)
            p = Product.objects.create(name=data['name'], price=data['price'])
            return JsonResponse({'id': p.id, 'name': p.name, 'price': float(p.price)}, status=201)
        except (KeyError, json.JSONDecodeError):
            return JsonResponse({'error': 'Invalid payload'}, status=400)
```

## 5. Practical Examples

### Updating and Deleting Records in Pure Django

```python
    elif request.method in ["PUT", "PATCH"]:

    elif request.method == "DELETE":
        try:
            p = Product.objects.get(pk=pk)
            p.delete()
            return JsonResponse({'message': 'Deleted successfully'}, status=200)
        except Product.DoesNotExist:
            return JsonResponse({'error': 'Not found'}, status=404)
```

---

## 6. Code Explanation

- `request.body`: Contains the raw unparsed bytes sent in the HTTP request payload.
- `json.loads(request.body)`: Decodes the JSON string into a Python dictionary.
- `@csrf_exempt`: Exempts the view from CSRF token verification (essential when building pure Django APIs consumed by curl, mobile apps, or Postman).
- `list(Product.objects.values(...))`: Quickly extracts model attributes into a serializable list of dictionaries.

---

Sending a POST request via cURL:



## 8. Real-World Use Case

Building lightweight internal webhook endpoints (e.g. receiving alerts from monitoring services or payment notifications) without introducing the full dependency footprint of DRF.

---

## 9. Common Mistakes

1. **Trying to read `request.POST` for JSON payloads:** `request.POST` only parses form-encoded data (`application/x-www-form-urlencoded`). It is completely empty when clients send `application/json`! You must read `request.body`.
2. Forgetting `safe=False` when returning lists in `JsonResponse`.

---

## 10. Best Practices

- Handle `json.JSONDecodeError` to catch malformed payloads gracefully.
- Notice the limitations of pure Django: manual validation, manual serialization, and manual CSRF handling quickly become tedious—which is why **Django REST Framework (DRF)** was invented!

## 12. Interview Questions

**Q1: How do you parse an incoming JSON payload in a standard Django view?**  
*Answer:* By reading the raw byte stream from `request.body` and passing it to Python's `json.loads()`:
```python
import json
try:
    data = json.loads(request.body)
except json.JSONDecodeError:
    return JsonResponse({'error': 'Malformed JSON'}, status=400)
```

**Q2: What are the main challenges of building large REST APIs using pure Django without DRF?**  
*Answer:* Pure Django lacks:
1. Automated model serialization and deserialization.
2. Robust input validation and error formatting.
3. Token and JWT authentication backends.
4. An interactive web-browsable API UI.
5. Automated pagination, filtering, and OpenAPI/Swagger documentation generation.
These repetitive requirements are solved out-of-the-box by Django REST Framework (DRF).

---

## 13. Summary

- Pure Django builds APIs using `JsonResponse` and `request.body`.
- Requires `@csrf_exempt` for non-browser clients.
- DRF exists to eliminate the manual serialization boilerplate of pure Django APIs.
