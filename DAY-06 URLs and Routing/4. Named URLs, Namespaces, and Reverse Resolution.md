# 4. Named URLs, Namespaces, and Reverse Resolution

## 1. Introduction

Hardcoding URLs like `<a href="/store/products/42/">` directly inside templates and view logic creates brittle code. If you ever change the URL pattern, every hardcoded link throughout the project breaks. Django provides **Reverse URL Resolution** to generate URL strings dynamically using **Named URLs** and **Application Namespaces**.

---

## 2. Why Do We Need It?

- **Maintainability:** You can change URL structures in `urls.py` (e.g. from `/user-profile/` to `/u/`) and every link across all templates and Python code updates automatically.
- **Collision Prevention:** Two apps (e.g. `blog` and `store`) can both have a view named `'detail'`, distinguished cleanly via namespaces: `'blog:detail'` vs `'store:detail'`.

---

## 3. How It Works

### Reverse Resolution Workflow:
1. In `blog/urls.py`, define `app_name = 'blog'` and set `name='detail'` on the path.
2. In Python code, call `reverse('blog:detail', kwargs={'pk': 42})`.
3. In templates, call `{% url 'blog:detail' pk=42 %}`.
4. Django looks up the pattern in the URL table and constructs the string `/blog/42/`.

---

## 4. Syntax

```python
# File: blog/urls.py
from django.urls import path
from . import views

app_name = 'blog'  # Application Namespace

urlpatterns = [
    path('', views.index, name='index'),
    path('<int:pk>/', views.detail, name='detail'),
]
```

### In Templates:
```html
<a href="{% url 'blog:index' %}">All Posts</a>
<a href="{% url 'blog:detail' pk=post.id %}">{{ post.title }}</a>
```

### In Python Views:
```python
from django.urls import reverse
from django.shortcuts import redirect

def post_created_view(request):
    # Generates URL string
    url = reverse('blog:detail', kwargs={'pk': 10})
    return redirect('blog:detail', pk=10)
```

---

## 5. Practical Examples

### Cross-App Navigation Architecture
```python
# File: store/urls.py
from django.urls import path
from . import views

app_name = 'store'

urlpatterns = [
    path('product/<slug:slug>/', views.product_detail, name='product_detail'),
    path('cart/checkout/', views.checkout, name='checkout'),
]
```

In a navigation bar template (`navbar.html`):
```html
<nav>
    <a href="{% url 'blog:index' %}">Tech Blog</a>
    <a href="{% url 'store:checkout' %}">Cart & Checkout</a>
</nav>
```

---

## 6. Code Explanation

- `app_name = 'blog'`: Sets the application namespace. This tells Django that all route names inside this file are prefixed by `blog:`.
- `reverse('blog:detail', kwargs={'pk': 10})`: Performs a reverse lookup; returns the string `'/blog/10/'`.
- `redirect('blog:detail', pk=10)`: A shortcut that calls `reverse()` internally and returns an `HttpResponseRedirect` (302).

---

## 7. Expected Output

In template output:
```html
<a href="/blog/">Tech Blog</a>
<a href="/store/cart/checkout/">Cart & Checkout</a>
```
If tomorrow you change `path('cart/checkout/', ...)` to `path('pay/', ...)`, the template output automatically becomes:
```html
<a href="/store/pay/">Cart & Checkout</a>
```

---

## 8. Real-World Use Case

Large-scale SaaS platforms use namespaced URL resolution across dozens of interconnected modules (e.g. `billing:invoices`, `auth:password_reset`, `api:v1:user_list`), guaranteeing zero broken internal links.

---

## 9. Common Mistakes

1. **Forgetting `app_name` in app `urls.py`:** Causes `NoReverseMatch: 'blog' is not a registered namespace`.
2. **Passing arguments as positional instead of keyword args:**
   `reverse('blog:detail', args=[10])` works, but `kwargs={'pk': 10}` is much more readable and explicit.

---

## 10. Best Practices

- Always set `app_name` in every app's `urls.py`.
- Always use `{% url 'app:name' %}` in templates—never hardcode `/path/to/page/`.
- Use `reverse_lazy()` instead of `reverse()` in class-based view attributes.

## 12. Interview Questions

**Q1: What is a `NoReverseMatch` error and how do you fix it?**  
*Answer:* A `NoReverseMatch` exception occurs when Django's URL resolver cannot find a matching pattern for a given name, namespace, or set of arguments. Fixes include checking for typos in the pattern name, ensuring `app_name` matches the namespace prefix, and verifying that all required positional/keyword arguments (`args` or `kwargs`) match the route's path converters.

**Q2: What is the difference between `reverse()` and `reverse_lazy()`?**  
*Answer:* `reverse()` evaluates immediately upon execution. If called at module load time (e.g., when initializing class attributes or forms before `urls.py` has finished loading), it crashes. `reverse_lazy()` returns a lazy evaluation object that computes the URL string only when the attribute is actually accessed at runtime.

---

## 13. Summary

- Named URLs decouple templates and views from hardcoded URL paths.
- Application namespaces (`app_name = '...'`) prevent name collisions.
- Use `reverse()` in Python and `{% url %}` in templates.
