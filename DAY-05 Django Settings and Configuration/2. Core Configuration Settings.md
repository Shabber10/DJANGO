# 2. Core Configuration Settings

## 1. Introduction

Beyond basic flags, `settings.py` defines configuration dictionaries and lists that control the core plumbing of Django: **`MIDDLEWARE`**, **`TEMPLATES`**, **`DATABASES`**, and **`AUTH_PASSWORD_VALIDATORS`**.

---

## 2. Why Do We Need It?

Modern web backends require modular layers for security, template compilation, database drivers, and user authentication. These configuration dictionaries configure how each subsystem behaves.

---

## 3. How It Works

### Core Configurations:
1. **`MIDDLEWARE`:** An ordered list of middleware classes executed sequentially during the request/response lifecycle.
2. **`TEMPLATES`:** A list of dictionaries configuring template engines (backend, directories, context processors).
3. **`DATABASES`:** Configures database connections. Defaults to SQLite.
4. **`AUTH_PASSWORD_VALIDATORS`:** Rules enforcing strong user passwords (minimum length, common password check, numeric check).

---

## 4. Syntax

```python
# Database configuration (Default SQLite)
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}

# Middleware pipeline
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    'django.middleware.csrf.CsrfViewMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.contrib.messages.middleware.MessageMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
]
```

---

## 5. Practical Examples

### Customizing Password Strength Rules
```python
# File: config/settings.py
AUTH_PASSWORD_VALIDATORS = [
    {
        'NAME': 'django.contrib.auth.password_validation.UserAttributeSimilarityValidator',
    },
    {
        'NAME': 'django.contrib.auth.password_validation.MinimumLengthValidator',
        'OPTIONS': {
            'min_length': 10, # Enforce at least 10 characters
        }
    },
    {
        'NAME': 'django.contrib.auth.password_validation.CommonPasswordValidator',
    },
    {
        'NAME': 'django.contrib.auth.password_validation.NumericPasswordValidator',
    },
]
```

---

## 6. Code Explanation

- `ENGINE`: Specifies the database backend module (e.g. `sqlite3`, `postgresql`, `mysql`).
- `NAME`: The database file path (for SQLite) or database name on the SQL server.
- `MIDDLEWARE`: Execution order matters! Middleware runs top-to-bottom on incoming requests, and bottom-to-top on outgoing responses.

---

## 7. Expected Output

When a user attempts to register with password `password123`:
Django displays validation errors:
```text
- This password is too common.
- This password must contain at least 10 characters.
```

---

## 8. Real-World Use Case

Switching from SQLite to PostgreSQL in staging or production is accomplished simply by altering the `DATABASES['default']` dictionary without changing a single line of application model code.

---

## 9. Common Mistakes

1. Scrambling the order of `MIDDLEWARE`. For example, `AuthenticationMiddleware` relies on `SessionMiddleware`, so it must always appear *after* `SessionMiddleware`.

---

## 10. Best Practices

- Keep SQLite for quick prototyping and local unit testing.
- Use PostgreSQL or MySQL for production.
- Keep password validators enabled to protect user accounts.

## 12. Interview Questions

**Q1: Why is SQLite the default database in Django, and when should it be replaced?**  
*Answer:* SQLite requires zero installation or server setup, storing data in a single file (`db.sqlite3`), making it ideal for learning and rapid local prototyping. It should be replaced in production by PostgreSQL or MySQL because SQLite locks the entire database file during writes, creating bottlenecks under concurrent multi-user traffic.

**Q2: What happens if `CsrfViewMiddleware` is removed from `MIDDLEWARE`?**  
*Answer:* Removing it disables Django's automated protection against Cross-Site Request Forgery, leaving all POST/PUT/DELETE forms vulnerable to malicious external sites submitting requests on behalf of authenticated users.

---

## 13. Summary

- `DATABASES` defines database engines and connection details.
- `MIDDLEWARE` processes requests and responses in an ordered chain.
- `AUTH_PASSWORD_VALIDATORS` enforces password security policies.
