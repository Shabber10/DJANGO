# 2. Django Features and Architecture

## 1. Introduction

Django's architecture provides an opinionated yet flexible foundation. Rather than requiring developers to stitch together multiple uncoordinated libraries for databases, admin tools, and authentication, Django offers a cohesive developer experience where every layer is designed to collaborate smoothly.

---

## 2. Why Do We Need It?

In large-scale enterprise development, architectural consistency is paramount:
- When code follows standard design patterns, new engineers onboard quickly.
- Security practices are applied uniformly across the entire system.
- Database access and data mutations remain predictable, auditable, and testable.
- Applications remain loosely coupled, enabling modular monoliths or microservices refactoring.

---

## 3. How It Works

Django's architecture rests upon six core pillars:
1. **Object-Relational Mapper (ORM):** Interacts with databases purely through Python classes and methods, completely abstracting raw SQL queries while preventing SQL injection.
2. **Automated Admin Interface (`django.contrib.admin`):** Generates an instant, permission-protected, web-based management console directly from model definitions.
3. **URL Routing Engine (`django.urls`):** A clean URL dispatcher that maps URLs directly to callable views with typed path converters.
4. **Django Template Language (DTL):** A sandboxed, designer-friendly templating system with inheritance, tags, and filters.
5. **Security Harness:** Built-in safeguards against CSRF, XSS, SQL Injection, and Clickjacking.
6. **Database Migration Framework:** Automatically generates schema migration scripts whenever model definitions change, versioning database schemas in code.

---

## 4. Syntax

```python
# File: store/models.py
from django.db import models

class Product(models.Model):
    name = models.CharField(max_length=200)
    price = models.DecimalField(max_digits=10, decimal_places=2)
    is_active = models.BooleanField(default=True)

    def __str__(self):
        return f"{self.name} (${self.price})"
```

```python
# File: store/admin.py
from django.contrib import admin
from .models import Product

@admin.register(Product)
class ProductAdmin(admin.ModelAdmin):
    list_display = ('name', 'price', 'is_active')
    list_filter = ('is_active',)
    search_fields = ('name',)
```

## 5. Practical Examples

### Defining a Model with Domain Logic
```python
# File: academy/models.py
from django.db import models

class Course(models.Model):
    title = models.CharField(max_length=255)
    description = models.TextField()
    seats_available = models.PositiveIntegerField(default=30)
    is_published = models.BooleanField(default=False)

    def enroll_student(self):
        if self.seats_available > 0:
            self.seats_available -= 1
            self.save()
            return True
        return False
```

---

## 6. Code Explanation

- `models.Model`: Base class for all Django ORM entities.
- `enroll_student(self)`: Encapsulates domain logic directly on the model instance (Domain Model pattern), ensuring consistency across web views, APIs, and background tasks.
- `self.save()`: Generates and executes an SQL `UPDATE` statement against the active database.

## 8. Real-World Use Case

In digital learning platforms (Coursera/Udemy clones), Django's built-in Admin is used by operations, instructors, and customer support to inspect enrollments and refund requests without engineering having to build custom internal portals.

---

## 9. Common Mistakes

1. **Writing raw SQL queries for routine CRUD:** Bypasses ORM sanitization and breaks database engine portability.
2. **Modifying models without running migrations:** Causes database schema mismatch errors (`OperationalError: no such column`).

---

## 10. Best Practices

- Always implement `__str__()` on every model for readable representation in admin and logs.
- Group domain logic inside model methods rather than duplicating checks across views.
- Keep apps modular with distinct single responsibilities.

## 12. Interview Questions

**Q1: What are Django's key components and how do they interact?**  
*Answer:* Models handle data and database logic; Views handle business logic and HTTP requests; Templates render HTML; URLs route requests; Admin provides CRUD management; and Middleware intercepts requests/responses globally.

**Q2: What is the "Loose Coupling" architectural principle in Django?**  
*Answer:* Components are independent. You can change template engines, swap database backends, or run Django as a headless API without breaking other layers.

---

## 13. Summary

- Django is built upon modular, loosely coupled components providing high developer velocity.
- The ORM abstracts database queries safely and portably.
- The Admin interface gives immediate back-office productivity.
- Migrations keep database schemas version-controlled in Python code.
