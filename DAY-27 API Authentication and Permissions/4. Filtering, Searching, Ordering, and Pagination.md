# 4. Filtering, Searching, Ordering, and Pagination

## 1. Introduction

Large-scale REST APIs cannot return entire database tables in a single JSON response. Django REST Framework provides powerful, pluggable backends for **Filtering**, **Full-Text Searching**, **Dynamic Ordering**, and **Pagination** to let API clients query data flexibly.

---

## 2. Why Do We Need It?

Frontend and mobile developers need to query specific subsets of data:
- Searching products: `/api/products/?search=wireless`
- Filtering by category: `/api/products/?category=electronics`
- Sorting by price: `/api/products/?ordering=-price`
- Navigating pages: `/api/products/?page=2&page_size=20`
DRF handles all of these query parameters declaratively.

---

## 3. How It Works

- **Filtering (`django-filter`):** Maps query parameters directly to model field lookups.
- **Searching (`SearchFilter`):** Performs multi-column search (`LIKE %q%`).
- **Ordering (`OrderingFilter`):** Allows clients to specify sort columns via `?ordering=field`.
- **Pagination (`PageNumberPagination` / `LimitOffsetPagination`):** Slices QuerySets and wraps results with `count`, `next`, `previous` links.

---

## 4. Syntax

### Installing django-filter:
```bash
pip install django-filter
```

In `settings.py`:
```python
INSTALLED_APPS = [
    ...,
    'django_filters',
]

REST_FRAMEWORK = {
    'DEFAULT_FILTER_BACKENDS': [
        'django_filters.rest_framework.DjangoFilterBackend',
        'rest_framework.filters.SearchFilter',
        'rest_framework.filters.OrderingFilter',
    ],
    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination',
    'PAGE_SIZE': 10,
}
```

## 5. Practical Examples

### Complete Filtered, Searchable, Ordered ViewSet
```python
# File: store/views.py
from rest_framework import viewsets, filters
from django_filters.rest_framework import DjangoFilterBackend
from .models import Product
from .serializers import ProductSerializer

class ProductViewSet(viewsets.ModelViewSet):
    queryset = Product.objects.all().order_by('-id')
    serializer_class = ProductSerializer

    # Enable filter backends
    filter_backends = [DjangoFilterBackend, filters.SearchFilter, filters.OrderingFilter]
    
    # 1. Exact / Lookup Filtering (?is_available=true&category=1)
    filterset_fields = ['is_available', 'category']
    
    # 2. Text Search (?search=keyboard)
    search_fields = ['name', 'description']
    
    # 3. Dynamic Ordering (?ordering=-price or ?ordering=name)
    ordering_fields = ['price', 'created_at', 'stock_count']
```

---

## 6. Code Explanation

- `filterset_fields`: Enables direct field queries: `/api/products/?is_available=true`.
- `search_fields`: Searches across multiple fields using `LIKE`: `/api/products/?search=laptop`. Prefix with `^` for startswith, or `@` for full-text search.
- `ordering_fields`: Whitelists allowed sorting attributes to prevent SQL injection or unindexed sorts.

## 8. Real-World Use Case

E-commerce search engines, admin dashboards with multi-column filtering, and mobile feeds supporting infinite scrolling.

---

## 9. Common Mistakes

1. **Allowing unindexed fields in `ordering_fields`:** Sorting on unindexed columns across large tables causes slow full table scans in PostgreSQL/MySQL.
2. Forgetting to install `django-filter` when using `DjangoFilterBackend`.

---

## 10. Best Practices

- Always whitelist permitted fields in `ordering_fields` and `filterset_fields`.
- Use `PageNumberPagination` for standard pages, and `LimitOffsetPagination` for mobile infinite scroll feeds.

## 12. Interview Questions

**Q1: What are the differences between `PageNumberPagination` and `LimitOffsetPagination` in DRF?**  
*Answer:* `PageNumberPagination` uses 1-based page numbers (e.g. `?page=3`), matching traditional numbered pagination bars. `LimitOffsetPagination` uses database offsets and limits (e.g. `?limit=20&offset=40`), representing "give me 20 records starting from row 40", which is ideal for infinite-scrolling mobile feeds.

**Q2: How do you perform full-text search in PostgreSQL using DRF's `SearchFilter`?**  
*Answer:* By prefixing search fields with the `@` symbol: `search_fields = ['@name', '@description']`. When running on PostgreSQL, DRF translates `@` into PostgreSQL's native full-text search index queries (`to_tsvector`), providing fast stemming and relevance ranking.

- `django-filter` provides declarative field filtering.
- `SearchFilter` searches across text columns (`?search=`).
- Pagination wraps lists with metadata and navigation links.
