# 3. Django Caching Framework and Redis

## 1. Introduction

Generating dynamic content involves database lookups, template rendering, and business calculations. **Caching** saves the result of expensive computations into fast in-memory key-value stores (such as Redis or Memcached), allowing subsequent requests to be served in sub-millisecond response times without hitting the database.

---

## 2. Why Do We Need It?

- High-traffic websites handle thousands of identical requests per minute (e.g., product listings, news headlines).
- Database queries and ORM overhead are the primary bottlenecks in web scale.
- In-memory caching with Redis serves cached data directly from RAM at 50,000+ operations/second.

---

## 3. How It Works

Django provides 4 granular caching layers:
1. **Per-Site Caching:** Caches the entire HTTP response for the entire website via middleware.
2. **Per-View Caching:** Caches individual view responses with the `@cache_page` decorator.
3. **Template Fragment Caching:** Caches specific HTML chunks inside templates via `{% cache %}`.
4. **Low-Level Cache API:** Programmatic caching of arbitrary Python objects using `cache.get()` and `cache.set()`.

---

## 4. Syntax

```python
# File: settings.py (Django 5.x built-in Redis cache backend)
CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.redis.RedisCache',
        'LOCATION': 'redis://127.0.0.1:6379/1',
        'OPTIONS': {
            'CLIENT_CLASS': 'redis.client.Redis',
        },
        'TIMEOUT': 300,  # Default TTL: 5 minutes
    }
}
```

---

## 5. Practical Examples

### 1. View Caching with `@cache_page`
```python
# File: blog/views.py
from django.views.decorators.cache import cache_page
from django.shortcuts import render
from .models import Article

# Cache this view for 15 minutes (900 seconds)
@cache_page(60 * 15)
def popular_articles(request):
    articles = Article.objects.filter(is_popular=True).order_by('-views')[:10]
    return render(request, 'blog/popular.html', {'articles': articles})
```

### 2. Low-Level Cache API
```python
# File: services/analytics.py
from django.core.cache import cache
from .models import Order

def get_monthly_revenue_stats(year, month):
    cache_key = f"revenue_stats_{year}_{month}"
    data = cache.get(cache_key)
    
    if data is None:
        # Expensive aggregation query
        data = Order.objects.filter(created_at__year=year, created_at__month=month).aggregate(...)
        # Store in Redis for 1 hour (3600 seconds)
        cache.set(cache_key, data, timeout=3600)
    
    return data
```

---

## 6. Code Explanation

- `cache.get(key)`: Retrieves data from Redis. Returns `None` if the key does not exist or has expired.
- `cache.set(key, value, timeout)`: Serializes Python data and stores it in Redis with a Time-To-Live (TTL).
- `cache.delete(key)`: Invalidates the cache entry when underlying data is updated.
- `@cache_page(timeout)`: Automatically inspects request URL, query parameters, and headers to cache and return the full `HttpResponse`.

---

## 7. Expected Output

```text
First Request (Cache Miss):
Database query executed. Time: 145ms. Status: 200 OK.

Subsequent Requests (Cache Hit):
Served directly from Redis. Time: 3ms. Status: 200 OK.
```

## 8. Real-World Use Case

**Leaderboards and Dashboards:**
An executive dashboard calculates revenue, user acquisition, and churn rates across millions of records. Instead of recalculating every time a page refreshes, the stats are computed once an hour and cached in Redis.

---

## 9. Common Mistakes

1. **Caching User-Specific Data Globally:** Using `@cache_page` on views with user-specific sensitive data (e.g., account balance) serves one user's private data to all other users! Use `vary_on_cookie` or `vary_on_headers`.
2. **Forgetting Cache Invalidation:** Updating a database record without calling `cache.delete(key)` leaves stale, outdated data in cache.
3. **Unpicklable Objects:** Caching generator objects or unpicklable lambda functions triggers errors.

---

## 10. Best Practices

- Prefer Redis over Memcached for persistence, replication, and rich data structure support.
- Always implement cache key versioning or namespacing (e.g., `user_profile:v1:101`).
- Invalidate cache entries in model `post_save` / `post_delete` signals.

## 12. Interview Questions

**Q1: What is the Thundering Herd (Cache Stampede) problem and how do you prevent it?**
*Answer:* A cache stampede occurs when a high-traffic cache key expires. Hundreds of concurrent requests suddenly experience a cache miss simultaneously and all hit the database at once, overwhelming the server. Mitigations include: probabilistic early expiration (XFetch algorithm), distributed locking (`redis-lock`) so only one worker recalculates the cache, or background asynchronous cache regeneration.

**Q2: How does `Vary` header support work in Django's caching?**
*Answer:* When caching views, Django uses the `Vary` header (via `@vary_on_headers` or `@vary_on_cookie`) to create distinct cache keys based on specific HTTP request headers (like `Accept-Language`, `User-Agent`, or `Cookie`). This ensures mobile users get mobile-cached pages and French-language users get French-cached pages.

---

## 13. Summary

- Caching stores expensive query results and rendered views in fast RAM.
- Django 5 includes native Redis cache backend support (`django.core.cache.backends.redis.RedisCache`).
- Use `@cache_page` for views, `{% cache %}` for templates, and `cache.get()` / `cache.set()` for data.
- Always pair caching with a clear invalidation strategy.
