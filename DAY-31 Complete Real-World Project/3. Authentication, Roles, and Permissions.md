# 3. Authentication, Roles, and Permissions

## 1. Introduction

Enterprise applications serve users with diverse organizational responsibilities. A junior employee must only access their own attendance and leave records, an HR manager must be able to view and approve department-wide requests, and a system administrator must have complete operational governance. In this lesson, we implement **Role-Based Access Control (RBAC)**.

---

## 2. Why Do We Need It?

- Broken Access Control is the #1 vulnerability on the OWASP Top 10 list.
- Without role enforcement, employees could manipulate URL parameters to inspect colleagues' salaries or approve their own vacation requests.
- Decorators and mixins provide clean, DRY, reusable access barriers across views.

---

## 3. How It Works

1. **Role Definition:** Assign roles on the user model (`ADMIN`, `HR`, `EMPLOYEE`).
2. **Custom Decorators:** Check roles before executing function-based views (`@hr_required`, `@admin_required`).
3. **CBV Mixins:** Subclass `UserPassesTestMixin` to enforce role authorization on class-based views.
4. **Template Tags:** Conditionally render UI elements based on user roles (`{% if request.user.is_hr %}`).

---

## 4. Syntax

```python
# File: apps/accounts/decorators.py
from django.contrib.auth.decorators import user_passes_test
from django.core.exceptions import PermissionDenied

def hr_required(view_func):
    def check_role(user):
        if user.is_authenticated and (user.role in ['HR', 'ADMIN'] or user.is_superuser):
            return True
        raise PermissionDenied
    return user_passes_test(check_role)(view_func)

def admin_required(view_func):
    def check_role(user):
        if user.is_authenticated and (user.role == 'ADMIN' or user.is_superuser):
            return True
        raise PermissionDenied
    return user_passes_test(check_role)(view_func)
```

## 5. Practical Examples

### 1. Role-Based Class-Based View Mixin
```python
# File: apps/accounts/mixins.py
from django.contrib.auth.mixins import UserPassesTestMixin
from django.shortcuts import redirect

class HRRequiredMixin(UserPassesTestMixin):
    def test_func(self):
        user = self.request.user
        return user.is_authenticated and (user.role in ['HR', 'ADMIN'] or user.is_superuser)

    def handle_no_permission(self):
        if not self.request.user.is_authenticated:
            return redirect('accounts:login')
        from django.core.exceptions import PermissionDenied
        raise PermissionDenied("You do not have administrative HR privileges to access this area.")
```

### 2. Multi-Role Authentication Views
```python
# File: apps/accounts/views.py
from django.contrib.auth import views as auth_views
from django.shortcuts import render, redirect
from django.contrib import messages
from .forms import EmployeeRegistrationForm

class CustomLoginView(auth_views.LoginView):
    template_name = 'accounts/login.html'
    redirect_authenticated_user = True

    def get_success_url(self):
        user = self.request.user
        if user.role in ['HR', 'ADMIN']:
            return '/employees/dashboard/'
        return '/attendance/my-records/'
```

---

## 6. Code Explanation

- `PermissionDenied`: Raising this exception triggers Django's standard `403 Forbidden` response.
- `redirect_authenticated_user = True`: If an already logged-in user visits the login page, they are redirected immediately to their dashboard.
- `get_success_url()`: Dynamically routes managers to the executive dashboard and standard employees to their personal timesheet.

## 8. Real-World Use Case

**Executive Salary Confidentiality:**
Salary negotiation data must be restricted to HR executives and C-level managers. RBAC decorators prevent ordinary employees or unauthorized staff from ever querying payroll endpoints.

---

## 9. Common Mistakes

1. **Relying Only on Template Hiding:** Hiding a button in HTML with `{% if user.is_hr %}` does NOT secure the backend view. Users can still send `POST` requests directly. Always enforce checks on the server view.
2. **Hardcoding Superuser Checks:** Only checking `if user.is_superuser` prevents creating specialized staff roles like HR or department leads.
3. **Redirecting to Login on 403:** Authenticated users denied permission should see a `403 Forbidden` page, not be redirected back to the login page.

---

## 10. Best Practices

- Enforce permissions at the view layer using decorators or mixins.
- Pair view authorization with template tag conditionality for a clean UX.
- Centralize role checks inside model properties (`user.is_hr`, `user.is_admin`).

## 12. Interview Questions

**Q1: How does Django's `UserPassesTestMixin` work in Class-Based Views?**
*Answer:* `UserPassesTestMixin` is an authorization mixin from `django.contrib.auth.mixins`. It requires overriding the `test_func()` method, which must return `True` if the user is authorized or `False` if denied. When a request arrives, `dispatch()` evaluates `test_func()`. If it returns `False`, Django calls `handle_no_permission()`, which either redirects to `LOGIN_URL` (for unauthenticated users) or raises `PermissionDenied` (403 Forbidden).

**Q2: Why should you never rely on UI button hiding for access control?**
*Answer:* Hiding UI elements is strictly a presentation convenience (cosmetic security). Attackers can inspect page source, guess endpoint URLs, or construct direct HTTP requests via Postman or cURL. True security must be enforced on the server within the view, serializer, or model layer before any data is processed or returned.

---

## 13. Summary

- Implement Role-Based Access Control (RBAC) via custom user roles.
- Protect function-based views with `@hr_required` and `@admin_required` decorators.
- Protect class-based views using `HRRequiredMixin`.
- Always enforce access barriers on the backend, not merely in templates.
