# 6. REST API Integration with DRF and JWT

## 1. Introduction

Modern enterprise systems must interface with mobile applications, single-page frontends, and external third-party software. In this lesson, we expand our Employee Management System by building a high-performance **REST API** using **Django REST Framework (DRF)** secured with **JSON Web Tokens (JWT)**.

---

## 2. Why Do We Need It?

- Mobile applications (iOS/Android) cannot consume HTML templates; they require clean JSON data.
- JWT authentication enables secure, stateless API access across distributed microservices without database session lookups.
- DRF Serializers handle data validation, formatting, and nested relational lookups automatically.

---

## 3. How It Works

1. **Serializers:** Map `Department`, `Employee`, `Attendance`, and `LeaveRequest` models to JSON.
2. **ViewSets:** Provide standard REST operations (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`).
3. **Routers:** Automatically generate RESTful URL patterns (`/api/v1/employees/`).
4. **JWT Auth:** `rest_framework_simplejwt` provides token pair endpoints (`/api/token/`, `/api/token/refresh/`).

---

## 4. Syntax

```python
# File: apps/api/serializers.py
from rest_framework import serializers
from apps.employees.models import Employee, Department
from apps.attendance.models import Attendance
from apps.leaves.models import LeaveRequest

class DepartmentSerializer(serializers.ModelSerializer):
    employee_count = serializers.IntegerField(source='employees.count', read_only=True)

    class Meta:
        model = Department
        fields = ['id', 'name', 'code', 'description', 'employee_count']

class EmployeeSerializer(serializers.ModelSerializer):
    department_name = serializers.CharField(source='department.name', read_only=True)
    full_name = serializers.CharField(source='user.get_full_name', read_only=True)
    email = serializers.EmailField(source='user.email', read_only=True)

    class Meta:
        model = Employee
        fields = ['id', 'employee_id', 'full_name', 'email', 'department', 'department_name', 'designation', 'salary', 'hire_date', 'status']
```

## 5. Practical Examples

### 1. ViewSets and Custom Permissions
```python
# File: apps/api/views.py
from rest_framework import viewsets, permissions, filters
from django_filters.rest_framework import DjangoFilterBackend
from apps.employees.models import Employee, Department
from .serializers import EmployeeSerializer, DepartmentSerializer

class IsHRorReadOnly(permissions.BasePermission):
    def has_permission(self, request, view):
        if request.method in permissions.SAFE_METHODS:
            return request.user.is_authenticated
        return request.user.is_authenticated and (request.user.role in ['HR', 'ADMIN'] or request.user.is_superuser)

class EmployeeViewSet(viewsets.ModelViewSet):
    queryset = Employee.objects.select_related('user', 'department').all()
    serializer_class = EmployeeSerializer
    permission_classes = [IsHRorReadOnly]
    filter_backends = [DjangoFilterBackend, filters.SearchFilter, filters.OrderingFilter]
    filterset_fields = ['department', 'status']
    search_fields = ['user__first_name', 'user__last_name', 'employee_id', 'designation']
    ordering_fields = ['hire_date', 'salary', 'created_at']
```

### 2. URL Routing and JWT Configuration
```python
# File: apps/api/urls.py
from django.urls import path, include
from rest_framework.routers import DefaultRouter
from rest_framework_simplejwt.views import TokenObtainPairView, TokenRefreshView
from .views import EmployeeViewSet

router = DefaultRouter()
router.register(r'employees', EmployeeViewSet, basename='api-employee')

urlpatterns = [
    # JWT Authentication Endpoints
    path('token/', TokenObtainPairView.as_view(), name='token_obtain_pair'),
    path('token/refresh/', TokenRefreshView.as_view(), name='token_refresh'),
    # API Resource Routes
    path('', include(router.urls)),
]
```

---

## 6. Code Explanation

- `IsHRorReadOnly`: Custom DRF permission class allowing all authenticated employees to read employee data via `GET`, but restricting `POST`, `PUT`, and `DELETE` exclusively to HR and administrators.
- `DefaultRouter`: Generates full REST routing:
  - `GET /api/v1/employees/` -> list
  - `POST /api/v1/employees/` -> create
  - `GET /api/v1/employees/{id}/` -> retrieve
  - `PUT /api/v1/employees/{id}/` -> update
  - `DELETE /api/v1/employees/{id}/` -> destroy
- `DjangoFilterBackend`: Allows query parameter filtering (e.g., `?department=1&status=ACTIVE`).

## 9. Common Mistakes

1. **Missing Bearer Scheme Prefix:** Sending `Authorization: <token>` instead of `Authorization: Bearer <token>`.
2. **Forgetting `select_related()` on ViewSet Querysets:** Triggers severe N+1 database queries on large JSON responses.
3. **Exposing Sensitive Passwords:** Including `password` fields directly in user serializers without `write_only=True`.

---

## 10. Best Practices

- Use SimpleJWT for stateless, secure API token authentication.
- Always implement custom permission classes (`BasePermission`) to secure write actions.
- Use `DefaultRouter` for standardized, idiomatic REST API URLs.
- Include filtering, search, ordering, and pagination on all list endpoints.

## 12. Interview Questions

**Q1: How does JWT authentication differ from traditional session authentication in Django?**
*Answer:* Traditional session authentication is stateful: upon login, Django stores a session key in a database table (`django_session`) and sends a cookie to the client. On every request, Django must query the database to validate the session. JWT authentication is stateless: the server cryptographically signs a payload (containing user ID and expiration) using `SECRET_KEY`. The client includes the token in the `Authorization: Bearer <token>` header. The server verifies the token signature mathematically without hitting the database, allowing effortless horizontal scaling across multiple servers.

**Q2: What is the purpose of `source` in DRF serializer fields?**
*Answer:* The `source` argument specifies the attribute or method on the model instance from which the serializer field should extract its value. It supports dotted traversing across relationships (e.g., `source='department.name'` traverses foreign keys) and calling model methods or properties (e.g., `source='user.get_full_name'`). If omitted, DRF defaults to the field name on the model.

## 13. Summary

- DRF provides serialization and ViewSets for rapid, robust REST API creation.
- SimpleJWT enables stateless Bearer token authentication.
- Implement granular access control with `BasePermission` subclasses.
- Expose endpoints via `DefaultRouter` with integrated filtering and search.
