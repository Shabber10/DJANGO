# 2. Creating and Rendering Django Forms

## 1. Introduction

Django gives developers flexible control over how forms are presented in templates. While default helpers like `form.as_p` provide quick prototyping, production web designs often require custom CSS classes (Bootstrap, Tailwind CSS), custom grid layouts, and individual field rendering.

---

## 2. Why Do We Need It?

Enterprise UI systems require fine-grained markup control:
- Styling inputs with CSS utility classes (e.g. `class="form-control"`, `class="w-full border-gray-300 rounded"`).
- Rendering custom icon prefixes, helper text, and specific tooltip popovers.
- Placing fields in multi-column responsive grids.

---

## 3. How It Works

Django offers multiple rendering tiers:
1. **Shortcut Methods:** `form.as_p` (paragraphs), `form.as_table` (HTML table rows), `form.as_ul` (list items), `form.as_div` (modern `<div>` wrappers, default in Django 5).
2. **Field-by-Field Iteration:** Looping over `{% for field in form %}`.
3. **Manual Field Rendering:** Explicitly rendering `{{ form.email }}`, `{{ form.email.label_tag }}`, and `{{ form.email.errors }}`.

---

## 4. Syntax

```html
<!-- Method 1: Shortcut (Django 5+ default div) -->
{{ form.as_div }}

<!-- Method 2: Manual field iteration -->
{% for field in form %}
    <div class="form-group mb-3">
        {{ field.label_tag }}
        {{ field }}
        {% if field.help_text %}
            <small class="form-text text-muted">{{ field.help_text }}</small>
        {% endif %}
        {% for error in field.errors %}
            <div class="invalid-feedback d-block">{{ error }}</div>
        {% endfor %}
    </div>
{% endfor %}
```

---

## 5. Practical Examples

### Attaching CSS Classes in `forms.py`
```python
# File: accounts/forms.py
from django import forms

class UserRegistrationForm(forms.Form):
    username = forms.CharField(
        max_length=50,
        widget=forms.TextInput(attrs={
            'class': 'form-input border rounded px-3 py-2 w-full',
            'placeholder': 'Choose a username'
        })
    )
    email = forms.EmailField(
        widget=forms.EmailInput(attrs={
            'class': 'form-input border rounded px-3 py-2 w-full',
            'placeholder': 'you@example.com'
        })
    )
    terms_confirmed = forms.BooleanField(
        required=True,
        label="I accept the Terms of Service"
    )
```

---

## 6. Code Explanation

- `widget=forms.TextInput(attrs={'class': '...'})`: Injects HTML attributes (such as CSS classes, placeholders, or data attributes) directly into the rendered `<input>` tag.
- `field.label_tag`: Automatically generates `<label for="id_username">Username:</label>`.
- `field.errors`: A list of validation errors specific to that field.
- `form.non_field_errors`: Errors not associated with a specific field (e.g., cross-field login validation failures).

---

## 7. Expected Output

When rendered manually, clean custom markup is produced:
```html
<div class="form-group mb-3">
    <label for="id_username">Username:</label>
    <input type="text" name="username" class="form-input border rounded px-3 py-2 w-full" placeholder="Choose a username" id="id_username" required>
</div>
```

---

## 8. Real-World Use Case

Implementing modern Tailwind CSS or Bootstrap 5 floating labels, payment card input maskers, and accessible ARIA form elements.

---

## 9. Common Mistakes

1. **Forgetting to render `form.non_field_errors`:** If a form validation failure applies to the form as a whole, the error won't appear next to any individual field, confusing users if non-field errors aren't rendered at the top of the form.

---

## 10. Best Practices

- Render `{{ form.non_field_errors }}` at the top of the form layout.
- Use `widget.attrs` or libraries like `django-crispy-forms` for clean CSS framework integration.
- Ensure all inputs retain accessible `<label>` associations for screen readers.

## 12. Interview Questions

**Q1: How do you add CSS classes to Django form widgets?**  
*Answer:* By specifying the `widget` parameter on the field in `forms.py` and passing the `attrs` dictionary:
`name = forms.CharField(widget=forms.TextInput(attrs={'class': 'form-control'}))`. Alternatively, iterate through `self.fields.values()` in the form's `__init__` method to apply classes dynamically.

**Q2: What is the difference between `field.errors` and `form.non_field_errors()`?**  
*Answer:* `field.errors` contains validation errors tied to a specific input (e.g. invalid email format). `form.non_field_errors()` contains errors resulting from form-wide cross-field validation inside the `clean()` method (e.g., "Passwords do not match").

---

## 13. Summary

- Forms can be rendered using shortcuts (`as_div`, `as_p`) or field-by-field.
- CSS classes and HTML attributes are attached via `widget=Widget(attrs={...})`.
- Always render `non_field_errors` for complete user feedback.
