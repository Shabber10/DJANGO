# 3. Form Fields and Widgets

## 1. Introduction

In Django Forms, there is a fundamental separation between **Fields** and **Widgets**. Understanding this distinction is key: a **Field** represents data validation and type coercion logic, while a **Widget** represents the physical HTML rendering in the browser.

---

## 2. Why Do We Need It?

The same logical piece of data can be presented in multiple HTML formats:
- A `DateField` can be rendered as a text box (`TextInput`), a browser date picker (`DateInput`), or three dropdown selects (`SelectDateWidget`).
- A `ChoiceField` can be rendered as a dropdown select (`<select>`) or a list of radio buttons (`RadioSelect`).
Separating the Field (logic) from the Widget (HTML markup) provides ultimate flexibility.

---

## 3. How It Works

- **Field (`forms.CharField`, `forms.IntegerField`, etc.):** Handles Python validation, `required` status, min/max limits, and converts raw HTTP text into Python data structures.
- **Widget (`forms.TextInput`, `forms.PasswordInput`, etc.):** Generates the `<input>`, `<textarea>`, or `<select>` HTML tag and determines the `type="..."` attribute.

---

## 4. Syntax

```python
from django import forms

class OrderForm(forms.Form):
    # Field: CharField | Default Widget: TextInput
    customer_name = forms.CharField(max_length=100)

    # Field: CharField | Custom Widget: PasswordInput (masks characters)
    pin = forms.CharField(widget=forms.PasswordInput)

    # Field: CharField | Custom Widget: Textarea
    delivery_notes = forms.CharField(widget=forms.Textarea(attrs={'rows': 3}))

    # Field: ChoiceField | Default Widget: Select
    SHIPPING_CHOICES = [
        ('std', 'Standard (3-5 days)'),
        ('exp', 'Express (1-2 days)'),
        ('ovn', 'Overnight Delivery'),
    ]
    shipping_method = forms.ChoiceField(choices=SHIPPING_CHOICES, widget=forms.RadioSelect)

    # Field: DateField | Custom Widget: DateInput with HTML5 datepicker
    delivery_date = forms.DateField(widget=forms.DateInput(attrs={'type': 'date'}))
```

## 5. Practical Examples

### Exploring Multiple Widgets
```python
# File: survey/forms.py
from django import forms

class FeedbackForm(forms.Form):
    RATING_CHOICES = [(1, '★☆☆☆☆'), (2, '★★☆☆☆'), (3, '★★★☆☆'), (4, '★★★★☆'), (5, '★★★★★')]
    
    rating = forms.ChoiceField(
        choices=RATING_CHOICES,
        widget=forms.RadioSelect,
        initial=5
    )
    subscribe_newsletter = forms.BooleanField(
        required=False,
        widget=forms.CheckboxInput,
        label="Subscribe to monthly developer digest"
    )
```

---

## 6. Code Explanation

- `widget=forms.PasswordInput`: Renders `<input type="password">`, masking characters as they are typed.
- `widget=forms.RadioSelect`: Renders individual `<input type="radio">` tags for each choice instead of a `<select>` dropdown.
- `attrs={'type': 'date'}`: Instructs modern browsers to display native datepicker calendar popups.

---

## 7. Expected Output

`FeedbackForm` rendered in HTML:
- A series of 5 radio buttons with star ratings.
- A checkbox input for the newsletter subscription.
- Clean semantic HTML mapped to Python data types.

## 8. Real-World Use Case

Designing customer checkout forms where payment options are displayed as custom radio cards, and birthdates use HTML5 calendar pickers.

---

## 9. Common Mistakes

1. **Confusing Fields and Widgets:** Writing `forms.PasswordInput()` as a field definition (e.g. `password = forms.PasswordInput()`). Remember: `CharField` is the field; `PasswordInput` is the widget!
   ```python
   # INCORRECT:
   password = forms.PasswordInput() # Error!
   # CORRECT:
   password = forms.CharField(widget=forms.PasswordInput)
   ```

---

## 10. Best Practices

- Use HTML5 widget types (`type='date'`, `type='number'`, `type='email'`) to leverage native browser validation and mobile keyboards.
- Define choices as tuples of `(stored_value, display_label)`.

## 12. Interview Questions

**Q1: What is the relationship between Form Fields and Form Widgets in Django?**  
*Answer:* A Form Field is responsible for data validation, cleaning, and conversion into Python data types. A Form Widget is responsible for HTML rendering (generating `<input>`, `<select>`, `<textarea>` markup). Every field has a default widget (e.g., `CharField` defaults to `TextInput`), which can be overridden via the `widget` argument.

**Q2: What is the difference between `ChoiceField` and `MultipleChoiceField`?**  
*Answer:* `ChoiceField` validates a single selection from a predefined set of choices (default widget `<select>`), returning a single value. `MultipleChoiceField` allows selecting multiple choices (default widget `<select multiple>`), validating that all selected values exist in `choices` and returning a Python list of selected values.

---

## 13. Summary

- Fields handle Python validation; Widgets handle HTML rendering.
- Common widgets include `TextInput`, `PasswordInput`, `Textarea`, `RadioSelect`, `Select`.
- HTML attributes can be injected via `attrs={...}` on the widget.
