# 1. Django Security Architecture and OWASP Top 10

## 1. Introduction

Security is not an afterthought in Django; it is an architectural foundation. Django was deliberately engineered to protect applications against the most common vulnerabilities cataloged in the **OWASP Top 10** by default. Django's security-first philosophy mitigates vulnerabilities before developers write a single line of business logic.

---

## 2. Why Do We Need It?

Web applications face constant automated attacks:
- Data breaches caused by SQL Injection or stolen sessions cost organizations millions in fines and reputational damage.
- Cross-Site Scripting (XSS) allows attackers to hijack accounts.
- Django's built-in defenses protect against these threats automatically, provided developers follow standard framework patterns.

---

## 3. How It Works

### Django's Defenses Against OWASP Top 10:
1. **Injection (SQLi):** Parameterized queries in Django ORM prevent user input from breaking out of SQL syntax.
2. **Broken Authentication:** Salted PBKDF2 hashing, session fixation protection, and secure cookie flags.
3. **Cross-Site Scripting (XSS):** Automated HTML escaping in the Django Template Language.
4. **Cross-Site Request Forgery (CSRF):** Mandatory cryptographic CSRF tokens on all POST/PUT/DELETE forms.
5. **Security Misconfiguration:** `python manage.py check --deploy` audit command.

---

## 4. Syntax

### Running Django's Automated Security Audit:
```bash
python manage.py check --deploy
```

---

## 5. Practical Examples

### Interpreting `check --deploy` Output
```text
System check identified some issues:

WARNINGS:
?: (security.W004) You have not set SECURE_HSTS_SECONDS.
?: (security.W008) Your SECURE_SSL_REDIRECT setting is not set to True.
?: (security.W012) SESSION_COOKIE_SECURE is not set to True.
?: (security.W016) CSRF_COOKIE_SECURE is not set to True.
?: (security.W018) You should not have DEBUG set to True in deployment.

System check identified 5 issues (0 silenced).
```

---

## 6. Code Explanation

- `check --deploy`: An automated security linter that inspects your `settings.py` for common production misconfigurations.
- It verifies that SSL redirection is enforced, cookies are HTTPS-only, HSTS headers are enabled, and `DEBUG=False`.

---

## 7. Expected Output

When all production security settings are properly configured:
```bash
python manage.py check --deploy
```
Output:
```text
System check identified no issues (0 silenced).
```

---

## 8. Real-World Use Case

Compliance audits (SOC 2, ISO 27001, PCI-DSS, HIPAA) requiring automated vulnerability checks before code deployment.

---

## 9. Common Mistakes

1. **Running in production with `DEBUG = True`:** Leaks database passwords, SECRET_KEY, and environment variables on error screens.
2. Disabling security middleware (`CsrfViewMiddleware`, `SecurityMiddleware`) to "fix" development issues.

---

## 10. Best Practices

- Always run `python manage.py check --deploy` before deploying.
- Never disable built-in security middleware.
- Always use HTTPS in production.

## 12. Interview Questions

**Q1: How does Django's design protect against the OWASP Top 10 vulnerabilities?**  
*Answer:* Django addresses OWASP risks by default:
- **SQL Injection:** Avoided via ORM parameterized queries.
- **XSS:** Mitigated via automatic HTML escaping in templates.
- **CSRF:** Prevented via `CsrfViewMiddleware` and per-session tokens.
- **Clickjacking:** Mitigated via `XFrameOptionsMiddleware`.
- **Session Hijacking:** Mitigated via `HttpOnly`, `Secure`, and `SameSite` cookie flags.

**Q2: What is the purpose of `python manage.py check --deploy`?**  
*Answer:* It runs the system check framework with deployment-specific security checks, verifying that critical production settings (such as `DEBUG=False`, `ALLOWED_HOSTS`, `SECURE_SSL_REDIRECT`, `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`, and `SECRET_KEY` strength) are properly configured before going live.

---

## 13. Summary

- Django is secure by default against common OWASP vulnerabilities.
- `check --deploy` audits production configuration.
- Never bypass built-in security protections.
