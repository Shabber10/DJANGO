# 3. Field Options and Primary Keys

## 1. Introduction

Every model field accepts keyword arguments known as **Field Options**. These options customize column constraints, database indexing, nullability, form validation behavior, and human-readable labels. Understanding the subtle difference between options like **`null`** and **`blank`** is one of the most critical fundamentals in Django.

---

## 2. Why Do We Need It?

Databases and web forms have different concepts of "emptiness":
- A database needs to know if a column allows SQL `NULL` values.
- A web form needs to know if an input is required or can be submitted empty.
Django decouples these concerns using `null` (database constraint) and `blank` (form validation rule).

---

## 3. How It Works

### Core Field Options:
- **`null=True`:** Database-related. Allows storing SQL `NULL` in the column. Default is `False`.
- **`blank=True`:** Validation-related. Allows the field to be left empty in forms. Default is `False`.
- **`default=value`:** The default value for the field (can be a constant or a callable function).
- **`unique=True`:** Enforces a unique index constraint at the database level.
- **`primary_key=True`:** Designates this field as the primary key for the table.
- **`db_index=True`:** Creates a B-Tree database index to accelerate search queries.
- **`choices=[...]`:** Restricts field values to a predefined list of options.
- **`verbose_name="..."`:** Human-friendly label used by Admin and forms.

---

## 4. Syntax

```python
# File: accounts/models.py
from django.db import models

class UserProfile(models.Model):
    # Defining Choice Tuples
    ROLE_CHOICES = [
        ('admin', 'Administrator'),
        ('manager', 'Branch Manager'),
        ('staff', 'Support Staff'),
    ]

    phone = models.CharField(max_length=20, blank=True, default='') # Clean empty string for text!
    date_of_birth = models.DateField(null=True, blank=True)         # null=True for non-text!
    role = models.CharField(max_length=20, choices=ROLE_CHOICES, default='staff')
    email = models.EmailField(unique=True, db_index=True)
```

---

## 5. Practical Examples

### The Golden Rule: `null=True` vs `blank=True`
- **For string-based fields (`CharField`, `TextField`, `EmailField`):**
  Avoid `null=True`! If a string field has `null=True`, it has two possible values for "no data": `NULL` and the empty string `""`. Having two ways to represent empty data is redundant. Django convention is to use `blank=True, default=''`.
- **For non-string fields (`DateField`, `IntegerField`, `ForeignKey`):**
  Use `null=True, blank=True` when the value is optional.

---

## 6. Code Explanation

- `role = models.CharField(choices=ROLE_CHOICES)`: Enforces validation against the choice keys and provides a dropdown `<select>` widget in forms and admin.
- `db_index=True`: Creates an index on the column in PostgreSQL/MySQL, drastically accelerating `filter(email=...)` queries.
- `unique=True`: Creates a unique constraint, preventing duplicate values across the table.

---

## 7. Expected Output

Viewing choices in Python shell:
```python
>>> profile = UserProfile(role='admin')
>>> print(profile.get_role_display())
Administrator
```
Notice `get_FOO_display()`: Django automatically provides a helper method to return the human-readable label for any field with `choices`!

---

## 8. Real-World Use Case

User role management (`choices`), indexed email columns for instant login lookups (`unique=True, db_index=True`), and optional user birthdays (`null=True, blank=True`).

---

## 9. Common Mistakes

1. **Setting `null=True` on `CharField` or `TextField`:** Leads to inconsistent data where some rows contain SQL `NULL` and others contain `""`.
2. Passing a function call instead of function reference as default:
   ```python
   # INCORRECT:
   created_at = models.DateTimeField(default=datetime.now()) # Evaluated once on startup!
   # CORRECT:
   created_at = models.DateTimeField(default=datetime.now)   # Evaluated on every insert
   ```

---

## 10. Best Practices

- Avoid `null=True` on string-based fields; use `blank=True, default=''`.
- Use `null=True, blank=True` on optional numeric, date, and foreign key fields.
- Always use `get_<fieldname>_display()` to print choice labels.

## 12. Interview Questions

**Q1: Explain the difference between `null=True` and `blank=True` in Django.**  
*Answer:* `null=True` is purely database-related; it sets the column constraint to allow SQL `NULL` values. `blank=True` is purely validation-related; it informs Django forms and the admin that the field may be left empty by users.

**Q2: What is the `get_FOO_display()` method in Django models?**  
*Answer:* For any model field `FOO` defined with the `choices` argument, Django automatically attaches a method named `get_FOO_display()`. When called on an instance, it returns the human-readable label corresponding to the current stored choice key.

---

## 13. Summary

- `null=True` allows SQL `NULL`; `blank=True` allows empty form inputs.
- String fields should use `blank=True` rather than `null=True`.
- `choices` creates clean dropdowns and exposes `get_FOO_display()`.
