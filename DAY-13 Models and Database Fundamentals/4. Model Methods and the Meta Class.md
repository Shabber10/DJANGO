# 4. Model Methods and the Meta Class

## 1. Introduction

Django models are full-featured Python classes. Beyond declaring columns, you can add custom domain logic by defining **Model Methods** and configure table-level metadata by defining an inner **`Meta`** class.

---

## 2. Why Do We Need It?

- **Fat Models, Thin Views:** Encapsulating calculations, state changes, and business rules inside models prevents duplicating code across multiple views or API handlers.
- **Table Metadata:** Configuring database table names, default sorting orders, verbose names, and composite unique constraints requires a centralized configuration block: `class Meta`.

---

## 3. How It Works

- **Methods:** Standard Python functions defined on the model class that operate on `self`. Common standard methods include `__str__()`, `get_absolute_url()`, and custom business methods.
- **`class Meta`:** An inner class that provides metadata options to Django's ORM, such as `ordering`, `db_table`, `verbose_name_plural`, and `indexes`.

---

## 4. Syntax

```python
# File: blog/models.py
from django.db import models
from django.urls import reverse

class Post(models.Model):
    title = models.CharField(max_length=200)
    slug = models.SlugField(unique=True)
    published_date = models.DateTimeField()

    class Meta:
        # Default QuerySet ordering (newest first)
        ordering = ['-published_date']
        # Custom table name in database
        db_table = 'blog_articles'
        # Proper plural name in Django Admin
        verbose_name_plural = 'Blog Posts'

    def __str__(self):
        return self.title

    def get_absolute_url(self):
        # Canonical URL for this specific post
        return reverse('blog:post_detail', kwargs={'slug': self.slug})
```

## 5. Practical Examples

### Implementing Custom Business Logic on Models
```python
# File: store/models.py
from django.db import models

class Order(models.Model):
    subtotal = models.DecimalField(max_digits=10, decimal_places=2)
    tax_rate = models.DecimalField(max_digits=4, decimal_places=2, default=0.08) # 8%
    is_paid = models.BooleanField(default=False)

    def calculate_total(self):
        return self.subtotal * (1 + self.tax_rate)

    def mark_as_paid(self):
        self.is_paid = True
        self.save()
```

---

## 6. Code Explanation

- `get_absolute_url()`: Django convention telling the framework how to calculate the canonical URL for an object. The Django admin automatically renders a "View on site" button if this method is defined!
- `ordering = ['-published_date']`: Automatically orders all QuerySets for this model in descending order (`-` indicates reverse/descending).
- `verbose_name_plural`: Corrects awkward Django admin plurals (e.g., prevents "Categorys" by setting `verbose_name_plural = "Categories"`).

---

## 7. Expected Output

In template rendering with `get_absolute_url`:
```html
<a href="{{ post.get_absolute_url }}">Read More</a>
<!-- Evaluates cleanly to: <a href="/blog/my-first-post/">Read More</a> -->
```

---

## 8. Real-World Use Case

E-commerce orders computing totals and taxes, inventory items checking stock availability, and articles providing canonical URLs for SEO sitemaps.

---

## 9. Common Mistakes

1. **Misspelling `verbose_name_plural`:** If misspelled, Django admin falls back to appending an "s" to the model name (e.g. `Companys`).
2. Overusing `ordering` in `Meta` for massive tables without indexing the ordered column, causing slow database table scans.

---

## 10. Best Practices

- Always implement `__str__()` and `get_absolute_url()`.
- Set `verbose_name_plural` for irregular English nouns (`Category` -> `Categories`).
- Encapsulate domain logic inside model methods rather than duplicating math in views.

## 12. Interview Questions

**Q1: What is the benefit of defining `get_absolute_url()` on a Django model?**  
*Answer:* `get_absolute_url()` defines the canonical URL for an entity in a single place. Templates can link directly using `{{ object.get_absolute_url }}`, redirect functions can pass the object directly (`redirect(my_post)`), and the Django Admin displays a "View on site" link on the record's change page.

**Q2: What is the difference between `ordering` in `class Meta` and `.order_by()` in queries?**  
*Answer:* `ordering` in `class Meta` sets the default sorting applied to all QuerySets generated for that model. `.order_by()` is called explicitly on an individual QuerySet, overriding the model's default `Meta.ordering` for that specific query.

---

## 13. Summary

- Model methods encapsulate business logic and calculations.
- `__str__()` and `get_absolute_url()` are standard conventions.
- `class Meta` configures table-level settings, ordering, and admin labels.
