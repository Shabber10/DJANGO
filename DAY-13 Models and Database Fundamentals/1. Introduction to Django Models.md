# 1. Introduction to Django Models

## 1. Introduction

A **Model** is the single, definitive source of information about your data. In Django, models are Python classes that inherit from `django.db.models.Model`. Each model maps to a single database table, where each attribute represents a database column.

---

## 2. Why Do We Need It?

Without an ORM and model abstraction:
- Developers must write raw SQL queries tailored to specific database dialects (PostgreSQL vs MySQL vs SQLite).
- Database schemas must be synchronized across team members manually.
- SQL injection vulnerabilities can easily slip into queries.
Django models provide a unified Python API that automatically generates schemas, manages migrations, and handles queries securely.

---

## 3. How It Works

1. You declare a class inheriting from `models.Model` inside `models.py`.
2. Django inspects the class attributes and data types.
3. Running `python manage.py makemigrations` translates the class into a migration blueprint.
4. Running `python manage.py migrate` executes the generated SQL `CREATE TABLE` statement in your active database.

---

## 4. Syntax

```python
# File: academy/models.py
from django.db import models

class Student(models.Model):
    first_name = models.CharField(max_length=50)
    last_name = models.CharField(max_length=50)
    email = models.EmailField(unique=True)
    enrollment_date = models.DateField(auto_now_add=True)
    is_active = models.BooleanField(default=True)

    def __str__(self):
        return f"{self.first_name} {self.last_name}"
```

---

## 5. Practical Examples

### Visualizing the Generated SQL Table
When Django migrates the `Student` model to SQLite or PostgreSQL, it executes:
```sql
CREATE TABLE "academy_student" (
    "id" integer NOT NULL PRIMARY KEY AUTOINCREMENT,
    "first_name" varchar(50) NOT NULL,
    "last_name" varchar(50) NOT NULL,
    "email" varchar(254) NOT NULL UNIQUE,
    "enrollment_date" date NOT NULL,
    "is_active" bool NOT NULL
);
```

---

## 6. Code Explanation

- `models.Model`: Base class required for all ORM entities.
- `id`: Django automatically creates an auto-incrementing integer primary key named `id` if none is explicitly specified.
- `table name`: By default, Django generates table names formatted as `<app_label>_<model_name>` (e.g. `academy_student`).
- `__str__()`: Returns a readable representation for the Django admin and debugging consoles.

---

## 7. Expected Output

Creating and inspecting records in `python manage.py shell`:
```python
>>> from academy.models import Student
>>> s = Student.objects.create(first_name="Shabber", last_name="Hussain", email="shabber@example.com")
>>> print(s.id)
1
>>> print(s)
Shabber Hussain
```

## 8. Real-World Use Case

Defining customer profiles, financial transaction ledgers, inventory catalogs, and blog posts across enterprise web services.

---

## 9. Common Mistakes

1. **Modifying `models.py` without running migrations:** Adding fields without running `makemigrations` and `migrate` causes immediate `OperationalError: no such column` crashes.
2. Naming models using plural words (e.g. `class Students(models.Model)`). Model names should always be singular nouns: `class Student`.

---

## 10. Best Practices

- Model names should always be singular nouns (`Customer`, `Product`, `Order`).
- Always implement the `__str__()` method.
- Group domain-specific business calculations inside model methods.

## 12. Interview Questions

**Q1: What is the role of `models.Model` in Django?**  
*Answer:* `models.Model` is the base class that equips a Python class with Django's ORM capabilities. It registers the class with the application registry, translates class attributes into database table columns, handles database transactions and migrations, and exposes the `objects` Manager for querying.

**Q2: What is the `BigAutoField` and why is it preferred over `AutoField` in modern Django?**  
*Answer:* `AutoField` is a 32-bit integer primary key, which tops out at ~2.14 billion records. `BigAutoField` is a 64-bit integer supporting up to 9 quintillion records, preventing primary key exhaustion in high-volume production databases.

---

## 13. Summary

- Models represent database tables in Python classes.
- Inherit from `models.Model`.
- Migrations translate model code into SQL schema changes.
