# 2. Model Fields and Data Types

## 1. Introduction

Django provides a comprehensive catalog of built-in **Model Fields**. Each field type specifies the appropriate column type in the underlying database, provides default HTML form widgets, and enforces data validation constraints.

---

## 2. Why Do We Need It?

Using accurate field types ensures data integrity and storage optimization:
- Storing currency in floating point fields causes rounding errors; `DecimalField` provides exact precision.
- Storing long-form articles in `CharField` causes truncation; `TextField` handles unbounded text.
- Specialized fields (`EmailField`, `URLField`, `UUIDField`) enforce validation out of the box.

---

## 3. How It Works

### Core Model Fields Overview:
- **`CharField(max_length=N)`:** Short text strings (`VARCHAR(N)`). `max_length` is mandatory!
- **`TextField()`:** Long-form unbounded text (`TEXT` in SQL).
- **`IntegerField()`, `PositiveIntegerField()`, `BigIntegerField()`:** Numeric values.
- **`DecimalField(max_digits=D, decimal_places=P)`:** Fixed-precision decimal numbers, essential for financial data.
- **`BooleanField()`:** True/False values (`BOOLEAN` or `TINYINT(1)`).
- **`DateField()`, `DateTimeField()`:** Calendar dates and timestamps.
- **`EmailField()`, `URLField()`, `SlugField()`:** Text fields with built-in format validation.
- **`UUIDField()`:** Universally unique identifiers (`UUID`).
- **`FileField()`, `ImageField()`:** File and image storage references.

---

## 4. Syntax

```python
# File: store/models.py
from django.db import models
import uuid

class Product(models.Model):
    # Unique identifier
    sku = models.UUIDField(default=uuid.uuid4, editable=False, unique=True)
    
    # Text fields
    name = models.CharField(max_length=200)
    slug = models.SlugField(max_length=200, unique=True)
    description = models.TextField(blank=True)
    
    # Financial and numeric data
    price = models.DecimalField(max_digits=10, decimal_places=2) # Up to 99,999,999.99
    stock_count = models.PositiveIntegerField(default=0)
    
    # Dates
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
    
    # Status
    is_available = models.BooleanField(default=True)
```

---

## 5. Practical Examples

### DateField auto_now vs auto_now_add
```python
# auto_now_add=True: Sets timestamp ONCE when object is first created
created_at = models.DateTimeField(auto_now_add=True)

# auto_now=True: Updates timestamp EVERY TIME object.save() is called
updated_at = models.DateTimeField(auto_now=True)
```

---

## 6. Code Explanation

- `max_digits=10, decimal_places=2`: Allows numbers up to 8 integer digits and 2 decimal fractions (e.g. `12345678.99`). Never use `FloatField` for monetary values!
- `auto_now_add=True`: Ideal for creation timestamps.
- `auto_now=True`: Ideal for last-modified timestamps.
- `editable=False`: The field will not be displayed in forms or the Django admin.

---

## 7. Expected Output

Querying product fields in Python shell:
```python
>>> p = Product.objects.get(id=1)
>>> type(p.price)
<class 'decimal.Decimal'>
>>> type(p.created_at)
<class 'datetime.datetime'>
```
Notice how Django ORM automatically converts SQL column types to exact Python objects!

---

## 8. Real-World Use Case

Managing financial transactions, invoices, and accounting ledgers where decimal arithmetic must maintain exact penny accuracy without IEEE floating point errors.

---

## 9. Common Mistakes

1. **Using `FloatField` for currency:** Floating-point rounding errors (`0.1 + 0.2 = 0.30000000000000004`) lead to balance discrepancies. Always use `DecimalField` for money.
2. Forgetting `max_length` on `CharField` (mandatory argument).

---

## 10. Best Practices

- Always use `DecimalField` for prices, salaries, and currency.
- Use `auto_now_add=True` on `created_at` and `auto_now=True` on `updated_at`.
- Use `SlugField` for SEO-friendly URL segments.

## 12. Interview Questions

**Q1: What is the difference between `CharField` and `TextField` in Django?**  
*Answer:* `CharField` maps to SQL `VARCHAR(N)` and requires a `max_length` parameter, suitable for small to medium length strings like titles, names, and slugs. `TextField` maps to SQL `TEXT` (or `LONGTEXT`), does not strictly enforce character limits at the database level, and is designed for long-form multi-paragraph content.

**Q2: How do `auto_now` and `auto_now_add` affect field editing in Django Admin?**  
*Answer:* Fields configured with `auto_now=True` or `auto_now_add=True` automatically receive `editable=False` and `blank=True`. Consequently, they are read-only and will not appear on admin edit forms or ModelForms by default unless explicitly added to `readonly_fields`.

---

## 13. Summary

- Django provides specialized fields for text, numbers, dates, and media.
- `DecimalField` guarantees monetary accuracy.
- `auto_now_add` logs creation; `auto_now` logs modifications.
