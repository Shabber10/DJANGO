# 3. QuerySet Methods - Ordering, Slicing, and Limiting

## 1. Introduction

Beyond filtering rows with `WHERE` clauses, database queries routinely require sorting results (`ORDER BY`), limiting returned rows (`LIMIT`), skipping offsets (`OFFSET`), checking existence (`EXISTS`), and retrieving specific columns. Django provides fluent QuerySet methods to handle these operations efficiently.

---

## 2. Why Do We Need It?

- **Pagination & Slicing:** Fetching 100,000 records into Python memory will crash servers. Python slicing syntax (`[:20]`) translates directly to SQL `LIMIT` and `OFFSET`.
- **Fast Existence Checks:** Calling `exists()` avoids fetching full row payloads when you only need to check if a record is present.
- **Specific Column Selection:** `values()` and `values_list()` fetch lightweight dicts or tuples without the overhead of full model instances.

---

## 3. How It Works

- **`order_by(*fields)`:** Orders results. Prefix with `-` for descending.
- **`[:10]`:** Slicing translates to SQL `LIMIT 10`. `[10:20]` translates to `LIMIT 10 OFFSET 10`.
- **`get(**kwargs)`:** Returns exactly ONE matching instance. Raises `DoesNotExist` if 0 matches, or `MultipleObjectsReturned` if >1 match.
- **`first()` / `last()`:** Returns the first or last record, or `None` if empty.
- **`exists()`:** Returns boolean, executing an optimized `SELECT 1 ... LIMIT 1`.
- **`count()`:** Executes SQL `SELECT COUNT(*)`.

---

## 4. Syntax

```python
# Ordering
products = Product.objects.all().order_by('-price', 'name')

# Slicing (Limit & Offset)
first_five = Product.objects.all()[:5]       # LIMIT 5
page_two = Product.objects.all()[10:20]      # LIMIT 10 OFFSET 10

# Existence and Counting
has_stock = Product.objects.filter(stock_count__gt=0).exists() # Fast!
total = Product.objects.filter(is_active=True).count()          # Fast!

# Selecting Specific Columns
names = Product.objects.values_list('name', flat=True) # ['Mouse', 'Keyboard']
data_dicts = Product.objects.values('id', 'name', 'price') # [{'id': 1, ...}]
```

---

## 5. Practical Examples

### Safe Single Object Retrieval
```python
# File: store/views.py
from django.http import Http404
from .models import Product

def get_product_by_slug(slug):
    try:
        # get() expects EXACTLY one match
        return Product.objects.get(slug=slug)
    except Product.DoesNotExist:
        raise Http404("Product not found")
    except Product.MultipleObjectsReturned:
        # Data integrity anomaly: duplicate slugs exist!
        return Product.objects.filter(slug=slug).first()
```

---

## 6. Code Explanation

- `Product.objects.get()`: Should only be used when looking up unique fields (e.g., `id`, `slug`, `email`).
- `values_list('name', flat=True)`: `flat=True` unpacks single-item tuples into a plain Python list of values.
- `Product.objects.all()[:5]`: Negative indexing (e.g. `[-1]`) is NOT supported by Django QuerySets because SQL has no native negative offset; use `.order_by('-id').first()` instead.

---

## 7. Expected Output

Inspecting SQL executed by `exists()`:
```sql
SELECT 1 AS "a" FROM "store_product" WHERE "store_product"."stock_count" > 0 LIMIT 1;
```
Notice how `exists()` does not pull heavy text or image columns, returning in microseconds!

---

## 8. Real-World Use Case

Implementing database pagination for infinite scrolling feeds, leaderboards sorted by high score (`order_by('-score')`), and checking if an email is already registered (`User.objects.filter(email=...).exists()`).

---

## 9. Common Mistakes

1. **Using `len(qs) > 0` instead of `qs.exists()`:** `len()` loads all database rows into Python memory before counting! `qs.exists()` checks existence in SQL with zero memory overhead.
2. Attempting to use negative slicing like `Product.objects.all()[-5:]` (raises `AssertionError`).

---

## 10. Best Practices

- Use `exists()` instead of `count() > 0` or `len() > 0` when checking existence.
- Use `values()` or `values_list()` when feeding data into JSON APIs or chart scripts.
- Always handle both `DoesNotExist` and `MultipleObjectsReturned` when using `get()`.

## 12. Interview Questions

**Q1: What is the difference between `get()` and `filter().first()`?**  
*Answer:* `get()` executes a query and expects exactly one matching record. If no record is found, it raises `DoesNotExist`; if more than one record is found, it raises `MultipleObjectsReturned`. `filter().first()` returns the first matching record if found, or returns `None` safely without raising an exception if no records match.

**Q2: What is the performance difference between `count()` and `len()` on a QuerySet?**  
*Answer:* `count()` executes an SQL `SELECT COUNT(*)` on the database server without fetching rows into memory. `len(queryset)` evaluates the entire QuerySet, pulls all rows and columns across the network into Python memory, and instantiates model objects before counting them with Python's built-in `len()`.

---

## 13. Summary

- `order_by()` sorts results; `-` indicates descending order.
- Slicing `[:N]` maps to SQL `LIMIT` and `OFFSET`.
- Use `exists()` and `count()` for database-level efficiency.
