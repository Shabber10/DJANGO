# 1. Introduction to ORM and Django Shell

## 1. Introduction

An **Object-Relational Mapper (ORM)** is a software abstraction layer that maps database records to object-oriented programming entities. In Django, rather than writing raw SQL strings (`SELECT * FROM users`), you manipulate Python objects directly (`User.objects.all()`). The **Django Shell** (`python manage.py shell`) provides an interactive REPL to experiment with the ORM and test queries in real time.

---

## 2. Why Do We Need It?

- **Database Engine Portability:** The exact same Python code works seamlessly across SQLite, PostgreSQL, MySQL, and Oracle without changing query syntax.
- **SQL Injection Immunity:** The ORM uses parameterized queries automatically, neutralizing SQL injection vectors.
- **Developer Productivity:** Instant autocompletion, type hinting, and automated relationship traversal in Python.

---

## 3. How It Works

Every Django model has a default **Manager** named **`objects`**. The Manager provides methods (like `all()`, `filter()`, `create()`) that generate SQL queries under the hood and return **QuerySets**—lazy collections of model instances.

---

## 4. Syntax

### Launching the Django Interactive Shell:
```bash
python manage.py shell
```

### Creating and Saving Records:
```python
from store.models import Product

# Method 1: Using .save()
p1 = Product(name="Laptop", price=999.99)
p1.save()  # Executes SQL INSERT

# Method 2: Using .create() (Instantiates and saves in one step!)
p2 = Product.objects.create(name="Mouse", price=29.99)
```

---

## 5. Practical Examples

### Interactive Exploration in Django Shell
```python
>>> from store.models import Product

# Count total rows
>>> Product.objects.count()
2

# Retrieve first record
>>> prod = Product.objects.first()
>>> prod.name
'Laptop'

# Update a property and persist
>>> prod.price = 899.99
>>> prod.save() # Executes SQL UPDATE

# Delete a record
>>> prod.delete() # Executes SQL DELETE
(1, {'store.Product': 1})
```

---

## 6. Code Explanation

- `Product.objects`: The default model manager.
- `Product.objects.create(...)`: Shortcut that initializes a model instance and executes the SQL `INSERT` statement in one call.
- `prod.save()`: Inspects the instance. If it lacks a primary key (`id=None`), it generates an `INSERT`; if an `id` is present, it generates an `UPDATE`.
- `prod.delete()`: Executes an SQL `DELETE` and returns a tuple with the number of deleted records and a dictionary broken down by model type.

---

## 7. Expected Output

Querying database records via shell:
```text
>>> Product.objects.all()
<QuerySet [<Product: Mouse>]>
```

---

## 8. Real-World Use Case

Rapid data seeding, manual record verification during debugging, running maintenance scripts, and building complex query logic before adding it to production views.

---

## 9. Common Mistakes

1. **Calling `python` instead of `python manage.py shell`:** A raw Python shell does not configure `DJANGO_SETTINGS_MODULE`, causing `AppRegistryNotReady` exceptions when importing models.
2. Forgetting to call `.save()` when instantiating via `Product(name="...")`.

---

## 10. Best Practices

- Install `django-extensions` and `ipython` to get rich colored syntax and autocompletion when running `python manage.py shell_plus`.
- Use `Model.objects.create()` for concise code when creating single records.

## 12. Interview Questions

**Q1: What is an ORM and what are its primary advantages and disadvantages?**  
*Answer:* An ORM bridges relational database tables and object-oriented code.  
*Advantages:* Database portability, protection against SQL injection, rapid development velocity, unified migrations, and clean model encapsulation.  
*Disadvantages:* Slight CPU overhead compared to raw SQL, risk of suboptimal queries (such as N+1 query problems) if not properly tuned, and potential complexity for highly specialized analytical OLAP queries.

**Q2: What is the difference between `python` and `python manage.py shell`?**  
*Answer:* `python manage.py shell` sets `DJANGO_SETTINGS_MODULE` and initializes the Django application registry (`django.setup()`) before launching the Python interpreter, allowing models, settings, and framework components to be imported and used immediately.

---

## 13. Summary

- Django ORM translates Python objects to database tables.
- Model Manager `objects` handles querying.
- `manage.py shell` provides an interactive environment to test queries.
