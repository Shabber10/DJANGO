# 2. QuerySets - Retrieving and Filtering Records

## 1. Introduction

A **QuerySet** is a collection of database queries that can be constructed, filtered, sliced, and chained before execution. One of the most powerful aspects of Django QuerySets is that they are **lazy**—evaluating a QuerySet does not actually hit the database until the data is explicitly needed.

---

## 2. Why Do We Need It?

Web applications require filtering data based on dynamic conditions: active users, orders placed this week, products within a price range. Django provides a rich set of **Field Lookups** appended to field names using double underscores (`__`) to execute SQL `WHERE` clauses cleanly in Python.

---

## 3. How It Works

QuerySets are lazy. Building a QuerySet does not execute SQL:
```python
# No database query is sent yet!
query = Product.objects.filter(is_active=True).filter(price__lt=50)

# SQL is executed ONLY when the data is evaluated:
for p in query:    # 1. Iteration
    print(p.name)
count = len(query) # 2. Slicing/len
first = query[0]   # 3. Indexing
```

---

## 4. Syntax

```python
# Retrieving records
all_items = Product.objects.all()
cheap_items = Product.objects.filter(price__lte=25.00)
non_active = Product.objects.exclude(is_active=True)

# Field Lookups Syntax: <field>__<lookup_type>=<value>
# __exact, __iexact (case-insensitive)
# __contains, __icontains
# __gt, __gte, __lt, __lte (greater than, less than)
# __in, __startswith, __endswith, __range
```

---

## 5. Practical Examples

### Exploring Field Lookups
```python
# Case-insensitive substring match (SQL LIKE '%laptop%')
laptops = Product.objects.filter(name__icontains="laptop")

# Range check (SQL BETWEEN 10 AND 50)
mid_range = Product.objects.filter(price__range=(10.00, 50.00))

# Membership check (SQL IN ('electronics', 'books'))
selected = Product.objects.filter(category__in=['electronics', 'books'])

# Date lookups (SQL EXTRACT)
recent = Product.objects.filter(created_at__year=2026, created_at__month=10)

# Chaining multiple filters:
results = Product.objects.filter(is_active=True).exclude(price__gt=100)
```

---

## 6. Code Explanation

- `filter(**kwargs)`: Returns a new QuerySet containing records matching the lookup arguments.
- `exclude(**kwargs)`: Returns a new QuerySet containing records that do NOT match the lookup arguments.
- Double underscore `__`: Django's lookup syntax separator.
- Chaining: Multiple `.filter()` and `.exclude()` calls can be combined; Django compiles them into a single optimized SQL query using `AND` clauses.

---

## 7. Expected Output

Inspecting the compiled SQL query in shell:
```python
>>> qs = Product.objects.filter(price__lt=50, is_active=True)
>>> print(qs.query)
SELECT "store_product"."id", "store_product"."name", "store_product"."price" 
FROM "store_product" 
WHERE ("store_product"."price" < 50 AND "store_product"."is_active" = 1)
```

---

## 8. Real-World Use Case

Building e-commerce catalog filters with multiple search facets (e.g. category, minimum price, maximum price, in-stock status).

---

## 9. Common Mistakes

1. **Using single underscore instead of double underscore:**
   `Product.objects.filter(price_lt=50)` -> `FieldError: Cannot resolve keyword 'price_lt' into field`. Always use double underscore `price__lt`!
2. Assuming `filter()` executes immediately. QuerySets are lazy until evaluated.

---

## 10. Best Practices

- Leverage QuerySet laziness to dynamically construct query filters based on user GET parameters.
- Use `print(queryset.query)` to inspect the generated SQL during development.

## 12. Interview Questions

**Q1: What does QuerySet laziness mean and why is it advantageous?**  
*Answer:* QuerySet laziness means Django does not execute the SQL query until the results are actually consumed (e.g., through iteration, slicing, `len()`, `list()`, or `bool()`). This allows developers to chain multiple `.filter()` and `.exclude()` operations dynamically without incurring multiple round-trips to the database; Django combines all filters into a single optimized SQL statement.

**Q2: What is the difference between `__contains` and `__icontains`?**  
*Answer:* `__contains` performs a case-sensitive substring match (in SQL: `LIKE '%val%'` or `LIKE BINARY`). `__icontains` performs a case-insensitive match (in SQL: `ILIKE '%val%'` or `LIKE UPPER('%val%')`).

---

## 13. Summary

- QuerySets are lazy and hit the database only when evaluated.
- `filter()` and `exclude()` refine search results.
- Double underscore `__` denotes field lookups (`gt`, `lt`, `icontains`, `in`, `range`).
