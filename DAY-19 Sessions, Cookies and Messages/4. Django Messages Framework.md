# 4. Django Messages Framework

## 1. Introduction

When users perform actions in web applications—such as updating a profile, adding an item to a cart, or encountering an authorization error—the application must deliver temporary feedback. Django provides the **Messages Framework** (`django.contrib.messages`) to handle these one-time notification banners (often called **flash messages**).

---

## 2. Why Do We Need It?

Because the Post/Redirect/Get (PRG) pattern redirects the browser to a completely new GET request, simple template context variables cannot survive the redirect. The Messages Framework stores notification strings in the user's session or cookie, displays them on the next page view, and automatically deletes them once rendered!

---

## 3. How It Works

- Message levels categorize severity:
  - `DEBUG` (10)
  - `INFO` (20)
  - `SUCCESS` (25)
  - `WARNING` (30)
  - `ERROR` (40)
- Shortcut functions (`messages.success`, `messages.error`, `messages.warning`) add messages.
- Stored in signed cookies or sessions via `FallbackStorage`.
- Rendering `{% for message in messages %}` in templates consumes and clears the messages.

---

## 4. Syntax

```python
# In Views: Adding messages
from django.contrib import messages
from django.shortcuts import redirect

def profile_update(request):
    # Logic...
    messages.success(request, "Your profile settings have been saved successfully!")
    messages.warning(request, "Your subscription will expire in 3 days.")
    messages.error(request, "Failed to connect to billing server.")
    return redirect('profile')
```

### In Templates: Rendering messages
```html
{% if messages %}
    <div class="messages-container">
        {% for message in messages %}
            <div class="alert alert-{{ message.tags }}" role="alert">
                {{ message }}
            </div>
        {% endfor %}
    </div>
{% endif %}
```

---

## 5. Practical Examples

### Mapping Django Message Tags to Bootstrap or Tailwind Classes
In `config/settings.py`:
```python
from django.contrib.messages import constants as message_constants

# Map Django 'error' tag to Bootstrap 'danger' CSS class
MESSAGE_TAGS = {
    message_constants.DEBUG: 'secondary',
    message_constants.INFO: 'info',
    message_constants.SUCCESS: 'success',
    message_constants.WARNING: 'warning',
    message_constants.ERROR: 'danger', # Default is 'error', mapped to 'danger'
}
```

In `base.html`:
```html
{% if messages %}
    <div class="container mt-3">
        {% for message in messages %}
            <div class="alert alert-{{ message.tags }} alert-dismissible fade show" role="alert">
                {{ message }}
                <button type="button" class="btn-close" data-bs-dismiss="alert" aria-label="Close"></button>
            </div>
        {% endfor %}
    </div>
{% endif %}
```

---

## 6. Code Explanation

- `messages.success(request, text)`: Shortcut that appends a message with level `SUCCESS`.
- `message.tags`: Returns a space-separated string of message attributes (e.g. `'success'` or `'error'`), ideal for mapping directly to CSS alert classes (`class="alert alert-{{ message.tags }}"`).
- Once a template iterates over `messages`, Django automatically clears them from storage so they won't appear on subsequent page loads!

---

## 7. Expected Output

After saving a form, the user sees a green banner at the top of the redirected page:
```html
<div class="alert alert-success" role="alert">
    Your profile settings have been saved successfully!
</div>
```
Refreshing the page causes the banner to disappear because the flash message was consumed.

---

## 8. Real-World Use Case

Providing confirmation alerts after user registration, payment processing, deleting items, password resets, and permission denials across all web apps.

---

## 9. Common Mistakes

1. **Trying to read messages without rendering them:** Iterating over `messages` in template code marks them as used. If you iterate over them in an inclusion tag and then try to iterate again in `base.html`, the second loop will be empty.

---

## 10. Best Practices

- Place the messages rendering snippet in your master `base.html` layout so alerts appear consistently across all views.
- Customize `MESSAGE_TAGS` to match your CSS framework (Bootstrap `danger` vs Tailwind `red-500`).

## 12. Interview Questions

**Q1: How does Django's Messages Framework persist notifications across redirects?**  
*Answer:* The Messages framework uses a configurable storage backend (by default, `FallbackStorage`, which combines signed cookies and sessions). When a message is added in a view, it is serialized into a cookie or session. When a subsequent view renders a template that iterates over `messages`, the messages are read and marked as processed, and Django deletes the cookie or session record at the end of that response.

**Q2: What is the `extra_tags` parameter in Django messages?**  
*Answer:* `extra_tags` allows passing additional custom CSS classes or keywords when recording a message (e.g., `messages.error(request, "Invalid payment", extra_tags="financial modal")`). These tags are concatenated into `message.tags`, enabling custom styling or targeted JavaScript modal triggers in the frontend.

---

## 13. Summary

- Flash messages deliver one-time user notifications.
- Persist across redirects via cookies or sessions.
- Automatically cleared once iterated over in templates.
