# 3. User Login Session Lifecycle

## 1. Introduction

The integration between Django's Authentication subsystem and the Session Framework governs the complete **Login Session Lifecycle**. Understanding how user identities are bound to session tokens, persisted across requests, rotated for security, and purged upon logout is vital for secure web development.

---

## 2. Why Do We Need It?

If session lifecycles are poorly managed:
- **Session Hijacking:** Attackers can intercept or fixate session cookies to impersonate users.
- **Zombie Sessions:** Stale sessions remain valid long after a user logs out or changes their password.
- Django enforces strict cryptographic validation and automatic session invalidation upon password modification.

---

## 3. How It Works

### The Complete Authentication Lifecycle:
1. **Unauthenticated Session:** A guest visits the site. Django creates an anonymous session.
2. **Login (`login(request, user)`):**
   - Django invokes `request.session.cycle_key()`, destroying the anonymous session ID and generating a new, cryptographically random key.
   - It stores `_auth_user_id`, `_auth_user_backend`, and `_auth_user_hash` inside the session payload.
3. **Subsequent Requests:** `AuthenticationMiddleware` reads `_auth_user_id` from the session and populates `request.user`.
4. **Session Invalidation:** If the user changes their password, `_auth_user_hash` no longer matches the user's new password hash; Django automatically invalidates all other active sessions!
5. **Logout (`logout(request)`):** Flushes the session from the database and removes the cookie.

---

## 4. Syntax

```python
# File: accounts/views.py
from django.contrib.auth import update_session_auth_hash
from django.contrib.auth.forms import PasswordChangeForm
from django.shortcuts import render, redirect

def change_password(request):
    if request.method == "POST":
        form = PasswordChangeForm(request.user, request.POST)
        if form.is_valid():
            user = form.save()
            # CRITICAL: Keeps user logged in after password change!
            update_session_auth_hash(request, user)
            return redirect('accounts:profile')
    else:
        form = PasswordChangeForm(request.user)
    return render(request, 'accounts/change_password.html', {'form': form})
```

## 5. Practical Examples

### Inspecting Internal Session Auth Keys
```python
# In Django shell:
>>> session = request.session
>>> session.keys()
dict_keys(['_auth_user_id', '_auth_user_backend', '_auth_user_hash'])
>>> session['_auth_user_id']
'1' # String representation of the User primary key
```

---

## 6. Code Explanation

- `_auth_user_hash`: A cryptographic HMAC of the user's password hash. If the user changes their password on their phone, any open sessions on their laptop or other browsers will fail the hash check on their next request and be logged out automatically.
- `update_session_auth_hash(request, user)`: Updates the current session with the new password hash so the user who just changed their password isn't logged out of their current session.

---

## 7. Expected Output

When a user updates their password without `update_session_auth_hash`:
- User is logged out immediately and redirected to the login screen.
When updating with `update_session_auth_hash`:
- User remains smoothly logged in, while all other active sessions on other devices are terminated.

---

## 8. Real-World Use Case

Banking and enterprise security: forcing global logout across all devices when an employee's password is reset or suspicious activity is detected.

---

## 9. Common Mistakes

1. Forgetting to call `update_session_auth_hash()` after custom password changes, which unexpectedly logs the user out.

---

## 10. Best Practices

- Always call `update_session_auth_hash(request, user)` after updating a user's password.
- Use `SESSION_COOKIE_AGE = 1209600` (default 2 weeks) or customize based on security needs.
- Set `SESSION_EXPIRE_AT_BROWSER_CLOSE = True` on high-security financial applications.

## 12. Interview Questions

**Q1: What is `update_session_auth_hash` in Django and why is it needed?**  
*Answer:* When a user's password changes, Django's session verification hash (`_auth_user_hash`) is invalidated to automatically log out all active sessions across all devices for security. Calling `update_session_auth_hash(request, user)` updates the hash in the current request's session, allowing the user who initiated the password change to remain logged in while terminating all other sessions.

**Q2: What is the default lifespan of a Django session?**  
*Answer:* The default lifespan is 2 weeks (1,209,600 seconds), configured by the `SESSION_COOKIE_AGE` setting in `settings.py`.

---

## 13. Summary

- Django pairs authentication state with session keys.
- Changing passwords automatically invalidates sessions across other devices.
- `update_session_auth_hash` keeps the active user logged in after password changes.
